Revised 2026-11-10. The earlier plan was a research log of the first build; it stays in git history (commit `a7f64e6c`). Model, geometry and outline work from that build is kept unless a task below says otherwise.

Test-first per the ADR 0053 amendment of 2026-11-10: the three benchmark paths (smooth 4-node S-curve, 12-node kinked path, two-node arc) as tests and in a thread-CPU budget test (≤ 2 ms native, ≤ 4 ms wasm; 200-node freehand ≤ 16 ms wasm); a reference test against the same normal-offset definition sampled 64× denser (with caps and joins) for the tight arc, the kinked path and a taper preset; uniform profile equals the ordinary stroke; caps, joins, dashes, markers. Then call it synchronously in the session (memoised on the exact key) and build diamonds on the centre line, ghost diamond on hover, sideways drag with live mm readout, Delete, Done/Escape, and the numeric field. Profile buttons (Uniform, Taper start/end/both) and the numeric field are one undo step each.
5. **Delete the old kernel and the worker; browser check** (criteria 2, 4–9). Delete the modules listed in the ADR 0053 amendment item 7 (`width_profile` moves to plain `f64` first), the editor width-job code (`width_job.rs`, `wasm_width.rs`, `session/width_jobs.rs`), the frontend width worker and its `useEditorSession` wiring, the conservative nudge reach box and the plain-stroke stand-in for pending or failed outlines. Keep the behavioural assertions of `variable_curved_0110.rs` and `variable_outline_0110.rs`, drop the rest. Browser check of each mode and of a live width drag at 800 × 600 and desktop size; keep the geometry and format tests; tests for the profile buttons and the icon bar.
6. **Review and gate.** UX review, architect review (format change, public API), tester on `navi-curvyo`, full gate once, one PR, customer acceptance.

## Decide at go

- Task 2 solving synchronously instead of in a worker (Proposal, vetoable); the width outline is synchronous too (ADR 0053 amendment 2026-11-10).
- Anything in the old build that the demo shows as unused (outline code that nothing calls) is deleted in task 5, not carried.
- Width drag (Proposal, changed by UX review U3): the first movement past the point tolerance chooses the axis for the whole drag; across the line the width at the press grows by twice how far the pointer moves outward (the side of the first sideways movement) and shrinks when it moves back, never below zero. The numeric field shows millimetres.
- Spiro hold (customer 2026-11-11, replaces the U1 Proposal): no "cannot be solved" notice and no straight-line commit. Each solve starts from the previous shape (warm start). When the controls only moved, a solution whose tangent turns more than 90° differently in any segment is a jump and is refused; when a control was added or removed, a segment whose tangent sweeps more than 270° (or more than it did) is a loop and is refused (`SPIRO_MAX_TURN_CHANGE`, `SPIRO_MAX_NEW_SWEEP`, Proposal); of two solutions the one that sweeps least is taken, and a drag may leave a loop for a fresh solution that sweeps at least 90° less, never jump into one. The moving point then goes back toward its last taken place (six halvings) and the curve stays the last valid one. Lead decision 2026-11-11 (Proposal): every click places a control (solved from scratch where nothing near fits); a curve without a loop never enters one and the loop release applies only to a curve that already loops; a move of the curve beyond 4× the control move plus 2 mm is a jump (`STEADY_FACTOR`, `STEADY_SLACK_MM`); a held point catches up at most 1 mm per event faster than the pointer (`CATCH_UP_MM`); a hold search stops at 0.5 mm resolution; `stretch` is the largest singular value, so an unplaced path is drawn at the Pen preview's tolerance.
- A Spiro without solution that comes in from outside (a file of an earlier build) is drawn through its points with straight lines, silently, and its transform is refused with the old notice (Proposal).
