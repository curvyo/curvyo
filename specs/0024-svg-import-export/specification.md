# SVG import and export: open an Inkscape file, change it here, export it back, and see what was not kept

Status: Ready (UX notes 2026-10-15; Fragen 1-6 have recorded defaults, the ADR 0018 needs review)
Priority: Must
Origin: Customer (MVP slice 11, confirmed 2026-10-02: "imports and exports plain SVG well enough that a project can move to and from Inkscape without hand-fixing geometry"; R-SYS-006). The wording of the loss report, the page-size rules, the CSS subset, the Inkscape attributes and every item marked **Proposal** are the product owner's, vetoable at the demo.
Depends on: `0023-groups`, `0050-layers-and-objects-panel` (layers, names, hidden, locked, opacity), `0054-combine-open-paths` (compound paths with open outlines), `0051-sidebar-and-no-menu` (the File tab), `0049-linked-clone` and `0056-mirror-and-negative-scale` (built or specified; the criteria that touch them say so). It is the first importer and exporter, so it also does what ADR 0002 §10 asks of "the SVG import story".

## User value

As a maker who draws in Inkscape today I want to open my SVG here, work on it, and export an SVG that Inkscape opens without anything moved, flattened, renamed or resized, so that I can switch tools gradually, one job at a time, and never have to redraw or repair a file by hand.

As a maker who gets SVG files from elsewhere (a box generator, a stock site, a customer) I want an odd file to open with a defined result and a plain list of what could not be kept, so that I never have to guess why a shape is missing or a size is wrong.

**What the reference tools do, and what we do differently** (from their documentation and behaviour as far as I know; check against the version the customer uses):

- *Inkscape.* SVG is its file format, so nothing is lost by construction, and everything Inkscape does not draw (a `curvyo:` attribute, an `inkstitch:` attribute) survives because it stays in the XML. It keeps a path as written and records node types in `sodipodi:nodetypes`, keeps stars, arcs and spirals as `sodipodi:type` paths, marks layers with `inkscape:groupmode="layer"`, locks with `sodipodi:insensitive`, and writes `fill-rule:evenodd` on most paths it draws. Files from Inkscape 0.91 and earlier assume 90 pixels per inch; 0.92 and later use 96 (Inkscape wiki, "CSS96"). It asks the maker about legacy files in a dialog.
- *Ink/Stitch.* Its embroidery settings live in the SVG as `inkstitch:`-prefixed attributes on the elements, so its files are SVG and Inkscape can edit them. We use the same idea for our own data (a `curvyo:` namespace) and, unlike a plain exporter, we read it back.
- *LightBurn.* Imports SVG (and many other formats), with a setting in Edit > Settings that chooses 72 or 96 dpi for SVG pixels; the forum threads show that a wrong choice is the most common "my SVG came in 25 % too small" case, mostly with Illustrator files. It has no list of what it dropped.
- *What is better here.* (1) A defined result for every readable file, never a refusal for a feature we do not have: the file opens, and one notice says how many things were not kept. (2) That list is named, counted, shows where each thing was in the file, and is one button away, not hidden in a log. (3) Page size is decided by rules that a maker can read, and an Illustrator or old Inkscape file is recognised and the notice says which resolution was used, so no setting and no dialog is needed. (4) Our own data goes into the SVG in a namespace and comes back, but only while the plain SVG next to it still says the same, so an edit made in Inkscape always wins over stale data of ours.

## Words used below

- **Supported subset:** what this spec says is read and written. Everything else is a **loss** and is listed in the **report**.
- **Report:** the list of losses of one import or one export (criteria 8 to 14). An **entry** has a stable **id** (a name, for example `text`), a category, a count and examples.
- **Category:** **Not imported** (something drawn or cut in the file is missing here) or **Approximated** (it is here but looks or cuts a little differently). Export entries are **Notes**.
- **Page:** the document rectangle (`0015`). A document has one.
- **User unit:** the unit of the numbers inside the SVG, before the viewBox maps them to the page.
- **Shadow data:** a `curvyo:` attribute that repeats, exactly, a value that the plain SVG attributes can only say approximately (criterion 57).
- **Leaf:** a path, compound path, rectangle, ellipse, polygon or star. **Clone:** `0049`.
- Lengths are compared with the tolerances of the earlier specs: 1e-6 mm for drawn outlines, 1e-9 mm for stored values.

## What exists today

Facts from the code on `main` and from the accepted specs (2026-10-14).

- **No SVG code exists.** `Open` takes a `.curvyo` project only (`0001`, `0051`). ADR 0002 §10 fixes the strategy: a documented subset, golden files, a named and listed loss, gradients not in the subset (amended 2026-10-08).
- **The model has no per-node transform.** A group has none (`0023` criterion 25); a primitive stores a frame and a `rotation`; a path stores anchors; only a clone (`0049`) has a matrix. So every SVG transform is applied to the geometry on import and never written back.
- **A style is resolved per leaf** (ADR 0002 §5): fill none or one colour plus opacity, stroke on or off with width in mm, colour, opacity, dash (a list in multiples of the stroke width, no phase), join (miter limit fixed at 4), cap, and markers (`0017`, `0018`). Opacity of a node composes per paint, not as a group (`0050` Question 5, A). There is one fill rule, nonzero (`0054`).
- **Compound paths** hold open and closed outlines, touching or crossing (`0054`, built after `0050`). Holes are outlines of opposite direction (`0016`, `0035`).
- **Layers** are top-level groups with a `layer` marker, a name, `visible`, `locked` and `opacity` (`0050`). Groups nest to 32 levels (`0023`). Other nodes carry the same four registers.
- **Primitives:** rectangle (four corner radii, circular, `0013`), ellipse and circle, polygon and star (3 to 1024 points, inner ratio, first-vertex angle). Every primitive has a `rotation`. A stretch converts a rotated primitive to a path (`0047`, `0056`).
- **Page:** 1 to 100,000 mm per side (`0015`), a display unit mm, cm or in, a background colour with alpha or none (`0040`).
- **The File tab** holds New, Open…, Save, Save as…, Close, Quit and the version line; `0051` leaves "Export and Import of drawings" to this spec. There is no menu on Linux and Windows. Messages go to the canvas notice slot (transient notices of 3 s, one persistent banner with one text button) or sit 4 px under the button that caused them (`docs/design-system.md`).
- **Crates:** pure logic lives in `*-core` crates that build for wasm, with no file access; a platform crate reads and writes files (`CLAUDE.md` §6, ADR 0011). Golden files live in the crate's `tests/fixtures/` (`CLAUDE.md` §5).

## Acceptance criteria

### A. The commands

1. Given the File tab and Ctrl+O, when the maker chooses Open…, then the OS file dialog (the browser's file picker in the browser build) offers `.curvyo` and `.svg` files in one list. The kind of file is decided by its content, not its extension: a file whose first non-blank bytes (after an optional UTF-8 byte order mark) are `<` is read as SVG; the project container of `0001` as a project; anything else is refused by criterion 6. The unsaved-changes check, the cancel rule and the rule "Discard changes nothing until the new project has opened" of `0051` criteria 18 and 25 to 27 apply unchanged to an SVG.
2. Given an SVG that opens, then it replaces the project and the result is: an untitled project (the title is "*Curvyo", Save does what Save as… does and offers the SVG's file name with `.curvyo` as the default name), **dirty** (the content exists in no saved file, so New, Open and Close ask first), both undo stacks and the history empty (`0020` criterion 25), selection and tool reset, no entered group, the page and display unit of criteria 15 to 20, the active tab as `0051` criterion 14 says, and the notice of criterion 8. Test: open each fixture of "Fixtures", read the title, the dirty flag and the history length.
3. **Proposal.** Given a project is open, when the maker chooses **Import SVG…** in the File tab, then the same dialog (only `.svg`) opens and the file's content is added to the project as **one new layer** named after the file without its extension ("poster"), on top, at the coordinates the file gives (nothing is moved or scaled to fit; the page, display unit and background are not changed; content outside the page is allowed, `0015`), and each layer of the file becomes a group inside the new layer (layers do not nest, `0050` decision 2). The new layer's top-level children are selected afterwards. It is one history step named "Import SVG" and Ctrl+Z removes all of it. It runs no unsaved-changes check, because it replaces nothing. The report and the notice are those of criteria 8 to 11. Page size rules (15 to 20) are used only to convert the file's units to millimetres. Without this button a part from a second file could not be brought into the drawing at all, because the app has one project at a time and no copy between projects.
4. Given the File tab, when the maker chooses **Export SVG…**, then the OS save dialog opens (a download in the browser build) with the default name "<project file name without extension>.svg", or "Untitled.svg". On success the whole document is written as criteria 52 to 61 say, the canvas notice slot says "Exported <file name>." (3 s; "Downloaded <file name>." in the browser build), and the project is unchanged: not dirty, same path and title, no history step. A cancelled dialog changes nothing. A failed write shows the existing error dialog pattern with the text "Can't export drawing" and the system's reason, and writes no partial file (the file is written whole or not at all). Exporting an empty document writes a valid SVG with no drawing elements.
5. Given the File tab, then the two buttons sit in one new row **Import SVG…** and **Export SVG…** (118 px each, as the others) below Close and above the divider of Quit, and are never dimmed or hidden by the state of the project. No menu, popup, dialog or popover is added (`0051` criterion 24; the OS file dialogs are the only layers). Neither button has a chord in this spec (all shortcuts get the one review of R-SYS-009); the tooltips name none. The inline unsaved-changes block of `0051` still replaces the five buttons it replaced, and these two stay where they are. The row heights, wrapping at 800 x 600 and the tooltip texts are the ux-engineer's.
6. Given a file that cannot give any result, then it is refused with the existing "Can't open project" dialog (text per case below), the open project stays untouched, and nothing is written. These are the only refusals; every other problem is an entry of the report. (a) Not XML, or XML whose root element is not `svg` in the SVG namespace: "This file is not an SVG drawing." with the first parse error's line and column when there is one. (b) The file declares entities in a DOCTYPE that criterion 68 does not allow (external, parameter, or built from other entities): "This file defines XML entities, which Curvyo does not read because they can be used to exhaust memory." (c) Larger than 50 MiB (criterion 69): "This file is larger than 50 MiB." (d) Not UTF-8 text (UTF-8 with or without byte order mark only): "Only UTF-8 SVG files can be opened. Save the file as plain SVG." (e) Compressed (starts with the gzip bytes 1F 8B, an `.svgz`): "Compressed SVG (.svgz) is not supported. Save the file as plain SVG." Test: one fixture per case, the dialog text exactly, the project and its dirty flag unchanged.
7. Given an import or an export that takes longer than 200 ms, then the cursor is `wait` and the canvas is not interactive until it finishes, as for the long operations of `0019` criterion 49 (`aria-busy`). The page shows the result in the same frame the work ends. There is no progress bar and no cancel: the budgets of criterion 71 keep it short.

### B. The report of what was not kept

8. Given an import or an export, then it ends with one notice in the canvas notice slot, `role="status"`:
   - nothing to report: "Opened poster.svg. Everything was kept." / "Imported poster.svg. Everything was kept." (the export says only what criterion 4 says);
   - entries present, as a **persistent banner** in the slot (the slot's existing banner pattern with one text button, `docs/design-system.md`): "Opened poster.svg. 7 things were not kept or were approximated." with the button **Show list** and a second text button **Dismiss**. "1 thing was" for one. The count is the number of **objects and elements affected**, summed over entries (one rectangle with a clip path and a gradient counts twice), not the number of entries, and the banner also names the page size in the form "Page 297 × 210 mm." when the size came from a rule of criteria 16 to 19 (an entry exists then). The banner takes no focus; it is announced once.
   - An export with notes: "Exported poster.svg. 2 notes." with the same two buttons.
9. Given **Show list**, then the list opens **in the File tab body**, replacing the buttons in place the way the inline unsaved-changes block does (`0051` criterion 25): the File tab becomes active (body shown if hidden), the project block stays, the buttons are replaced by the list, a heading "Not kept when opening poster.svg" (or "Notes for export"), the list, and the buttons **Copy as text** and **Close** at the bottom. The list scrolls inside a reserved area that is as tall as the buttons it replaces plus the space below them (never taller than the tab body); the page around it does not move. **Close**, Escape, a change of tab or a new Open, Import, New or Close ends it and brings the buttons back with focus on the button that opened it. It is `role="group"` named by its heading, not a dialog. Copy as text puts the whole report on the clipboard as plain text (the same words, one entry per paragraph) and the notice slot says "Report copied." The list never opens by itself and no other tab grows a section for it. Dismiss closes only the banner; the list stays reachable by criterion 11. (Customer Frage 3.)
10. Given an entry, then it shows, in this order: its category word ("Not imported" or "Approximated" or "Note", also as text, not by colour alone), the sentence of the catalogue (criterion 12) with the count in it, and up to **five examples**, each "<element or object name> (line 41)": the object's `inkscape:label` or `id` and the line number in the file, or for export the object's name. More than five: "and 12 more." Entries are sorted Not imported before Approximated, and inside a category in the order of the catalogue; examples in file order. A name is shown as text (never as markup, `clean_name` of `0050`) and cut to 40 characters. A report never holds more than 200 entries and 1,000 examples; beyond that the last entry says "and more entries were left out" and the notice count stays true.
11. Given the report, then it is kept in memory until the next Open, Import, New, Close or the end of the session, is not saved in the `.curvyo` file, and is reachable while it lasts: **Dismiss** removes the banner only; a File tab button **Last report…** (shown only while a report exists, hidden otherwise, `0043`-style "hidden, not disabled") opens the list again. The first edit of the drawing does not remove the report. The report of an import and the notes of an export are separate; a new export replaces the earlier export's notes only.

14. Test: a document with 3 clones, 2 paths with markers, 4 leaves with opacity 80 % and a fill plus a stroke each, and 2 more with opacity 80 % and a fill only, expects 3, 2 and 4.

### C. The page, the units and the viewBox

15. Given the root `<svg>` with `width`, `height` and `viewBox`, then the page is width × height converted to millimetres (px 25.4/96, pt 25.4/72, pc 25.4/6, mm, cm, in, and em as 16 px, ex as 8 px; a number without a unit is px), and the viewBox maps to that rectangle by `preserveAspectRatio` (default `xMidYMid meet`). Examples: `width="210mm" height="297mm" viewBox="0 0 210 297"`: page 210 × 297 mm, one user unit is 1 mm, so `<rect x="10" y="20" width="30" height="40"/>` becomes a rectangle from (10, 20) to (40, 60). `width="2in" height="1in" viewBox="0 0 200 100"`: page 50.8 × 25.4 mm, one user unit is 0.254 mm, and `<rect x="100" width="100" height="100"/>` is from (25.4, 0) to (50.8, 25.4). A viewBox that does not start at 0 (`viewBox="10 10 100 100"`) puts its top-left corner on the page's top-left corner.
16. Given a root with `width` and `height` but **no viewBox**, then one user unit is one CSS pixel (25.4/96 mm = 0.264583 mm; the SVG rule) and the entry `no-viewbox` is listed. Example: `width="210mm" height="297mm"` and `<rect width="100" height="50"/>`: page 210 × 297 mm, the rectangle is 26.4583 × 13.2292 mm. Nothing is guessed from the numbers' size.
17. Given a root with a viewBox but no usable `width` and `height` (missing, `auto`, or a percentage), then the page is the viewBox size read as pixels, and the entry `size-assumed` says so. Example: `viewBox="0 0 100 50"` only: page 26.4583 × 13.2292 mm, one user unit 0.264583 mm. Given a root with neither size nor viewBox, then the page is the drawing's bounding box from (0, 0) to its right and bottom edge (the stroke excluded), in millimetres, **rounded up to whole millimetres** (at least 1 mm), and nothing is moved: `<rect x="10" y="10" width="100" height="50"/>` gives a page of 30 × 16 mm with the rectangle at (2.6458, 2.6458), 26.4583 × 13.2292 mm. An empty drawing with no size gets the size of a new document (`0015`).
18. Given a viewBox whose aspect ratio differs from width : height, then the whole `preserveAspectRatio` is honoured (all nine alignments, `meet` and `slice`, and `none`) by applying the viewBox-to-viewport map to the geometry. Example: `width="100mm" height="100mm" viewBox="0 0 200 100"` (meet, centred): scale 0.5, and `<rect width="200" height="100"/>` is from (0, 25) to (100, 75); with `preserveAspectRatio="none"`: from (0, 0) to (100, 100). No clip is applied for `slice` (an entry `clip-path` is not made for it; content outside the page is kept).
19. **Pixel size of known generators.** Given a file whose root has no viewBox or a viewBox together with pixel sizes, and which names its program, then: (a) a comment `Generator: Adobe Illustrator` or the namespace `http://ns.adobe.com/AdobeIllustrator/10.0/` makes px mean 1/72 inch, because Illustrator writes points as px; (b) `inkscape:version` below 0.92 on the root without a viewBox makes the user unit 1/90 inch, the legacy of Inkscape 0.91 and earlier. In both cases the entry `pixel-size` names the program and the resolution, and the banner names the page size. All other files use 96 per inch. There is no setting and no dialog (Frage 6). Test: an Illustrator-made fixture of 595.28 × 841.89 px gives 210 × 297 mm; the same numbers from another program give 157.50 × 222.75 mm.
20. Given the rest of the root: (a) a page side below 1 mm or above 100,000 mm is clamped to that range, the drawing is not scaled, and `size-clamped` is listed; (b) `sodipodi:namedview` with `inkscape:document-units` of `mm`, `cm` or `in` sets the display unit (`0015`), any other value leaves mm; (c) `pagecolor` with `inkscape:pageopacity` sets the document background (`0040`): the colour with that opacity, or none when the opacity is 0 or the attribute is missing; (d) several `inkscape:page` elements (Inkscape 1.2): the first sets the page size only when the root gives none, content of all pages is kept on the one page and `pages` is listed; (e) a nested `<svg>` element is a group with the viewBox map of criterion 18 applied and `x`, `y`, `width`, `height` honoured, its overflow clip ignored (`clip-path` is listed when the nested box is smaller than its content).

### D. Shapes and paths

21. Given a `<path>`, then the whole path-data grammar of SVG 1.1 and 2 is read: M m L l H h V v C c S s Q q T t A a Z z, implicit repeats (extra coordinate pairs after M are lines, after C more curves), commas, spaces and none where unambiguous (`M10-5`, `1.5.5` is 1.5 and .5, `1e-3`, `.5`, `-.5`), exponents, and arc flags written without separators (`a1 1 0 00 5 5`). S and T use the reflected control point (or the start point after a different command). Q and T are raised to cubic Béziers exactly. A Z followed by a drawing command without M starts a new subpath at the start of the one just closed. The result for each command is a segment of the model (lines and cubic Béziers).
22. Given an arc `A`, then it is converted to cubic Béziers of at most 45° each, exactly as the SVG implementation notes (F.6) define the centre, with radii that are too small scaled up, a zero radius becoming a line, equal end points dropping the arc, and the four flag combinations choosing the four arcs. Every point of the result lies within 0.001 mm of the true arc for radii up to 100 mm. Example: `M 10 0 A 10 10 0 0 1 0 10` in a millimetre drawing is the quarter circle about (0, 0) from (10, 0) to (0, 10) (sweep 1 is clockwise on the screen); the points of the result are 10 ± 0.001 mm from (0, 0), and with the same flags `0 0` the arc bulges the other way. A rotated ellipse arc (`A 20 10 30 …`) is tested the same way against a computed ellipse.
23. Given path data with an error (a letter that is not a command, a number where a flag belongs, a missing coordinate), then the path is imported up to the last complete command before the error, as SVG says to render it, and `broken-path` is listed with the position of the error in the example. A path that is empty or has no complete command is skipped and counted in `empty-shape`. Example: `M 10 10 L 20 20 L 30` gives an open path of two nodes.
24. Given a path with several subpaths, then they become **one compound path** (`0054` criterion 27): subpath order is outline order, a subpath with `Z` is closed and without it is open, touching and crossing subpaths are kept as written. A path with one subpath is an ordinary path. A subpath of one `M` and nothing else, or of `M` plus a zero-length `Z`, is skipped and counted in `single-point`. Nodes are never merged, removed or re-ordered: a closed subpath whose last point equals its first and which has `Z` keeps both nodes as written (no clean-up is made on import; a "merge coincident end nodes" action is a later command).
25. Given the nodes of an imported path, then each gets a kind: with `sodipodi:nodetypes` on the element and the right number of letters, `c` is Corner, `z` Symmetric, `s` and `a` Asymmetric; without it (or with a wrong count), a node whose two handles are collinear and of equal length is Symmetric, collinear and unequal Asymmetric, everything else Corner (tolerance 1e-6 relative). The kind changes nothing about the drawn outline.
26. Given a `<rect>`, then it is a rectangle: `x`, `y`, `width`, `height`, and `rx`, `ry` (one missing takes the other's value; each clamped to half the side). `rx = ry` (within 1e-9 mm) becomes the same radius at all four corners; `rx ≠ ry` becomes a path with the elliptical corners as arcs (criterion 22), without an entry. A `width` or `height` of 0 or below, or a missing one, skips the element (`empty-shape`). Percent and unit lengths follow criterion 15 (percent of the viewBox).
27. Given `<circle>` and `<ellipse>`, then they are an ellipse (a circle when rx = ry) with centre and radii; a radius of 0 or below skips the element. `<line>` is an open path of two nodes; `<polyline>` an open path; `<polygon>` a closed path (no polygon or star primitive is guessed from its points, criterion 29 and D4; the primitives come from our own data and Inkscape's star data only; architect, 2026-10-14: the guess contradicted criterion 29 and has no round trip, because the export never writes a `<polygon>`). A `points` list with an odd number of numbers drops the last number and lists `broken-path`.
28. Given a `<path>` with `sodipodi:type="star"` (Inkscape's star and polygon tool) that carries `sodipodi:sides`, `sodipodi:r1`, `sodipodi:r2`, `sodipodi:arg1`, `sodipodi:cx`, `sodipodi:cy` and `inkscape:flatsided`, then it is a polygon (flat-sided) or star primitive with those numbers, **but only if** the drawn `d` equals the outline of that primitive within 1e-3 mm; if the maker edited the path since (the shape no longer matches), it is an ordinary path. `inkscape:rounded` or `inkscape:randomized` other than 0 make it an ordinary path. `sodipodi:type` `arc` and `spiral` are ordinary paths from `d` (ellipse arcs are not in the model, `0021`).
29. Given any other `<path>`, then no primitive is guessed from its geometry: a closed path that looks like a circle or a rectangle stays a path (the maker converts nothing, loses nothing, and the node data stays as drawn).
30. Given a coordinate, radius or length that is not a finite number or that lands beyond ±10,000,000 mm after all transforms, then the element is skipped and `out-of-range` is listed. An element with a negative or zero `stroke-width` keeps its fill and has no stroke.

### E. Transforms

31. Given `transform` on any element, then every transform of the element and its ancestors, with the viewBox map, is composed in SVG order and **applied to the geometry** of each leaf; groups carry none (`0023`). The syntax of `matrix`, `translate`, `scale`, `rotate(a)` and `rotate(a cx cy)`, `skewX`, `skewY`, in any list with commas or spaces, is read. A transform that cannot be read is treated as the identity and `unreadable-value` is listed. A transform with determinant 0 (for example `scale(0)`) skips the element (`empty-shape`). Example (millimetre drawing): `<g transform="translate(100 50)"><path transform="rotate(90)" d="M10 0 L20 0"/></g>` is an open path whose nodes are (100, 60) and (100, 70) (rotate maps (x, y) to (−y, x) here).
32. Given a path, then anchors and handle vectors are transformed by the matrix (handles as vectors, anchors as points); the open or closed state, node order and node kinds stay; a mirror (negative determinant) keeps the order of the anchors (the direction on screen is mirrored; `0056` criterion 19).
33. Given a rectangle, ellipse, polygon or star and a transform, then the rules of `0056` criteria 18 to 22 are applied with the matrix as the signed map: a rotation, a uniform scale, a mirror and a translation (any mix) keep the primitive and set its `rotation` and frame (a mirrored rectangle permutes its corner radii to the same physical corners); a transform that stretches (unequal magnitudes) keeps an unrotated rectangle or ellipse as such when the axes stay aligned (a rectangle with radii becomes a path if the radii would be elliptical, criterion 26), and converts a rotated or skewed primitive, and every polygon and star under a stretch, to a path exactly. No entry is made for a conversion. Examples: `<rect width="20" height="10" transform="rotate(30)"/>` is a rectangle of 20 × 10 mm with `rotation` 30° and centre (6.1603, 9.3301); `<rect width="20" height="10" transform="skewX(30)"/>` is a closed path with nodes (0, 0), (20, 0), (25.7735, 10), (5.7735, 10); `<rect width="20" height="10" transform="scale(2 1)"/>` is a rectangle of 40 × 10 mm.
34. Given a stroke and a transform, then the stroke width is multiplied by √|det| (the geometric mean of the two scale factors, the rule of `0005` criterion 8); the dash list does not change, because it is in multiples of the width. When the two scale factors of the transform differ by more than 1e-6 relative (a stretch or skew) and the stroke is painted, `stroke-averaged` is listed.
35. Given nested elements with different viewBox maps, transforms and a layer transform (Inkscape stores a layer's offset as `transform="translate(…)"` on the layer), then the result is the same as applying the nested matrices to each leaf in one step; the order of the leaves and their styles are unchanged by the baking. Test: the nested-transform fixture compared with an independent computation of five points per leaf, within 1e-6 mm.

### F. Style

36. Given the sources of a style, then they apply in this order, the later wins: the presentation attribute, the matching simple rule of a `<style>` element (specificity: `#id` over `.class` over element name over `*`; same specificity: later in the file wins), the `style` attribute (`prop: value;`, comments, `!important` read as plain, property names in any case). Inherited properties (fill, stroke and its parts, fill-opacity, stroke-opacity, fill-rule, display-independent `visibility`) are resolved down the tree to each leaf; `opacity` and `display` are not inherited. A leaf's resulting style is stored whole on the leaf (ADR 0002 §5). `<style>` is supported for these selectors: element name, `.class`, `#id`, `*`, and comma lists of them (this is what Illustrator and Figma write); `type="text/css"` or none. A rule with a combinator, attribute selector or pseudo-class, and every `@` rule (`@import` is never followed) is skipped and counted in `unsupported-css`; `var()`, `calc()` values are `unreadable-value`.
37. Given colours, then these forms are read: `#rgb`, `#rrggbb`, `#rgba`, `#rrggbbaa`, `rgb()` and `rgba()` with numbers or percentages, `hsl()` and `hsla()`, the 148 CSS colour names, `transparent` (alpha 0), and `currentColor` (the `color` property, default black). The colour's alpha multiplies the paint opacity (criterion 39). An unreadable colour is ignored and `unreadable-value` listed; the property then takes the value it would have without it (inherited or default).
38. Given a fill or stroke, then: `none` switches it off; a colour switches it on; `url(#id)` to a gradient is replaced by the colour in the middle of the gradient (the stops interpolated in sRGB at offset 0.5, each channel rounded to the nearest whole value, halves up: black to white gives `#808080`) and `gradient` is listed; to a pattern by `#808080` and `pattern` is listed; `url(#id) red` with a missing target uses the fallback colour; a missing target without fallback is `none`; `url(file.svg#x)` is `none` and lists `external-reference`. The default fill is black and the default stroke is none, as in SVG; when a stroke is off, the file's width, colour and caps are still stored when present, otherwise the application defaults.
39. Given opacity, then `fill-opacity` times the fill colour's alpha is the fill opacity, `stroke-opacity` times the stroke colour's alpha is the stroke opacity, and `opacity` on an element is the node's opacity register (`0050`), also on groups and layers. Example: `fill="rgba(255,0,0,0.5)" fill-opacity="0.5" opacity="0.8"` gives a red fill with opacity 0.25 on a node with opacity 0.8. A group or layer with opacity below 1 that holds more than one painted leaf is listed in `group-opacity`.
40. Given the stroke parts, then `stroke-width` (any length unit; a percentage is a percentage of the viewBox diagonal divided by √2, as SVG says) becomes millimetres (criterion 34 for transforms); `stroke-linecap`: butt, round, square; `stroke-linejoin`: miter, round, bevel (`miter-clip` and `arcs` are read as miter); `stroke-miterlimit` other than 4 on a miter join lists `miter-limit`; SVG `marker-start`, `marker-mid`, `marker-end` and `marker` are not read and list `svg-marker`.
41. Given `stroke-dasharray`, then each length becomes millimetres and is divided by the stroke width in millimetres, so the list is stored in multiples of the width (`0007` criterion 8). An odd count is kept as written (the renderer repeats it, `0017` criterion 32); `none`, an empty list, a list with a negative number, or a list that sums to 0 is solid (the last two list `unreadable-value`). Example: `stroke-width="0.5" stroke-dasharray="2 1"` in a millimetre drawing is the list `4 2`; `stroke-width="2" stroke-dasharray="6 4"` in a pixel drawing is `3 2`. A `stroke-dashoffset` other than 0 lists `dash-offset` and is not kept.
42. Given `display:none` on an element or an ancestor, or `visibility:hidden` on a leaf, then the element is imported as **hidden** (`visible` false, `0050`), not dropped, so the maker finds it in the Layers tab; a hidden layer is a hidden layer. `visibility` is read on leaves only (a group has no such state here).
43. Given `fill-rule` and `clip-rule`, then `clip-rule` is ignored without an entry and `fill-rule` is handled by Part H. Properties of the `unsupported-property` list (`paint-order`, `mix-blend-mode`, `isolation`, `vector-effect`) on a painted leaf list that entry with their names.

### G. Structure: groups, layers, clones

44. Given `<g>`, `<a>` and `<switch>`, then `<g>` and `<a>` are groups and `<switch>` is its first child that passes (no `requiredFeatures` or `systemLanguage` test is made: the first child element); an empty group is not imported (`0023` criterion 14). A group keeps its `inkscape:label` as name (cleaned by `clean_name`), its `opacity` and its hidden state. Its `id` is not kept as a name. Order is z-order: document order, last on top. Groups nested deeper than 32 levels are merged into their parent from level 33 on, with `group-depth` listed.
45. Given a `<g inkscape:groupmode="layer">` that is a child of the root `<svg>`, then it is a **layer** (`0050`): `inkscape:label` is the name (else the `id`, else "Layer N"), `display:none` makes it hidden, `sodipodi:insensitive="true"` makes it locked, `opacity` is its opacity, and its transform is applied to its children. An empty layer is kept. Layers are listed in file order, first at the bottom. A layer inside a group or a layer inside a layer is a group, and for a layer inside a layer `sublayer` is listed. Loose elements at the root stay loose at the top level (`0050` decision 2).
46. Given an element with `sodipodi:insensitive="true"`, then it is locked, whether a layer or an object.
47. Given `<use>` (Frage 2, default A), then the referenced element is copied to the place of the `use`: the target's own style, the `use`'s transform composed with `x`/`y` as a translation, and the style properties set on the `use` and its ancestors inherited by the copy where the target does not set them (SVG's rule). `<symbol>` is read as a group (its viewBox and `preserveAspectRatio` are applied when the `use` has a `width` and `height`). The copy is an ordinary leaf, with no link. A `use` to another file or address lists `external-reference`; a reference cycle or a target that does not exist is skipped (`unsupported-element`). The expansion is limited to depth 16 and 100,000 copies per file, and the copies count toward the 5,000,000 path commands of criterion 69; past the limit the `use` elements are skipped and `limit-reached` is listed.
48. Given `defs`, `symbol`, `clipPath`, `mask`, `pattern`, `marker`, gradients, `filter` and `style`, then they are never drawn on their own; they are read only as far as a rule above uses them (a gradient for its middle colour, a style for its rules, a symbol through `use`). Every use of the others is listed under its entry (`clip-path`, `mask`, `filter`, `pattern`, `svg-marker`).
49. Given `<text>`, `<tspan>`, `<textPath>`, `<flowRoot>` and `<image>`, then they are not imported (`text`, `image`), the first 30 characters of the text are in the example, and no placeholder object is made. `<foreignObject>`, `<script>`, `<animate*>`, `<set>`, `<audio>`, `<video>`, `<canvas>`, `<iframe>` list `unsupported-element`. Elements of other namespaces are ignored; those not in the silent list are named in `foreign-data` (for example `inkstitch`). Text converted to paths in Inkscape is ordinary paths and imports without an entry.

### H. The even-odd fill rule (Frage 1, default A)

50. Given a path (or an inherited style) with `fill-rule: evenodd`, **a fill that is on**, only closed outlines, and outlines that **do not touch (`touching_outlines`, 0.001 mm, ADR 0002 §3), cross each other or cross themselves**, then the outlines are wound so that the nonzero fill of the compound path looks exactly as the even-odd fill did: an outline's depth is the number of other closed outlines of the same path that contain it; an outline of even depth gets the direction of the outermost outline that contains it (an outline of depth 0 keeps its written direction) and an outline of odd depth the opposite direction, so the winding sum is 0 or 1 everywhere; a reversal is the one of Combine (`0054`). A path with the fill off is not re-wound and not listed (nothing is painted; the written direction is kept). Nothing is listed. Example: `<path fill-rule="evenodd" d="M0 0H40V40H0Z M10 10H30V30H10Z"/>` (both squares written clockwise): after import the point (20, 20) is not filled and (5, 5) is, with the nonzero rule; with `fill-rule="nonzero"` the same data stays as written and (20, 20) is filled. Three nested squares: (5,5) filled, (15,15) not, (25,25) filled.
51. Given `evenodd`, a fill that is on, and outlines that cross each other, touch (within 0.001 mm), or cross themselves (a pentagram, two overlapping circles in one path), or a path that has an open outline with an area next to at least one other outline (even-odd fills an open outline closed by its straight line and XORs it with the rest, which no choice of windings reproduces, and reversing an open outline would change its cutting direction), then the outlines stay as written, the object is drawn with the nonzero rule, and `even-odd-crossing` is listed with the count of such paths. A path with one outline that does not cross itself is unaffected either way. Most Inkscape files (which write `evenodd` everywhere) list nothing.

### I. Export

52. Given an export, then the file is UTF-8 XML, a single `<svg>` with `xmlns`, `xmlns:inkscape`, `xmlns:sodipodi` and `xmlns:curvyo="urn:curvyo:svg:1"`, `width` and `height` in millimetres ("210mm"), `viewBox="0 0 <w> <h>"` so one user unit is one millimetre, and `curvyo:format="1"` (the version of this SVG profile, independent of the application version). A `sodipodi:namedview` with `inkscape:document-units` of the display unit, `pagecolor` and `inkscape:pageopacity` of the background (opacity 0 when none) follows. The background is **not** written as a rectangle (it would become a cuttable object). Skeleton for an A4 document with one layer "Cut" holding a rectangle:

    ```xml
    <?xml version="1.0" encoding="UTF-8"?>
    <svg xmlns="http://www.w3.org/2000/svg" xmlns:inkscape="http://www.inkscape.org/namespaces/inkscape"
         xmlns:sodipodi="http://sodipodi.sourceforge.net/DTD/sodipodi-0.dtd" xmlns:curvyo="urn:curvyo:svg:1"
         width="210mm" height="297mm" viewBox="0 0 210 297" curvyo:format="1">
      <sodipodi:namedview id="namedview1" inkscape:document-units="mm" pagecolor="#ffffff" inkscape:pageopacity="0"/>
      <g id="layer1" inkscape:groupmode="layer" inkscape:label="Cut">
        <rect id="rect1" x="10" y="20" width="30" height="40" fill="none" stroke="#000000" stroke-width="0.25"/>
      </g>
    </svg>
    ```
53. Given the tree, then layers are written as `<g inkscape:groupmode="layer" inkscape:label="name">` at the top level in stacking order, hidden ones with `style="display:none"`, locked ones (layer or object) with `sodipodi:insensitive="true"`, opacity as `opacity`; groups as plain `<g>` with `inkscape:label` when named; loose top-level objects directly under the root; z-order is document order. Names are escaped as XML text (`&`, `<`, `>`, quotes) and written without control or bidirectional control characters. Ids are `layer1`, `g1`, `path1`, `rect1`, `ellipse1`, `circle1`, `polygon1`, `star1`, `compound1` numbered per kind in document order; they are not the internal node ids and no identifier of the project leaks into the file.
54. Given a path, then it is written as `<path d="…">` in **absolute** coordinates in millimetres with `M`, `L`, `C` and `Z` only, one subpath per outline in outline order, nodes in stored order and direction (`0054` criterion 26: a compound path is one `<path>`, `Z` after closed outlines only). Numbers use a decimal point whatever the operating system's language, at most 6 decimals, no trailing zeros, no exponent, never `-0`, separated by one space (`M 10 20 C 11.5 20 13 21.2 14 22 Z` form; commands and their numbers are separated by spaces). `sodipodi:nodetypes` is written from the node kinds (Corner `c`, Symmetric `z`, Asymmetric `s`) so Inkscape keeps them. No transform is written on a path and no group has one.
55. Given a primitive, then a rectangle with one radius at all corners is `<rect x y width height rx ry>`, with `transform="rotate(deg cx cy)"` when it is rotated; an ellipse is `<ellipse>` (a circle `<circle>`), rotated the same way; a polygon or star is a `<path>` with `d` and the Inkscape star data (`sodipodi:type="star"`, `sodipodi:sides`, `sodipodi:r1`, `sodipodi:r2`, `sodipodi:arg1`, `sodipodi:arg2`, `sodipodi:cx`, `sodipodi:cy`, `inkscape:flatsided`, `inkscape:rounded="0"`, `inkscape:randomized="0"`) so it opens in Inkscape as an editable star; a rectangle with different radii at its corners is a `<path>` with `curvyo:kind="rectangle"` and the shadow data of criterion 57. Test: the exported star fixture is opened in Inkscape by hand (criterion 65) and edited with the star tool.
56. Given a style, then it is written as presentation attributes (not a `style` attribute, which several cutter programs read less reliably): `fill` (`none` or `#rrggbb`), `fill-opacity` when below 1, `stroke`, `stroke-width` (mm), `stroke-opacity`, `stroke-linecap`, `stroke-linejoin`, `stroke-dasharray` (the list times the width, in mm, `none` when solid; zero values written as `0`), `fill-rule="nonzero"` on every filled leaf, `opacity` on a node below 1. Attribute order is fixed. A stroke that is off is written as `stroke="none"` and no other stroke attribute. Hidden, locked and names as criterion 53.
57. Given values that the standard attributes say less exactly than the model stores, then **shadow data** is added in the `curvyo:` namespace and only there: `curvyo:dash` (the dash list in multiples of the width, exactly), `curvyo:stroke-width` (exact mm), `curvyo:radii` (the four corner radii), `curvyo:kind` (`rectangle`, `ellipse`, `polygon`, `star` when the standard element cannot say it), `curvyo:frame` (a primitive's centre, size, rotation, first-vertex angle, inner ratio), `curvyo:markers` (start, middle, end, place, count), `curvyo:outlines` (the open or closed state of each outline of a compound path, when it cannot be told from `Z`). Names use `inkscape:label` and need no shadow data. On import, shadow data is used **only if** the standard SVG next to it still agrees (lengths within 1e-6 mm, each dash length times the width within 1e-6 mm, geometry of a primitive within 1e-3 mm); otherwise the standard SVG wins and the shadow value is dropped without an entry. Attributes in `curvyo:` that are not in this list are ignored. **Number text:** lengths and coordinates in standard attributes have at most 6 decimals (criterion 54); every number in `curvyo:` data, and opacities, ratios and angles in any attribute, are written as the shortest decimal text that reads back to the same `f64` (Rust's `Display`, no exponent, never `-0`), so "exactly" in criterion 62 holds; angles in `curvyo:frame` are radians (architect, 2026-10-14).
58. Given a compound path, then the export meets `0054` criterion 26 and the import `0054` criterion 27 (as changed by Part H): same outlines, order, open or closed state, nodes and direction after a round trip, test with an open outline, a hole and a crossing pair.
59. Given a clone (`0049`), then it is written as an ordinary `<path>` with the resolved outline and its effective style and the note `clone-as-path` is listed (Frage 2 A); a clone with its own placement or style (`0057`) is written the same way. Markers (`0018`) are written only as `curvyo:markers` and listed in `markers-not-drawn`. Objects with opacity below 1 are listed in `opacity-composition` by the rule of criterion 14. Nothing else is listed: a hidden object is written hidden, which is a faithful picture, not a loss. What a hidden object means for a **machine** output is decided with the manufacturing view (R-MFG-005), not here.
60. Given the whole file, then it contains no absolute or relative file path of the maker, no user name, no time, no random number, no application version and no identifier of the project, only the drawing and the fixed text of this criterion's profile; two exports of the same document are byte-identical (criterion 72).
61. Given an export, then every `inkscape:`, `sodipodi:` and `curvyo:` attribute above is optional to other programs: removing them leaves a valid SVG 1.1 that any viewer draws as in Curvyo, apart from the notes of criterion 59. Test: strip the three namespaces from each exported fixture and compare the rendered outlines (an independent SVG path flattener in the test, tolerance 0.01 mm) with the document's outlines.

### J. Round trips

62. **Our own data.** Given a generated document that uses every kind and field of the model that this spec lists (path, compound path with open and closed outlines and holes, rectangle with four different radii and a rotation, ellipse, circle, polygon, star with the rotations 0°, 30° and −45°, groups nested three deep, layers hidden, locked and with opacity, names, dashes of odd length, caps, joins, all markers, stroke off, fill off, a background and a display unit), when it is exported and imported again, then the new document equals the old one: geometry within 1e-6 mm, **everything else exactly** (kinds, radii, counts, ratios, dash lists, flags, opacity, names, order, open or closed state, node kinds, direction), ids excepted. Clones come back as paths with the same outline (Frage 2 A). A property test runs this over 500 random documents of those kinds.
63. **Export is stable.** Given any document `d`, then export(import(export(d))) is byte-identical to export(d). Given an Inkscape fixture `f`, then export(import(export(import(f)))) is byte-identical to export(import(f)). Test: every fixture and the 500 random documents.
64. **Inkscape-made files.** Given each Inkscape-made fixture, then (a) import gives the expected document (golden, criterion 74), (b) export(import(f)) equals the golden exported file, (c) import of that export has the same document as (a) within 1e-6 mm (nothing is lost by the second trip, whatever the first one listed), and (d) the report equals the golden report.
65. **Inkscape opens our export (hand list, release check, not a CI test).** Given the exported goldens opened in the current stable Inkscape, then: the page size and units are as in Curvyo; layers appear in the Layers dialog with their names, hidden and locked states, in the order of the Layers tab; rectangles, ellipses and stars are still rectangles, ellipses and stars (the star tool edits them); dashes, caps, joins and opacity look the same; no object has moved; Edit > Undo history is empty; saving in Inkscape and importing that file here gives the same document again. The tester lists the Inkscape version and the result in the PR; the customer is invited to repeat it with one of his own files.
66. **Edited in between.** Given an exported file in which a coordinate, a width, a colour, a dash list or a star's point count is changed by hand in a text editor (as Inkscape would change it, without touching our shadow data), then the import shows the edited value, never the old one (criterion 57). Test: five such edits, each a fixture pair.

### K. Safety (untrusted files)

67. Given any SVG, then the importer is a pure function from bytes to a result; it opens no file, makes no network request, runs no script and follows no reference outside the document, whatever the file asks for (`<image href>`, `<use href>` to another file, `@import`, `xml-stylesheet`, DTD, `file:` and `http:` addresses): such references are listed as `external-reference`. The SVG is never inserted into the page or the DOM of the application, and no name from a file is shown as markup (`clean_name`, text nodes only). The app sends nothing anywhere because of an import or export (R-SYS-007). Test: the hostile fixtures with a network-denying test harness and a check that no fixture string appears unescaped in the page's output.
68. Given a DOCTYPE, then the external part (`PUBLIC … "…svg11.dtd"`) is never fetched and the DOCTYPE is accepted. Internal `<!ENTITY name "text">` declarations are accepted only when every one is a plain literal (no `SYSTEM`/`PUBLIC`, no `%`, no `&` or `<` in the value), at most 64 declarations of at most 256 bytes each, and the file holds at most 100,000 references to them; this is what Adobe Illustrator's older SVG exports declare (`ns_ai`, `ns_extend`, `ns_graphs`, … used in `xmlns:x="&ns_extend;"`), and refusing it would refuse real Illustrator files and hide criterion 19(a). Anything else refuses the file by criterion 6(b), so a billion-laughs or external-entity file cannot expand or read anything (architect, 2026-10-14, `adrs.md`). The five predefined entities and numeric character references are read.
69. Given limits, then: a file above 50 MiB is refused (criterion 6); XML nested deeper than 256 elements is refused as "not an SVG drawing"; more than 500,000 elements or 5,000,000 path commands stop the import at that point, keep everything read so far, and list `limit-reached` with the number of elements after the limit; a single attribute above 16 MiB is skipped; a `stroke-dasharray` longer than 1,000 numbers is read as its first 1,000; `use` limits as in criterion 47. No limit is reached by any fixture except the hostile ones.
70. Given arbitrary bytes, then the importer neither panics nor runs longer than 5 s on a file within the limits. Test: (a) every Inkscape fixture and every hostile fixture truncated at 200 evenly spaced lengths and with 200 single bytes changed, each yields a refusal or a result in under 2 s, no panic; (b) a fuzz target with the fixtures as seed corpus runs for 60 s in the nightly job without a crash or timeout.

### L. Budgets and determinism

71. Given a native release build (`#[ignore]` benchmarks on the build host, as `0056` criterion 27), then: importing a generated SVG of 20,000 paths with 400,000 nodes in total (about 12 MB) takes under 2.0 s from bytes to a finished document; importing the same content as 5,000 groups of 4 takes under 2.5 s; exporting that document takes under 1.5 s and writes under 25 MB; opening a 100 KB Inkscape file takes under 100 ms. The browser (WASM) times are reported in the PR description, not gated. After the import, 10,000 objects work in the Layers tab without a hang (`0050` criteria 48 to 52).
72. Given the same input bytes, then the importer gives the same document (apart from freshly minted ids) and the same report in the same order, and the exporter gives the same bytes, on every run and every operating system of the same CPU family; across native and WASM builds the imported numbers agree within 1e-9 mm and the golden documents are compared with that tolerance (`sin`, `cos` and `atan2` may differ in the last bit between platform libraries; `adrs.md`): no result depends on hash-map order, the clock, the locale, the file's path or the order of threads. Test: run twice, run with `LC_ALL=de_DE.UTF-8`, compare bytes; the ids written (criterion 53) are the same.

## Out of scope

- **Text.** `<text>` is not imported (entry `text`); a text node needs a font model and is its own spec. Text converted to paths works. (Decided: criterion 49.)
- **Gradients, patterns, filters, masks, clip paths.** Gradients are not in the model (ADR 0002 §10, 2026-10-08); the substitutes of criterion 38 are the whole answer. Applying a clip path as an intersection (fill-only, closed shapes) is a possible later command (Frage 5).
- **Images.** `<image>` is not imported; tracing a raster is `0025`.
- **Animation, scripts, interactivity, `foreignObject`.** Never run, never kept.
- **Full CSS.** Combinators, attribute selectors, pseudo-classes, `@media`, `@font-face`, `@import`, `var()`, `calc()`; only the simple selectors of criterion 36.
- **A per-node passthrough bag** that keeps what we do not model and writes it back (ADR 0002 §10), so `inkstitch:` data survives a trip through Curvyo (Frage 4). Until it exists, `foreign-data` says what is lost.
- **SVG markers**, `stroke-dashoffset` and a configurable miter limit: the model has none; they are listed.
- **Compressed SVG (`.svgz`)**, other encodings than UTF-8, files above 50 MiB, entity declarations.
- **A pixel-resolution setting** (LightBurn's 72 or 96) or a dialog at open; criterion 19 detects the two known cases and the notice names the page size (Frage 6). A "scale to a size" command for a wrong guess is the existing resize with typed values (`0019`).
- **Export of a selection**, export of the page only, export to other formats (PDF, DXF, PNG), export with a chosen resolution or unit, optimised or minified output, and a "Save as Inkscape SVG" that makes SVG the project format.
- **A live link to a file** (reload when the SVG changes on disk), batch import, drag and drop of a file onto the canvas, paste of SVG text from the clipboard (all possible later, each its own entry).
- **Merging coincident end nodes**, closing gaps, removing duplicate nodes or tiny segments, simplifying paths: nothing is cleaned on import.
- **Multiple pages.** One page; `pages` is listed.
- **Embroidery, plotter and CNC specifics** of SVG (stitch data, tool metadata): `foreign-data` lists them; each machine family decides its own.
- **Chords** for Import and Export (R-SYS-009 review), a menu entry (there is no menu).
- **Mobile.**

## Decided by the product owner

Each is vetoable at the demo; none changes what the customer asked for.

- **D1. Open reads SVG too; Import SVG… adds to the project (Proposal).** The brief says "open"; the second button costs one dialog route and one history step.
- **D2. The report is a notice, a banner with two buttons and a list inside the File tab, never a pop-up and never a standing section.** (Frage 3.) The list replaces the buttons in place like the unsaved-changes block, opens only on a button, and closes on Close or Escape.
- **D3. Defined result over refusal.** Only five cases refuse (criterion 6), all of them files from which no drawing can be built or that endanger the machine; everything else imports with an entry.
- **D4. Nothing is cleaned or guessed.** No node merged, no path turned into a circle, no coincident end closed. What is in the file is in the document. Primitives come only from primitive elements, from our own data and from Inkscape's star data, and only when the drawn shape agrees.
- **D5. Transforms are applied to geometry; no transform is ever written.** The model has none and the groups carry none (`0023`).
- **D6. Our data lives in `curvyo:` attributes and yields to the plain SVG whenever the two disagree.** An edit in Inkscape is never overruled by stale data of ours.
- **D7. Export writes millimetres as the user unit, presentation attributes, absolute coordinates, `M L C Z` only,** and the Inkscape attributes that let Inkscape keep layers, locks, labels, node types and stars. The background is the namedview, not a rectangle.
- **D8. Gradients become the middle colour, patterns mid grey, clips, masks and filters are ignored,** each listed. The alternative (leave the object out) would make parts of a design vanish silently from a cut file.
- **D9. Hidden objects are imported hidden and exported hidden.** SVG has a hidden state; the machine meaning is R-MFG-005's.
- **D10. Simple `<style>` rules are supported** (Illustrator and Figma write classes; without them their files import black).
- **D11. The loss report counts affected objects, lists up to five examples with line numbers and is written in plain sentences from one table.**
- **D12. Unit conversions are exact:** 25.4/96, 25.4/72, 25.4/90; em as 16 px.
- **D13. File kind is decided by content, not extension.**
- **D14. No format change here;** the XML parser, the crate and the dependencies are the architect's and are decided in `adrs.md` (new crate `curvyo-svg-core`, ADR 0017 proposed; `roxmltree`, `svgtypes`, `simplecss`).

## Open questions

Each has a default; nothing blocks the build.

**Frage 1 (EVENODD): Even-odd fill rule on import**
Our model has one fill rule (nonzero). Inkscape writes `fill-rule:evenodd` on almost everything it draws, so the choice decides how Combine'd donuts and letters look here. *A (default, and the architect's default in `0054`):* re-wind the closed outlines by depth so the picture is identical, and list `even-odd-crossing` only where outlines cross (criteria 50 and 51). *B:* keep the written windings, draw nonzero and always list it (as `0054` criterion 27 says now); an Inkscape donut of two same-direction circles then comes in as a filled disc. Recommendation A. If unanswered: A, and `0054` criterion 27 is changed in the PR that builds this.

**Frage 2 (USE-CLONE): Clones and `<use>` (the question of `0049` Question 7)**
*A (default):* an SVG `<use>` is read as an ordinary copy, a Curvyo clone is written as an ordinary path with a note (criteria 47 and 59). *B:* a `<use>` of a path whose placement is a rotation, mirror and translation (no scale) and whose style equals its original's is read as a linked clone; a clone is written as `<use xlink:href="#path1" transform="matrix(…)">` under the same condition and as a path otherwise (SVG scales a clone's stroke, ours does not). B keeps Inkscape clones linked in both directions; it needs a clone fixture in both directions and the id of the original in the file. Recommendation A for this slice, B as its own entry when makers ask. If unanswered: A.

**Frage 3 (REPORT-PLACE): Where the list of what was not kept lives**
*A (default):* a banner in the canvas notice slot with **Show list** and **Dismiss**; the list opens inside the File tab body in place of the buttons, closes on Close or Escape, and a **Last report…** button in the File tab (shown only while a report exists) opens it again (criteria 8 to 11). *B:* the banner offers **Save report…** only, which writes a text file; nothing is shown inside the app. *C:* the list is a card over the canvas. Recommendation A: B hides the answer in a file, C is a pop-up and covers the drawing. If unanswered: A.

**Frage 4 (BAG): The passthrough bag of ADR 0002 §10**
The ADR says unmodelled attributes are kept per node and written back. Answer A deviates from an accepted, customer-signed decision, so it is recorded in a new ADR (`adrs.md`, `needs-customer`). *A (default):* not in this slice; what is not modelled is listed (`foreign-data` for other programs' data such as `inkstitch:`) and is lost when saving from Curvyo. No format change. *B:* build the bag: foreign attributes on modelled nodes survive an Inkscape trip; costs a node register, a `format_version` bump, an ADR and the question what happens to a kept attribute when the object is edited, merged or split. Recommendation A, B when an Ink/Stitch maker asks. If unanswered: A.

**Frage 5 (CLIP): Clip paths on import**
*A (default):* ignored and listed (`clip-path`), the object comes in unclipped. *B:* a clip path is applied as an intersection (Boolean) for closed filled shapes without a stroke; everything else as A. B draws clipped artwork as the file shows it (Illustrator and Figma wrap whole drawings in a clip rectangle that is harmless to ignore, but a design clipped to a circle is not). B needs the geometry kernel in the importer and a rule for strokes. Recommendation A for the MVP slice. If unanswered: A.

**Frage 6 (PIXEL-SIZE): Pixel size of files without a unit**
*A (default):* 96 per inch, except that Adobe Illustrator files are read at 72 and Inkscape 0.91 and earlier files without a viewBox at 90, each named in the notice and the report (criterion 19). *B:* always 96 and say so. *C:* a per-user setting 72 or 96 in the File tab, as LightBurn has. Recommendation A: it needs no setting and no dialog and fixes the two common wrong sizes by itself; the page size in the notice makes a wrong guess visible. If unanswered: A.

### Suggestions that the PO and customer may take (not in this spec)

- The banner ends with the first commit after an import, not only on Dismiss (the report stays in Last report…): a banner that sits over the canvas bottom for a whole session is chrome in the way of the product. The criterion says Dismiss only; left as written.
- Per-example **Select** (and "Select affected objects") for Approximated entries: those objects exist in the document, and a link from the entry to them would answer "which one is it" better than a file id. Needs ids in the report; its own entry.
- Export has no dialog: units are millimetres, the whole drawing, hidden layers written hidden (criteria 4, 52, 53, Out of scope). A "visible only" or "selection only" export is the first thing a maker sending a file to a cutter will ask for; it belongs with R-MFG-005 and needs a place that is not a dialog (a switch beside the button would be a panel section for an operation).
- **Save report…** beside Copy as text (Frage 3 B's file) is a one-button later addition.
- The default name of Export SVG… after an Open of `poster.svg` is "poster.svg", the source's name (as Save as offers "poster.curvyo"), not "Untitled.svg". The OS dialog confirms an overwrite.
