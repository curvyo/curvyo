Notes from tasks 1 to 5 (implementer, 2026-11-09):
- The rule files are flat (`curvyo-laser-core/src/operation_*.rs`, public as `curvyo_laser_core::operations`), because the `0093` tester test `ac15` reads `src/` without subdirectories.
- Tasks 3 and 4 follow ADR 0046 and the spec as of `8b14ff37` (node-id keys, Missing item, Frage 167 A and 169 B). The working tree gained, uncommitted, the customer answers 167 B and 169 A (clone member keys by path, keys removed with the deleted object). Done (Part A2): key form by path. Member keys whose path names a node no longer live are removed by `sweep_dead_member_keys`, called from `commit_step` (the one place every local step goes through), so every delete path is covered in its own step (path join test `joining_two_paths...`). Reads ignore dead keys; a key left dead by a peer's merge goes at the next local step. Goldens: `operations_v39`, `operations_unknown_kind_v39`, `operations_unreadable_v39`, `operations_dangling_v39`, `operations_clone_member_v39`. Cut-out (Frage 168 A, criterion 23): one contour per item call; parts of one item that do not touch give one contour each; overlapping items are separate calls, not merged.
- Task 7 and 8 (2026-11-10): the summary counts clone members only as far as the clone is an own leaf; the member leaves of a clone (ADR 0046 criterion 11 and 12 counts) are open. Text and primitives count as one closed outline, so their open outlines are not counted by the run rules. The leaf index is keyed on the drawing read, so a membership change also rebuilds it (ADR 0046 wanted the chain index to change with the drawing only); the release budget numbers above are with this rebuild. Frage 169 A: no missing count. The `tests/cpu_time` helper is shared; the budget file is `tests/operations_budget.rs` (CI is in the performance job).
- Task 6 (implementer, 2026-11-09): `Session` has one field `operations: OperationsState` (notice only). Commands take the active laser page's operations only. Guides and dimensions are never targets; a guide notice reads "N guide(s) not assigned. Guides and fixtures never run." (fixtures cannot be selected in this session, so no fixture count). Dimension-only selections refuse with the "never run" notice. Notes for the lead: (a) the notice names guides only, the spec text names fixtures and does not name dimensions, PO to decide; (b) the summary (AC 17) and the leaf chain / index caches are not in task 6, they go with task 7 and the budgets of task 8; (c) the wasm bridge file is `wasm_operations.rs` (wasm32 only, like its siblings).
- `run_sequence` keeps an Unknown operation with the Marking section (it keeps its place and runs nothing).
- The summary's running count includes leaves that run while hidden (criterion 17 "hold an assignment and run"); ADR 0046 §5 says the first three counts are disjoint.
