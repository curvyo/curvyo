# ADRs for "Pen angle snap and typed values: Ctrl locks the angle of the next node, a key opens a Length and Angle entry"

Drafted by the product owner on 2026-10-19 at the lead's request, from the ADRs and the code on `main`, so that the spec can be Ready. The architect confirms or corrects the feature-local decisions before the build starts. Nothing here is `needs-customer`: no new ADR, no new crate, no new dependency, no stored field, no `format_version` change, no public API change in `curvyo-document-core`.

## Feature-local decisions

- 2026-10-19: **One constraint function.** `pub fn constrain_segment(last: Point, raw: Point) -> Point` in a new small module of `curvyo-ui-core` (doc sentence: "The Pen's Ctrl rule: the point that keeps the distance from the last node and takes the nearest angle stop.") calls `snap_angle` and nothing else. The preview, the click, the handle snap (the same function with the node as `last` and the pointer as `raw`, giving a handle end) and the readout all call it, so they cannot disagree. Tests first with the examples of criteria 1 to 3. — a second angle table would split the product's one convention.
- 2026-10-19: **The target test runs before the snap, on the raw pointer** (criterion 5). `pen_target` is unchanged; the Ctrl flag is read only on the "no target" path. — keeps `0034`'s cue, chip and press exactly as built.
- 2026-10-19: **The Ctrl flag reaches the Pen through the existing `constrain` parameter** of `Session::pointer_up` and the matching move and down calls, as the shape tools receive it (`0053` adrs notes `shift` and `constrain` already passed). `modifiers_changed` forwards to the Pen so a key press with the pointer at rest redraws the rubber band (criterion 4). No new input type.
- 2026-10-19: **The entry state is a pure module next to `shape_placement.rs`** (working name `pen_entry.rs`, doc sentence "The state of the Pen's typed Length and Angle entry, from the key that opens it until Enter, Escape or a press."). It holds the reference L, `Phase::Following` or `Phase::Frozen(Kept)`, the two field texts and their edited flags. It is a smaller sibling of `ShapePlacement`, not a generalisation of it: no trait and no generic (a shared type would serve two tools with different results). Pure functions: `resolve(L, kept, unit) -> Placed` with the permit rules of criteria 24 to 28 returning the point and an optional `Notice` code (`NotANumber(field)`, `NegativeLength`, `ZeroLength`, `TooFar`), and the polar step `L + len * (cos a, sin a)` with `a` reduced modulo 360 degrees. The notices' texts live with the other canvas notices, not in the module.
- 2026-10-19: **Reuse, no copy:** lengths go through `parse_length(text, unit)`, angles through `parse_entry_number(text, true)`, the coordinate limit through `transform_commit::is_sane`'s limit, the live segment's decimals through the create-drag readout formatter. The chip is `PlacementChip.tsx`'s surface and field component with two fields; if its field row is inline, it is made a shared component in this slice (as `0052` decision 1 did for the move chip) and not copied.
- 2026-10-19: **A typed node enters the path in progress exactly like a click.** The Pen's existing "add corner node at point" path is called with the resolved point, so the node kind, the handles of L, the order for a continuation (`0034` criterion 4) and the finish commit are the existing ones. No new commit label and no new history step; criterion 32.
- 2026-10-19: **The key gate.** Tab is handled in `session/key_table.rs` as `KeyAction::OpenPenEntry`, only for the Pen tool with a last node, no button held and no Ctrl, Alt or Cmd; with a button held it is consumed with no effect. `Session::operation_in_flight()` gains "the Pen entry is open" next to the placement line (so letters, chords and file chords are gated while the chip is open, as for a placement). The Escape cascade gets the open chip as step 1 through the existing "open chip" arm: the chip calls `cancel_pen_entry()` and returns focus. Tab inside the chip is handled by the chip (`preventDefault`), as in `PlacementChip.tsx`.
- 2026-10-19: **Cancel triggers** are those of `0052` decision 6: Escape, a tool switch (`set_tool` calls `cancel_pen_entry()`), and one capture-phase `pointerdown` listener mounted only while the chip is open, for a press outside the canvas and the chip. A press on the canvas is not a cancel: it adds the typed node when frozen (criterion 20) or is an ordinary Pen press when not.
- 2026-10-19: **Wasm surface.** The chip view (labels, texts, units, frozen flag), `pen_entry_edit(field, text)`, `pen_entry_place()`, `cancel_pen_entry()`. No change to `wasm_api.rs` beyond these; the Ctrl readout is a draw-list text item from `render-core`, not a DOM element.
- 2026-10-19: **Performance.** The snap is O(1) per pointer move (criterion 10); one `#[ignore]` release benchmark records the pointer-move cost with a path in progress and the one `resolve` per keystroke (under 1 ms, as `0052` decision 7). No real-window frame check beyond what `0052` did.
- 2026-10-19: **Collisions.** Shared files with `0055` (`pen_tool.rs`) and `0032` (`key_table.rs`, `session/keys.rs`, tool rail); merge conflicts, not design conflicts. The slice is not built beside either (`CLAUDE.md` §4, two implementers only on disjoint crates).
- 2026-10-19: **Tests at risk.** Pen tests that press Tab (none expected) and the key-gate table tests, which get a "Pen entry open" row. No existing Pen test uses Ctrl as a "no effect" case (the implementer greps and lists any in `plan.md`).
