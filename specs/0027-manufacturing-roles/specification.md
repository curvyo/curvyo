# Manufacturing roles: tell the laser per layer what to cut and what to engrave, and see it on the output page

Status: Ready (2026-11-04; Fragen 140 to 142 open with defaults A; ADR 0041; UX notes items 2 to 5 accepted by the lead as Proposals: notice above the rows, white casing on Cut lines drawn above Engrave, 2 px Engrave lines for all-open leaves, read-only lock glyph)
Priority: Must
Origin: Customer (R-MFG-002, MVP slice 14: "assign manufacturing roles to geometry (e.g. cut / engrave) within one file, so one drawing can drive one job with mixed operations"; customer picked this story on 2026-11-04). Also settles as far as this slice needs it R-MFG-005 "visible versus output" (the customer left it open on 2026-10-11 and asked for it to be decided with the manufacturing view). Everything marked Proposal is the product owner's and vetoable at the demo.

## User value

As a maker with a laser I want to say, layer by layer, which part of my drawing is cut, which is engraved and which stays out, and to see that on the output page of my machine, so that one drawing can drive one job with mixed operations and I can check the plan before any job exists, without my drawing changing.

**One-line meaning (Proposal, Frage 140, to confirm at the demo):** a role says what the laser does with the content of a layer: **Cut** follows the outlines, **Engrave** burns the surface, **Ignore** leaves it out of the job. A role is not a power, a speed or a material (`0028`), and it is not a toolpath (`0029`).

**What other tools do.** LightBurn: 30 colour-indexed layers; an object gets its layer from its stroke colour, and each layer has a mode (Line, Fill, Fill+Line, Image) and separate Show and Output switches. Everything is decided by a drawing colour, so the drawing carries the machine plan and one file serves one setup. Inkscape has no roles; laser plug-ins read layer names or stroke colours. Illustrator-to-Epilog/Trotec workflows use the "red hairline cuts, black fill engraves" convention. Ink/Stitch puts parameters on objects. Fusion 360 keeps operations in a Manufacture setup that references the design. We take the Fusion idea and LightBurn's Show/Output split: **the role lives in the manufacturing, keyed by the drawing's layer, so the drawing is never touched and the same layer can be Cut in one manufacturing and Engrave in another.** We do better than LightBurn in that no stroke colour has to be abused as a machine instruction, and the output page shows the plan in a form that cannot be mistaken for the drawing's own colours.

## Acceptance criteria

1. Given the Laser tab of a laser manufacturing (`0093`), then it has a **Layers** block (inline, no popup) below the Machine block (position is the ux-engineer's) with one row per layer of the drawing, front-most first as in the Layers tab (`0050`), each row showing the layer name, a state glyph for "hidden in the drawing" (read only, criterion 14) and a role control (criterion 2). When the drawing has objects that are in no layer, the block has one more row at the end, "Objects outside layers" (criterion 11). A drawing without layers and without loose objects shows the hint "The drawing has no layers yet." and nothing else.
2. Given a row, then its role control is three toggle buttons, **Cut**, **Engrave** and **Ignore** (text labels with a glyph each, `aria-pressed`, arrow keys move between them, at least 24 x 24 px). At most one is pressed. With none pressed the layer is **Unassigned**: the row says "No role" in muted text. Pressing the pressed button clears the role again (Proposal). The role of a hidden or locked layer can be changed like any other.
3. Given any layer, including every layer of an existing drawing when a manufacturing is added and every layer created later, then its role is **Unassigned** and nothing is stored for it (Frage 141, Proposal A). Add manufacturing writes no role. Nothing is ever assigned for the maker by layer name, colour or content. A layer that is duplicated or pasted is a new layer and starts with no role, whatever role its source has (ADR 0041, Consequences).
4. Given a role button pressed, then (a) the role is set for that layer in this manufacturing only, (b) the output page shows it in the next frame (criterion 6), (c) the whole action is **one undo step** named "Set role" (History tab, `0020`), and redo restores it, (d) pressing the same state again adds no step. Test: a project with layers A and B and two manufacturings M1 and M2; set A to Cut in M1; M2 still shows A as "No role"; undo makes M1's A "No role" again; the saved registers of the drawing's nodes (layers, objects, pages, styles) are byte-identical to before in every step (the drawing never changes; `0093` criteria 5 to 7).
5. Given the roles of a manufacturing, then they are stored **in that manufacturing, keyed by the id of the drawing's layer**, as one register per layer on the manufacturing, key `x.curvyo.laser.role.<peer:counter>` (the layer's node id in text form, e.g. `x.curvyo.laser.role.3:17`), value the string `cut`, `engrave` or `ignore`, absent meaning Unassigned (ADR 0041 §1, extending ADR 0033 §3), never on the layer or the objects. Clearing a role deletes the register. Given two copies of the same document in which one peer sets layer A to Cut and the other sets layer B to Engrave, when they merge, then both roles survive (per-layer merge, ADR 0009 §3; the exact shape is the architect's, a single atomic map would lose one of the two and fails this test). Given the same layer set in the same manufacturing by both peers to different roles, then one of the two wins as for any register.
6. Given the **Role view** (a switch in the Layers block, on by default; view state, not saved in the file, not an undo step, on again at start, Proposal), when it is on, then the output page draws every placed leaf by the role of its layer instead of its own style; the exact colours are tokens the ux-engineer defines (Proposal names `--role-cut`, `--role-engrave`, `--role-ignore`, each at least 3:1 against the output page), and **the three looks differ by shape as well as by colour**:
   - **Cut:** the outline only, a solid line one screen pixel wide at any zoom, no fill.
   - **Engrave:** the area filled flat, no outline.
   - **Ignore and Unassigned:** a muted dashed outline, no fill (the Laser tab says which of the two it is).
   When the switch is off, the output page shows the placed content as drawn, as `0093` criterion 5 did (Proposal, so the look of `0093` stays reachable). A legend of the three looks sits in the Layers block.
7. Given a leaf with a role, then its own style is ignored: stroke colour, stroke width, dash, markers, fill colour, fill opacity and object opacity change nothing about what is drawn or later output (a 5 mm wide stroke in a Cut layer is cut along its centre line; **Stroke to path** (`0085`) is how the maker cuts the outline of a wide stroke). Fill rule is the exception: Engrave fills a path by the fill rule the object has. Test: two copies of one rectangle, one with a 10 mm red stroke and no fill, one with a blue fill and no stroke, both in a Cut layer, draw the same single hairline; both in an Engrave layer draw the same filled area.
8. Given the kinds of content, then (a) **closed paths, compound paths and primitives:** Cut traces every outline; Engrave fills the area; a compound path with open outlines (`0054`) is traced as drawn for Cut and filled with its open outlines closed by a straight line for Engrave; (b) **open paths:** Cut traces them; under Engrave the rule for every leaf is one sentence: a leaf with at least one closed outline is filled (its open outlines closed by a straight line), a leaf whose outlines are all open (an open path, a single-line text) is drawn as a line (Frage 140 A, Proposal); (c) **texts:** as their outlines, a single-line text (`0076`) as its centre lines, so Engrave of a single-line text is the line; (d) **linked clones** as the paths they show, taking the role of the layer the *clone* is in, not that of its original; (e) **groups** as their members, at any depth; (f) **images** (`0058`) can only be engraved: in an Engrave layer they are drawn as a grey-scale preview of the working image at their place, in a Cut, Ignore or unassigned layer they are drawn as their frame in that role's look and are not output (notice in criterion 15).
9. Given a leaf, then its role is that of the **layer that holds it** (the top-level layer above it, however deep in groups). A leaf moved to another layer in the Vector workbench takes that layer's role at once on the output page.
10. Given a drawing in which the same layer holds objects on several pages (`0059`, layers are shared), then the one role of the layer applies to all of them, in every placement.
11. Given objects that are in no layer (loose top-level objects and groups, `0050` criterion 5), then the extra row "Objects outside layers" holds their role under the reserved key `x.curvyo.laser.role.outside` (not a layer id); it is Unassigned by default like any layer, and shown only while such objects exist (the stored role is kept when none exist).
12. Given **guides** (`0046`) and **dimensions** (`0070`), then they are never drawn on the output page, never output and never counted, whatever the role of their layer (they are not output in the drawing either). **Fixtures** of `0093` are not content of a layer and have no role.
13. Given **locked** (`0050`), then a locked layer or object is output like any other (a lock protects editing, not output; this stands as the `0050` ADR 0015 §2 reading, "locked is output", and is confirmed here). Given **opacity**, then it is view only: a leaf at 0 % opacity is drawn on the output page in its role's look at full strength and is output (Proposal: the output page shows what runs, never less).
14. Given **hidden** (the eye of `0050`, R-MFG-005, Frage 142, Proposal A), then an effectively hidden layer, group or object is **not drawn on the output page and not output**, in every role; its role stays stored, its row in the Layers block shows the hidden glyph and the caption "Hidden in the drawing: not output", and showing it again in the Vector workbench brings it back on the output page with its role. "Visible" and "output" are therefore two switches as in LightBurn in one direction only: a visible layer with the role **Ignore** is shown dimmed and is not output; there is no way to output something that is hidden. Test: layer A is Cut and hidden; Laser shows nothing of A and the Layers block marks it; unhide in Vector, Laser draws A as Cut again, role unchanged.
15. Given the Layers block, then below the rows one notice line counts what will not run, in at most 70 characters each, each shown only when its count is above zero: "2 layers have no role and are not output." (layers that are Unassigned and hold at least one output-capable object; **output-capable** means a visible leaf that is not a guide or dimension, an image included because it can be engraved; an empty layer or a layer holding only guides, dimensions and hidden objects is not counted), and "1 image in a Cut layer is not output." Nothing blocks, refuses or moves anything (permit; the gate that asks before export is `0029`).
16. Given the drawing is edited in the Vector workbench while the Laser tab is open (split view or switching), then the Layers block follows without a refresh: a new layer appears as "No role", a renamed layer shows its new name, a reordered layer moves, a deleted layer's row disappears, an object moved between layers is drawn in its new layer's role.
17. Given a layer that is deleted in the Vector workbench, then its role entry **stays in the file** (the drawing command does not write the manufacturing; Proposal) and is ignored and shown nowhere; undo of the deletion brings back the layer with its role. Given a role entry whose layer id does not exist (deleted layer, a file from a peer), then the file opens without error, nothing is shown for it, it is never rewritten or removed on read, and it is saved back unchanged.
18. Given a file in which a role value is not one of "cut", "engrave", "ignore" (a newer build wrote another role, or the value is not a string), then the layer reads as Unassigned, the row shows "Unknown role in file, treated as no role." (at most 70 characters), the layer is not output, and the value is never rewritten on read (ADR 0033 §3); pressing a role button replaces it in one undo step. A file in which a role key holds a container value instead of a plain value is refused as damaged (ADR 0041 §3, the open check for any container value under `x.*`).
19. Given a project with a laser manufacturing that has layers A (Cut), B (Engrave), C (Ignore), D (Unassigned), a role entry for a deleted layer id, and one layer with the unknown role "score", when it is saved and reopened, then every role, the stale entry and the unknown value are identical, the output page looks the same, and the file passes the golden-file test `laser_roles_v36.curvyo` (`curvyo-document-core/tests/fixtures/`); the slice does not change `format_version`, which stays 36 (ADR 0041 §7). A file from before this slice (`laser_workbench_v36.curvyo`, `machine_profile_v36.curvyo`) opens with every layer "No role" and writes nothing until the first edit. A build with the Laser extension switched off keeps the roles in the file and writes none (`0093` criterion 11).
20. Given a manufacturing is deleted (`0093` criterion 13), then its roles go with it, the drawing is untouched, and undo restores them.
21. Given a drawing with 1,000 objects in 10 layers, when a role is set, then the role set plus the next frame (`set_layer_role` followed by `frame_draw_list`, Laser tab open, 1,000 rectangles) cost together at most 50 ms of thread CPU; given 200 layers, then the Laser tab's view including the Layers block (`manufacturing_view_json`) costs at most 100 ms of thread CPU. Both are two tests in `curvyo-editor-wasm/tests/manufacturing_budget.rs`, release build, measured with `tests/cpu_time/` (thread CPU time, never wall time); budgets confirmed by the architect (adrs.md note 6).
22. Given the placed content on the output page, then it stays read-only (`0093` criterion 7): clicking a placed object does not select it and nothing in the drawing changes; the role is changed only through the Layers block.
23. Given the Vector workbench, then it is unchanged by this slice: the Layers tab, the canvas, Export and Print show no role, and a drawing exported or printed from Vector is the same with or without roles.
24. Given the whole slice, then there is no power, speed, passes or material (`0028`), no toolpath, preview, gate or G-code (`0029`), no network access, no device and no telemetry (`R-SYS-002`, `R-SYS-007`). The roles are stored and shown only: nothing reads them to produce output yet.

## Decided here as far as this slice needs it (R-MFG-005, Proposal until the customer answers Frage 142)

- **Output switch per layer = the role Ignore** (and "No role"). A per-object output switch is not built; moving the object to another layer does the same (the Layers tab of `0050` drags between layers).
- **Hidden is not output** (criterion 14), **locked is output**, **opacity does not matter** (criterion 13).
- Guides, dimensions and fixtures are never output (criterion 12).

## Questions for the customer

Frage 140 (ROLE-MEANING): What exactly do Cut and Engrave mean for the laser?
- A (recommended, criteria 6 to 8): **Cut** follows every outline of the layer's objects, open or closed, ignoring fills. **Engrave** burns the closed areas (fill), draws open paths as a line, and is the only role for images. **Ignore** is left out. Two layers (an Engrave layer and a Cut layer with the same shape) are how a maker engraves a shape and then cuts it out.
- B: Engrave burns closed areas only; an open path in an Engrave layer is not output and counts in the notice of criterion 15.
- C: LightBurn's names and modes: **Line**, **Fill** and **Fill+Line** (engrave the area, then follow the outline, in one layer). More direct for engrave-then-cut, but the words Cut and Engrave from the requirements disappear and `0028`/`0029` get a mode to handle more.
Default if unanswered: A. (A role is added later as a new stored value without a format change, so C's Fill+Line can still follow.)

Frage 141 (ROLE-DEFAULT): What role does a layer have before the maker assigns one?
- A (recommended, criterion 3): none ("No role"); it is not output and the Layers block counts it. Nothing runs by accident; the cost is one click per layer after Add manufacturing.
- B: Cut. The page looks busy at once, as in LightBurn, but a forgotten layer cuts through the material.
Default if unanswered: A.

Frage 142 (HIDDEN-OUTPUT): What does a layer or object that is hidden (eye off) do in the machine output?
- A (recommended, criterion 14): it is not drawn on the output page and not output; "what you see on the output page is what runs". Ignore is the output switch for things you want to see but not run.
- B: LightBurn's two independent switches: hidden things stay output if they have a role (drawn or not on the output page). Lets you hide clutter while working and still run it, but something invisible can burn.
- C: hidden is not output, but the output page draws it faded so you see what is missing.
Default if unanswered: A. (Locked is output in all three; this question is the open part of R-MFG-005.)

## Changes to accepted text (Proposal)

- `0093` criterion 5 and 6 ("the output page shows exactly the new drawing"): the geometry stays exactly the drawing; its look on the output page becomes the role look while the Role view switch is on (criterion 6). With the switch off the look is as `0093` shipped it. No criterion of `0093` is reworded; its tests run with the switch off.
- `0050` criterion 24 and 54 ("makes no statement about output") and ADR 0015 §2 ("hidden is not output, locked is"): the hidden reading is now decided here (Frage 142), the locked reading is confirmed. Criterion 54's statement about the save and `document.json` stays true: they carry hidden nodes.

## Out of scope

- Power, speed, passes, line interval, air assist, Z offset: `0028` (the material record and the test grid). A role here carries none; the manufacturing stores nothing about them.
- Toolpaths, preview, time estimate, the machine and material gate, G-code export, raster engraving of images, cut order and path ordering, kerf and tabs: `0029`.
- A **Score** role (a shallow cut): it is a Cut with its own power and speed, so it waits for `0028`; the stored values are strings, so adding it later needs no format change.
- A role per object or per path (a per-object override or output switch, R-MFG-005's remainder), roles by stroke colour, roles by layer name, roles for groups: move the object to another layer instead. Add later when makers ask.
- Setting a role from the output page by clicking a placed object (it stays read-only), a "select the layer's objects" button, multi-select of layers for one role, "same role for all", copying roles between manufacturings, a default role per layer stored in the drawing.
- Clean-up of the role entries of deleted layers (they stay in the file, criterion 17).
- Showing roles in the Vector workbench (a chip in the Layers tab, a role colour on the canvas).
- Other machine families and their roles (cutting plotter pen/cut, CNC pocket/profile, embroidery fill/satin); the same layer may get another role in another manufacturing, which the keyed storage already allows.
- Dimensions and guides as machine content, fixture jobs (`0063` stage 6).
