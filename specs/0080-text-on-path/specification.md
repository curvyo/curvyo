# Text on path: put a text on paths and shapes, keep it editable text

Status: Done (2026-10-26, customer; slice 1 PR #190, slice 2 PR #193; ADR 0022 accepted; was Ready for slice 1 on 2026-10-24)
Priority: Should
Origin: Customer (request of 2026-10-23, translated: "Put text on path. Text always stays text until you do Object to path — no matter how distorted, rotated, put on paths, ... it must always stay editable text. 'Text on path' is a button in the tool bar for text; after it you select paths. You can select several; then the text is put on all paths as linked clones. You can change the position on the path individually (by handles in the drawing), either on top of the path or below it, either with the top edge or with the baseline. You must be able to mirror the text, or rotate it (if it is a circle). You should also be able to put texts on circles, rectangles, stars, polygons that are not paths."). Every criterion marked **(Proposal)** is the product owner's idea and is not accepted until the customer says so.
Depends on: `0074` (text node, Text bar, Object to path), `0078` (Style group), `0049` and `0057` (linked clone, own style), `0003`, `0013`, `0021` (rectangle, ellipse with arcs, polygon and star with curve: primitives that stay primitives), `0016` and `0054` (compound paths, open outlines), `0046` (guides), `0056` (Flip), `0020` (one step per interaction). Companion: `0079-text-layout-controls` (alignment, letter and word spacing, rotation of letters, writing mode, the per-letter taper "Kegelverzerrung"), written in parallel; this spec uses its controls and does not repeat them.

## The operation in one line (Frage 33)

**Text on path places each letter of a text along a path or shape, standing on one side of it and touching it with its baseline or its top edge; the text stays editable text, follows every later change of the path, and becomes paths only by Object to path.**

## User value

As a maker who engraves round badges, curved names on wooden plates and lettering along the edge of a lid, I want to put a text on a circle, a rectangle, a star or any path I drew, move it along the shape with a handle, put it outside or inside, and still fix a typo or change the font afterwards, so that I do not have to convert the lettering to paths and set it again for every change, and so that one name can run along several shapes at once.

**Field reference (what the other tools do).**

- *Inkscape* ([manual](https://inkscape-manuals.readthedocs.io/en/latest/text-on-path.html)): select a text and a path, Text > Put on Path. SVG `<textPath>` with `startOffset` (length or percent) and, since SVG 2, `side="left|right"`. Kerning and letter spacing are kept; letters are rotated rigidly to the tangent at their middle. Text longer than the path is hidden. The path stays visible and is output with its own stroke; deleting it leaves the text invisible (an orphaned `<textPath>`) until Remove from Path. Shapes (circle, rect) work since 1.0 through the SVG 2 `path` attribute but are buggy in practice; most tutorials convert the circle first. No on-canvas handle for the start: the maker types the offset in the XML editor or moves letters with kerning keys.
- *Illustrator* ([Help](https://helpx.adobe.com/illustrator/using/creating-type-path.html)): Type on a Path tool, brackets for start, centre and end on the path; dragging the centre bracket across the path flips the text. Options: effects Rainbow (rigid, default), Skew, 3D Ribbon, Stair Step, Gravity; Align to path: Ascender, Descender, Center, Baseline; Flip; spacing at sharp turns. Overflow is hidden behind a red plus. One text per path; the path loses its stroke and fill when it becomes a type path.
- *Affinity Designer*: the Artistic Text tool on a curve or shape; a start and an end handle; "Reverse path direction"; shapes stay shapes. Text beyond the end is hidden.
- *LightBurn* ([Text reference](https://docs.lightburnsoftware.com/2.1/Reference/Text/)): "Apply Path to Text" with an Offset field and a Distort toggle (letters bent with the curve or left rigid); a Bend slider for a simple arc. The text stays editable only while the path exists: the docs say "you cannot delete the path", so makers hide it on a layer that is not output.
- *Cricut Design Space*: a Curve slider bends a text into an arc of a circle only; no other path.
- *Where we do better.* (1) **Any shape, as it is:** a circle, an ellipse arc, a rectangle with radii, a polygon or a star carries text and stays a primitive with its handles (customer rule: keep primitives). (2) **Handles in the drawing:** the start of the text is a handle on the path, dragged along it and across it; no offset field to guess. (3) **One text on several shapes** as linked text clones: fix a letter once, every copy changes, each keeps its own place (nobody of the five has this). (4) **The text never stops being text** (customer rule), whatever the path does; even deleting the path does not lose the curve (Frage 36). (5) The line that touches the path is the baseline or the top of the capital H, so a 10 mm text sits exactly 10 mm deep inside a ring (Frage 38).

## Terms

- **Carrier:** the path or shape a text is put on. Kinds: path (open or closed), one outline of a compound path, rectangle, ellipse (whole or arc, `0021`), polygon, star, a linked clone of a path (its resolved outline, `0049`), and any of these marked as guide (`0046`).
- **Text on path:** a text object (`0074`) that refers to a carrier. Its letters are laid out along the carrier's outline; it is still a text object (string, face, size, style).
- **Carrier direction and start:** the direction in which arc length grows along the outline, and where it is 0. Path: from its first node, in node order. Compound path outline: the picked outline's first node. Rectangle: the top-left corner of its own frame (the start of the top edge after the corner radius), clockwise on screen. Ellipse: the 0° point of its own frame (the rightmost point before rotation), clockwise on screen (y down, the angle convention of `0072`); an arc runs from its Start to its End angle (`0021`). Polygon and star: the first vertex (for a star its first tip, as its Angle sets it), clockwise. A rotated or flipped shape carries these with its transform.
- **Side:** **Above** = the letters lie on the left of the carrier direction (for a clockwise circle: outside; for a path drawn left to right: above it); **Below** = on the right.
- **Line on path:** the line of the text that lies on the carrier: **Baseline**, or **Top edge** (the top of the capital H, that is Size above the baseline, Frage 38). The letters always read upright for a viewer on their side; the reading direction follows from Side and Line: Above with Baseline and Below with Top edge read in the carrier direction, the two others against it. The letters are never mirror images unless Mirror letters is on (criterion 19).
- **Position:** the arc length in mm from the carrier start to the text's **middle** on the line on path: the middle of the extent of all its lines, whatever `0079`'s alignment says (the alignment only aligns the lines among themselves). Customer 2026-10-24; it was the start of the line before.
- **Distance (Proposal):** a gap in mm between the carrier and the line on path, positive away from the carrier towards the letters' side. If `0079` defines a baseline shift, it is the same value and one control.
- Lengths in millimetres; geometric tolerance 0.01 mm; notices at most 70 characters in the canvas notice slot, as in `0074`.

## Acceptance criteria

### Part A: putting a text on a path

1. Given the Text tool with a text in edit mode or selected, or the Select tool with one or more texts selected, then the Text bar and the Select bar's Text group (`0074` criterion 11) have a button **On path** (customer: "a button in the tool bar for text"). It is present whenever a text is the subject. It is enabled with exactly one text among the subjects; with two or more it stays in place, disabled, and its tooltip names the state ("3 texts selected") (Proposal, UX §0.6). On a text that is on a path already it starts pick mode too; the click moves the text to the new carrier, Side, Line, Distance and Mirror letters kept, Position at the default of criterion 5, one step "Put text on path"; the old carrier stays a guide (Proposal, UX §0.5).
2. Given On path pressed with exactly one text as subject, then the pointer enters **pick mode**: every carrier under the pointer shows the hover box of `0014` along its outline (for a compound path only the outline under the pointer), shapes in groups included without entering the group; objects that cannot carry text (texts, groups as a whole, images, layers) show no hover. A click on a carrier puts the text on it and ends pick mode; Shift+click adds the carrier to a pick set and stays in pick mode; Enter or a second press of On path puts the text on the pick set (slice 2) and ends; Escape or a right click ends pick mode and changes nothing. A click where no carrier is changes nothing and stays in pick mode. While the pointer is over a carrier, the text is drawn on it at its default placement (criterion 5) in the preview look of `0009`; the straight text stays drawn where it is (Proposal, UX §0.3). Pressed from edit mode, edit mode commits first; after the put, Escape or a right click, edit mode resumes on the same text with the caret at the same character index (Proposal, UX §0.4).
3. Given the Select tool with exactly one text and one or more carriers selected, when On path is pressed, then the text is put on the selected carriers at once without pick mode (Inkscape's route); with one carrier this is slice 1, with several slice 2.
4. Given a text put on a carrier, then the carrier **becomes a guide** (`0046`: drawn green and dashed, not output) in the same step (Frage 35, decided B); a carrier that is a guide already stays one. Nothing else changes: a rectangle, ellipse, arc, polygon or star stays that primitive with its parameters and handles (no conversion, customer rule), a path keeps its nodes, its style and its layer, and pressing Guide off later makes it a drawn, output object again with its old style. The text stays on it either way. No notice (the guide look shows it). A carrier on a locked layer stays as it is and is not made a guide; the text is put on it anyway (criterion 7; Proposal).
4a. Given a text released from its carrier (criterion 23), the text removed, or the text converted by Object to path (criterion 29), then the carrier **stays a guide** (Proposal: nothing changes behind the maker's back a second time, other texts may still be on it, and Guide off is one press). Undo of "Put text on path" brings back the carrier's role from before.
5. Given a text put on a carrier, then its defaults are Side Above, Line Baseline, Distance 0; on an open carrier the text's start lies at the carrier's start (Position is half the text's width, customer 2026-10-24); on a closed carrier the text's middle lies at the topmost point of the carrier as drawn (12 o'clock on a circle; for several topmost points, the one first in carrier direction) (Proposal). The text keeps its string, face, size, style and `0079` settings; its own transform from before (rotation, skew, stretch, `0074` criterion 26) is dropped, and Size is unchanged.
6. Given a text put on a path, then it is one history step "Put text on path" (`0020`), the carrier's change to a guide included; Undo gives back the straight text where it was, with its old transform, and the carrier with its old role.
7. Given a text on a locked layer or a carrier on a locked or hidden layer, then putting on is allowed for the carrier (it is only read and, on a locked layer, not made a guide, criterion 4) and refused for a locked text with the Pen's lock notice of `0074` UX §1.

### Part B: how the letters sit

8. Given a text on path, then each letter (each shaped cluster of `0074` criterion 5, kerning and ligatures kept) is placed rigidly: the middle of its advance on the line on path lies on the carrier (offset by Distance along the normal) at its arc length, and the letter is turned to the carrier's tangent there (Illustrator's Rainbow, Inkscape's behaviour). The letters are not bent. Arc lengths follow from the shaped advances plus `0079`'s spacing, measured along the carrier.
9. Given a straight carrier (a path of one line segment from (0, 0) to (100, 0)), then the text on it with Above, Baseline at the default Position of criterion 5 (half its width) draws the same outlines as the straight left-aligned text with its anchor at (0, 0), within 0.01 mm.
10. Given a circle of radius 50 mm centred at (100, 100) and a text "H" of Size 10 mm with its middle at the top (criterion 5), then: Above + Baseline: the H stands outside the circle, its baseline middle at (100, 50), its top at y = 40, upright. Below + Top edge: the H hangs inside, its top middle at (100, 50), its baseline at y = 60, upright. With the H's middle moved to the bottom (Position at the 90° point): Above + Top edge: the H lies outside, top middle at (100, 150), baseline at y = 160, upright and reading left to right; Below + Baseline: inside, baseline middle at (100, 150), top at y = 140, upright. All within 0.01 mm. (The four cases of a round badge.)
11. Given a text on a carrier with corners (rectangle, polygon, star, a path with corner nodes), then a letter whose middle falls on a corner takes the tangent of the side its middle lies on (at the corner point itself, the incoming side); letters may overlap at inner corners and spread at outer ones; nothing is refused (permit over refuse; spacing at corners is out of scope).
12. Given a text of several lines (`0074` criterion 4), then line k (counted from 0) is laid out exactly as line 0 with Distance increased by k line heights, in the direction from the letters' top edge to their baseline, so the lines stack as they do in a straight text; every line starts at the same Position (or is aligned there by `0079`). Test: two lines "H" / "H" at Size 10 mm on the circle of criterion 10, Above + Baseline, at the top: the second H's baseline middle is at (100, 50 + line height) within 0.01 mm.
13. Given a single-line font (`0076`), then the text on path is drawn as centre lines with the text's stroke, never filled, as a straight single-line text is.
14. Given a text on path whose face is missing (`0074` criterion 29), then it is laid out on the carrier with the substitute face and tagged "Font missing", as a straight text.

### Part C: handles and controls

15. Given a selected text on path (Select tool or Text tool), then a **position handle** sits on the carrier at the text's middle (customer 2026-10-24): a parameter handle in the look of the `0021` arc handles (UX decides the shape). Dragging it slides the text along the carrier: the text's middle follows the point of the carrier nearest to the pointer; on a closed carrier it passes the start without a jump. Live preview in the look of `0009` (since the customer note of 2026-10-27 there: the text is drawn as itself at the new place, its ghost outline stays at the old one), one step "Move text on path" on release, Escape cancels the drag. With Ctrl held the text's middle snaps: on an open carrier or an arc to its start, middle and end; on a closed carrier to its start, the quarter lengths from it and the default point of criterion 5; on an ellipse to the 15° and 22.5° stops of the arc handles (Proposal, UX §0.9, §3.3). While one or more texts on path are selected, each one's carrier outline is drawn as a thin solid line over the guide dashes (the **carrier line**, also for a carrier on a locked layer and a kept outline of criterion 25) (Proposal, UX §0.10, §4).
16. Given the position handle dragged across the carrier, more than 8 screen px to the other side, then Side switches (Above ↔ Below) and Line switches with it (Baseline ↔ Top edge), so that the text crosses the path and keeps its reading direction (Illustrator's centre-bracket flip); dragging back switches back; one step on release (Proposal).
17. Given a selected text on path, then a **double-click on its position handle** opens the handle's **entry box** (the handle entry chip of `0008`, `0052` and `0072`: a chip at the handle, Tab cycles its fields and buttons, Enter commits, Escape closes it without a change; customer 2026-10-24) with: **Position** (mm; on an ellipse carrier degrees in the convention of `0072` instead, Proposal), **Distance** (Proposal, mm, may be negative), **Side** (Above, Below), **Line** (Baseline, Top edge) and **Mirror** (criterion 18). Its buttons preview on the canvas; Enter writes one step: "Change text side", "Change line on path", "Mirror text on path" (Side and Line both swapped), "Move text on path" or "Change distance on path" when only that changed, "Change text on path" for several, nothing when nothing changed. The bar (Text bar and Select bar Text group) shows only **Release from path** (criterion 23) for it, on row 2 after Writing mode, Glyph orientation and Glyphs (Proposal, UX §0.1; the Taper is in the Fonts tab since 2026-10-25); the row-2 dot of the expand button still says a subject text is on a path.
18. Given **Mirror** pressed (Frage 34, decided C), then the text moves to the other side of the carrier and keeps its reading direction: Above + Baseline ↔ Below + Top edge, Above + Top edge ↔ Below + Baseline; the text's middle stays where it is on the carrier (customer 2026-10-24). One step "Mirror text on path" (in the entry box of criterion 17, written on Enter).
19. Given the Flip horizontally or Flip vertically button of `0056` on a text on path (Frage 34, decided C), then **Mirror letters** toggles: every letter is drawn as its own mirror image about its own vertical axis and the reading order reverses, so the line reads correctly from the back of a clear material; the carrier is not flipped and the text's middle stays where it is (customer 2026-10-24). Pressing again turns it off. One step "Flip". Object to path gives the mirrored outlines.
20. Given a text on an ellipse carrier (whole or arc), when it is selected with the Select tool, then the rotate handles of the selection box are shown and rotate the text about the ellipse's centre: on release Position changes so that the text's middle moves by the dragged angle along the ellipse (for a circle exactly that angle; for an ellipse the point at that parametric angle); the typed rotate entry `R` does the same, turning about the text's middle (customer 2026-10-24). 22.5° snap of `0008` applies. One step "Move text on path" (customer: "rotate it, if it is a circle").
21. Given a selected text on any other carrier, then the selection box shows no rotate, skew or edge handles; a corner drag with Ctrl scales Size uniformly (`0074` criterion 26, the text's middle fixed on the carrier); a corner drag without Ctrl does the same (a text on path has no stretch). A move drag of the text's body slides it along the carrier as the position handle does (criterion 15) and never takes it off the carrier. Arrow-key nudge: Right and Left move Position by 1 mm (Shift 10 mm) in and against the text's reading direction (not the carrier direction); Up and Down change Distance by 1 mm (Shift 10 mm), Up towards the top of the letters; one step per held run, as "Nudge" (Proposal, UX §0.7).
22. Given the text and its carrier selected together, then move, rotate, scale, skew and flip act on the carrier as for any object (a primitive stays a primitive where `0047` and `0056` allow it) and the text follows the transformed carrier; Size is not scaled by a carrier transform, except a uniform Ctrl corner scale of the pair, which scales Size by the same factor.

### Part D: follow, release, delete

23. Given **Release from path**, then the text becomes a straight text again: its anchor at the point where its first letter's baseline start was, turned by the carrier's tangent angle there (so the first letter does not move; Proposal), Size and style kept; the carrier is unchanged and stays a guide (criterion 4a). One step "Release from path". Typing then lays it out straight.
24. Given any edit of the carrier (node, handle or segment drag, Join, Split keeping the object, a parameter handle such as radius, corner radius, sides, Curve, Start and End of an arc, a transform of the carrier alone), then the text follows in the same frame during the drag (preview) and after the commit; Position (arc length) is kept and clamped by criterion 26 if the carrier got shorter. The text is not written by a carrier edit.
25. Given the carrier is removed (Delete, a Boolean operation, Combine, Split, Break apart, Cut, Fracture, Flatten, Object to path of a primitive that gives a new id), then by Frage 36 (decided A) the text keeps the carrier's outline as it was just before, as a carrier of its own that is not drawn and not output; the text looks exactly as before, stays editable, its position handle still works, and the Layers row tooltip adds "On a deleted path"; Release from path straightens it. Same step as the removing command; the notice adds "1 text kept its path." Undo brings the carrier back and the link with it. Object to path of a primitive keeping its id (`0003`) keeps the link to the new path.
26. Given a text longer than its carrier (Frage 37, decided A), then nothing is hidden: on an open carrier the letters past the end continue along the straight extension of the tangent at the end (and before the start along the extension at the start); on a closed carrier they keep going round and overlap the first letters. Every letter is drawn, hit, converted and output. There is no tag, notice or marker for it (customer, 2026-10-23: "you can see it").

### Part E: editing, selecting, Object to path, other commands

27. Given a text on path, then editing (`0074` criteria 2 to 10) works on it as on a straight text: a click with the Text tool on a letter or a double-click with the Select tool starts edit mode with the caret at the nearest boundary; the caret, the selection and the IME preedit follow the letters along the carrier (turned with the letter they stand at); typed letters appear in place along the carrier within the 50 ms of `0074` criterion 3 for 500 characters on a carrier of 1,000 segments. 32. Given a carrier with several texts on it (for example a top and a bottom text on one circle), then each text has its own string, side, line and position; nothing limits their number.
33. Given the Layers tab (`0050`), then a text on path is a `Text` row as in `0074` criterion 27; its tooltip adds "On path: Circle 3f9a1c" (the carrier's name). No new column or glyph.

### Part I: per-character kerning and vertical texts (slice 1; `0079` slices 3 and 4 are built first)

47. Given a text with per-character kerning (`0079` criteria 26 to 31) put on a path, then the kerns apply along the carrier: a character's Horizontal kerning adds to the arc length of that character and of every following character of its line (positive in reading direction along the carrier, criterion 8), and its Vertical kerning is cumulative as on a straight text (`0079` criterion 27): it moves that character and every following character of its line, each along the carrier's normal at its own arc length (positive towards the top of the letter), the characters before it staying, each letter keeping its tangent turn. A character's own rotation (`0079` criterion 27b) adds to its rigid turn on the path, about its cluster's centre, on top of Character rotation. The kern and rotation values are not changed by putting on, moving along or releasing; Release from path gives back the straight text with the same values. Test: "HHH" at Size 10 mm on the circle of criterion 10, Above + Baseline, centred at the top, middle H with Vertical kerning +2 mm: the middle H's baseline middle is at (100, 48) within 0.01 mm, the first H is as without the kern and the last H lies 2 mm further out along its own normal (radially); with Horizontal kerning +3 mm on the last H instead, its middle lies 3 mm further along the circle (arc length) from the first H's than without, within 0.01 mm (the text's middle stays at the top, so both ends move by half, customer 2026-10-24). with Per-character rotation 90° on the middle H instead, it is turned a quarter about its centre on the path and the outer two are as without. Alt+arrows (`0079` criterion 29) work in edit mode on a text on path. **(Proposal; cumulative vertical kern and own rotation: customer 2026-10-24)**
48. Given a text in a vertical writing mode (`0079` criterion 20, Vertical right to left or left to right) put on a path, then it is laid out horizontally along the carrier, as a Horizontal text with the same string, face, size, spacing and kerns would be (Inkscape's behaviour); its writing mode and glyph orientation stay stored unchanged. While it is on a path, the Writing mode and Glyph orientation buttons show the stored values, greyed in the `0078` look with the tooltip second line "Text on a path runs along the path"; they change nothing. Release from path gives back a straight text in its stored vertical mode and orientation (the first letter kept in place as criterion 23 says, measured on the vertical layout's first character). The file keeps the writing mode (criterion 34). Test: a text "AB" in Vertical, right to left on the circle of criterion 10 draws within 0.01 mm the same outlines as the same text in Horizontal; after Release from path its Writing mode is Vertical, right to left. **(Proposal)**

## Out of scope

- Illustrator's other path effects (Skew, 3D Ribbon, Stair Step, Gravity) and LightBurn's Distort (letters bent along the curve): a later story; the taper that keeps letters of a ring text from fanning out is `0079`'s "Kegelverzerrung".
- Automatic fit: squeezing or spreading the letters so the text fills the path exactly (Frage 37 option C), justified text on path.
- Text flowed inside a closed shape (area text), vertical layout along a path (letters stacked across the path; a vertical text is set horizontally on a path, criterion 48), right-to-left text on a path.
- Spacing rules at sharp corners (Illustrator's "Spacing"); collision avoidance between letters at inner corners.
- A "Reverse direction" command for paths and shapes (the maker uses Side and Line; reversing a path's node order is a path command for later).
- Select carrier / Select texts on this path buttons; a list of the texts on a path.
- A text on another text, on an image, on a group outline, on a bitmap trace.
- Clones of a straight text outside On path (Linked clone stays for paths only, `0049` criterion 1); a clone of a text clone; Own placement for text clones.
- SVG import and export of `<textPath>` (`0024` follow-up).
- Embroidery satin columns along text on path (Ink/Stitch's lettering along a path): a later embroidery story.
