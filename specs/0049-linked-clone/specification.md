# Linked clone: a second object that follows its original

Status: Ready (customer decisions of 2026-10-11 applied)
Note 2026-10-14: architect decision B on merge residue (`adrs.md`, commit 885c369), PO wording: a clone with no link at all is an orphan, not damage; the repair turns it into its stored outline when that is a valid path (criteria 35 and 38).
Priority: Should
Origin: Customer (request of 2026-10-10: a "linked clone" is a second origin object that contains all transformations of the original and changes live with it, and can still be moved, scaled, rotated and skewed on its own; only for paths; a rectangle or other primitive is converted to a path first, silently, as decided in `0047`). Customer decisions of 2026-10-11: (1) the exceptions to "no inheritance" are accepted (a clone reads its style and opacity from its original; visibility, lock and opacity resolve through the ancestors, ADR 0015); (2) a clone of a clone is allowed, so chains exist (this replaces the earlier rule that a clone of a clone becomes a clone of the original); (3) a selected clone is marked on the canvas and so is its original, at the same time (this replaces the earlier default of no mark); (4) the keyboard shortcuts stay as proposed (this spec has none) and all shortcuts get one overall review at the end (`README.md`). Everything in "Decided by the product owner" and every criterion marked **Proposal** is my own idea and is not accepted until the customer says so.

## User value

As a maker I want a clone of a path that stays linked to it, so that I can make twelve identical hinge tabs, mirror-placed parts or repeated holes, fix the shape once in the original, and have every clone change with it, while each clone still sits where I put it, turned and scaled as I need.

**What the other tools do, and what we do.**

- *Inkscape* (Edit > Clone, `<use>` in the file): Alt+D creates a clone exactly on top of the original, Shift+D selects the original, Unlink Clone turns it into a path. The clone shows the original's style unless the clone overrides a property. A preference decides what happens when the original is deleted (the clones are unlinked, the default, or deleted); a clone whose original is missing is an "orphaned clone". Alt+D on a clone makes a clone of the clone, a chain (we do the same, with a depth limit). A clone pasted into a file without its original is orphaned. A path operation on a clone unlinks it (preference). The clone can be moved, scaled, rotated and skewed; the original is untouched.
- *LightBurn*: the nearest thing is the Virtual Array, a grid of synced copies of one source. The copies cannot be selected or changed on their own, are drawn dashed, and are flattened into ordinary copies when the job is output.
- *Illustrator and Affinity*: symbol instances. The instances follow the symbol, can be transformed on their own, and "Break link to symbol" makes an ordinary object.

**What we do the same:** clone on top of the original, clones of clones (chains), Select original, Unlink, unlink (not delete) when the original is deleted, output as plain paths.
**What we do differently:**

- *Chains are limited and cannot break.* A clone of a clone follows that clone, 8 levels at most when a clone is made (criterion 52). No cycle can form, by construction (criterion 53). Deleting a clone in the middle of a chain re-points the clones behind it to the next original, with the matrices composed, so nothing moves (criterion 31). Inkscape leaves the clones behind it orphaned or unlinked, depending on a preference.
- *Selecting a clone marks it and its original.* The clone and the object it follows are traced in one colour at the same time, with text tags, so the maker sees the link without opening the panel (criteria 57 to 62). Inkscape shows it only in the status bar, as far as I know.
- *Every clone is a full object.* Select it, box it, transform it by gesture or typed value, group it, hide it (`0050`), exactly like a path. LightBurn's virtual copies cannot be touched.
- *No surprise when the original dies.* The clones become paths in the same step and stay where they are, or follow the next original that stays (criterion 31), where Inkscape needs a preference and leaves orphans.
- *The link is visible in the panel, inline.* The Style tab says "Linked clone of Path 3f9a1c" with Select original and Unlink buttons; the original says "3 linked clones" with Select clones. Inkscape shows it in the status bar, as far as I know.
- *Silent conversion of a primitive.* A rectangle is converted to a path as part of making the clone, with no warning (`0047`).

## Words used below

- **Original (also "origin"):** the object a clone refers to directly. It is a path, a compound path or another clone. It knows nothing of its clones.
- **Root original:** the path or compound path at the end of a clone's chain. For a clone of a path it is the original itself. The root holds the outline, the style and the `opacity` that the whole chain shows.
- **Chain:** clones that follow each other: B follows A, A follows O (a path). Written B → A → O. The **depth** of a clone is the number of clones from it down to the root, itself included: A has depth 1, B depth 2. The limit is 8 (criterion 52).
- **Clone:** an object of its own kind that has no outline, style, opacity or anchors of its own. It stores the id of its original and a **clone matrix** M. It is not a primitive, a path or a group.
- **Clone matrix M:** an affine map `x' = a·x + c·y + e`, `y' = b·x + d·y + f` (SVG order a, b, c, d, e, f), document millimetres, X right, Y down. Its linear part is L = (a, c; b, d). The identity is (1, 0, 0, 1, 0, 0).
- **Resolved outline of a clone:** the resolved outline of its original (for a path, its outline; every outline of a compound path) with M applied: every anchor point p becomes M·p, every handle vector v becomes L·v, open or closed state and node order are kept. Curves are cubic Béziers, so this is the exact image. The clone is drawn, hit-tested, boxed and measured by its resolved outline.
- **Composed matrix of a clone:** M of the clone times M of its original, and so on down the chain: for B → A → O it is M_B·M_A. The resolved outline of a clone is the composed matrix applied to the root's outline, and the two ways of computing it agree (criterion 50).
- **Local frame:** the clone's own axes, M applied to the document axes. A change of the original is seen by the clone in this frame (criteria 12 and 51).
- **Bake / unlink:** turn a clone into an independent path with the resolved outline (criterion 28). **Re-point:** change the original of a clone to another object and its matrix to the composed one, so that its drawn outline does not change (criterion 31).
- **Orphan:** a clone whose original cannot be found: its chain does not end in a path or compound path because an id in the chain names nothing, names a group or a primitive, or the chain runs in a ring (or an id is broken); or the composed matrix is not finite. The length of a chain never makes an orphan: the limit of 8 applies only when Linked clone creates a clone (criterion 52), and a chain that undo or a merge made deeper still resolves and draws. An entry of a matrix or composed matrix beyond ±1e7 does not make an orphan either; that limit only refuses a transform or an edit (criterion 17).
- Lengths are compared with the document's geometric tolerance, angles with 1e-9 rad, as in the earlier specs.

## Acceptance criteria

### Making a clone

1. Given the Select tool and one or more selected objects, each a path, compound path, rectangle, ellipse, polygon, star or clone, when the maker activates **Linked clone**, then for each selected object one new clone is created, its matrix is the identity (it lies exactly on what it was made from), it sits directly above that object in the stacking order, and the new clones are the only selected objects. One commit, labelled `linked_clone`. Test: A, B, C selected, the order becomes A, A', B, B', C, C' and A', B', C' are selected.
2. Given a selected rectangle (with or without rounded corners, turned or not), ellipse, polygon or star, then it is converted to a path in the same commit, before the clone is made, with no warning, hint, notice text or confirmation about the conversion. The converted object is "Object to path" of that shape (`0003` criteria 17 to 22, `0013` criterion 16): same id, same place in the stacking order, same style, same nodes. The clone's origin is that object. Test: a rectangle with four different corner radii gives a path of 8 nodes and a clone whose resolved outline equals that path's.
3. Given a clone selected, then Linked clone makes a clone of that clone: a chain (customer decision, 2026-10-11). The new clone has the identity matrix, its original is the selected clone, it lies exactly on the selected clone's resolved outline, it sits directly above it, and its depth is the selected clone's plus 1. Test: C1 = clone of P with a matrix that is not the identity; Linked clone on C1 gives C2 with original C1, the identity matrix, the same resolved outline as C1, and C2 sits above C1. Edit P and both change. A selected clone at depth 8 is refused (criterion 52).
4. Given a selection that contains a group (`0023`) or a layer (`0050`), then Linked clone is not offered, and nothing is converted. Given no selection, or a tool other than Select, then the button is not shown (it lives in the Select bar, UX notes).
5. Given a successful Linked clone, then a one-line notice reads "Created 1 linked clone." or "Created 3 linked clones.", disappears within 3 seconds, takes no focus and is a `role="status"` live region. It never mentions a conversion. Until `0020-undo-redo` has merged it ends with "No undo yet." as in `0016` criterion 29; the build that merges second removes the sentence (`0020` criterion 52).
6. Given any state of the app, then no key starts Linked clone, Select original, Select root original, Select clones or Unlink clone; they are buttons only (default of Question 6; the customer kept the shortcuts as proposed on 2026-10-11 and all shortcuts get one overall review at the end, `README.md`). Test: the key table has no entry for them.

### What a clone shows and how it follows

7. Given a clone with matrix M, then its drawn, hit-tested and measured outline is its resolved outline. Test: an origin square of side 10 mm at (0, 0) and M = scale 2, translate (30, 0): the clone is the square from (30, 0) to (50, 20). A compound path origin (a ring) keeps its hole: the point that was the ring's centre, after M, is not painted (`0016` criterion 31).
8. Given a clone, then it is drawn with its root original's style, read live: fill on or off, fill colour and opacity, stroke on or off, colour, opacity, dash, join and cap, markers. The clone has no style of its own (decision 2; customer, 2026-10-11). Its object opacity (`0050`) is the root's too, read live (criterion 49). Test: change the root's stroke colour to red; every clone of it, in a chain or not, is red in the next frame.
9. Given M with a scale, then stroke width, dash lengths and marker size of the clone are not scaled by M or by any matrix of its chain: they are the root's values in document millimetres. Test: root stroke 0.5 mm, M = scale 4: the clone's stroke is 0.5 mm wide on the canvas (a laser hairline stays a hairline); a clone of that clone with scale 2 draws 0.5 mm as well. The "Scale stroke width" and "Scale corner radius" switches do not apply to a clone.
10. Given any edit of an original that keeps the original object (a node, handle or segment drag, add, delete or change of a node, Join and Split of an open path keeping this object, a move, resize, rotate or skew, a style edit), then after the commit every clone that follows it, directly or through a chain, shows its composed matrix applied to the root's new outline, in the next frame. Test: origin square, clone with M = translate (100, 0), the origin's top-right node is dragged by (5, 5): the clone's top-right node moves to the origin's new node plus (100, 0).
11. Given a drag that edits the origin (a node, handle or segment drag, a move, resize, rotate or skew), then during the drag each clone is previewed like a selected object: its committed outline stays in its own style and the outline the release would give is drawn as the 1.5 px blue outline (`unified-object-editing` criteria 10 to 14). With more than 500 clones downstream of the edited object (direct and chained), no clone preview is drawn and the clones jump on release. Nothing is written before the release.
12. Given the original of a clone changes by a map T (a move, a rotation, a scale; the original may be a path or another clone, whose matrix then changes), then the clone's outline changes by M·T·M⁻¹ in the document, that is, the clone sees the same change in its local frame (resolved' = M·T·original; for a translation t of the original the clone moves by L·t). Test: M = turn by 90° clockwise on screen, (a, b, c, d) = (0, 1, -1, 0); the original is moved 5 mm right; the clone moves 5 mm down. A clone with M = translate only moves 5 mm right.
13. Given an edit of the original by one peer and a transform of the clone by another peer at the same time, then after the merge the clone's resolved outline is the clone's new matrix applied to the original's new resolved outline (the outline lives in the root and the link in the clone, so there is no conflict; along a chain every clone has its own `clone_link` register). Given two peers that transform the same clone at the same time, or one that re-points it and one that transforms it, then after the merge the clone's link is one of the written links as a whole, never a mix of their entries: the original and the matrix are one atomic value, the single register `clone_link = {origin, matrix}` (decision 1), so a matrix is never paired with an original it was not computed for.

### Transforming a clone

14. Given the Select tool and a selection that holds only clones, then it has the group box and the handles of `0019` over the resolved outlines: move, scale by corner and edge, rotate, skew, centre handle, typed entries (M, R, S, K) and the typed move of `0047` with its reference points. Skew and stretch are offered for every clone and never convert anything; no conversion notice appears. The box is the tight axis-parallel bounds of the resolved outline; it does not remember a rotation (`0019` criterion 7). A clone selected together with other objects uses the group box of the whole selection.
15. Given a transform gesture whose map in the document axes is G (a move, scale, rotate or skew, drag or typed) on a selection that contains a clone and none of the objects of its chain (its original, that one's original, and so on to the root), then the clone's matrix becomes G·M, nothing of the chain is written, and the clone's drawn outline is G applied to the outline it had (within 1e-6 mm). The clones that follow the transformed clone move in their local frames (criterion 12). One commit, the label of the other transforms (`transform_objects`).
16. Given the same gesture on a selection that contains a clone together with one or more objects of its chain, then the objects of the chain in the selection are transformed as objects (a path or compound path: its geometry becomes G applied to it; a clone: by this criterion, recursively), and every selected clone's matrix is set so that its drawn outline is G applied to the outline it had (within 1e-6 mm), whatever else is selected: the clone keeps its place relative to its original, as in any multi-object transform (`0019`). When its direct original is transformed by the same G the matrix becomes G·M·G⁻¹. Clones that are not selected follow (criterion 12). Given G or a matrix on the clone's chain has a determinant with absolute value below 1e-9 (a factor of 0 on one axis), so that the invariant cannot be met, then the selected clones of that case are unlinked first (criterion 28) and then transformed as paths. Tests: (a) the origin square at (0, 0), the clone at (30, 0) with M = translate (30, 0); both selected and scaled by (2, 1) about (0, 0): the origin is 20 wide, the clone covers x = 60 to 80. (b) Chain: O the square (0 to 10 mm), A = clone of O with M_A = translate (30, 0), B = clone of A with M_B = translate (0, 30); A and B selected, scaled by (2, 1) about (0, 0): A covers x = 60 to 80, y = 0 to 10 (M_A' = (2, 0, 0, 1, 60, 0)), B covers x = 60 to 80, y = 30 to 40 (M_B' = translate (0, 30)). (c) The same chain with O and B selected and A not: O covers x = 0 to 20, A follows to x = 30 to 50, y = 0 to 10, and B covers x = 60 to 80, y = 30 to 40 (M_B' = translate (30, 30)).
17. Given a transform or an edit that would put any coordinate of any resolved outline beyond ±1e7 mm, or any entry of a matrix or of a composed matrix beyond ±1e7, or make a value not finite, then nothing is written and nothing is converted, all or nothing, as `0019` criterion 22 says. This holds for the clones downstream of what is changed too: a change of an original that would push any clone that follows it, directly or through a chain, over a limit is refused as a whole, and the refusal names the first such clone. The limit acts at transform time only: reading a document never refuses or deletes a clone for a matrix beyond ±1e7 (two peers that each stay within the limit can merge into a composed matrix beyond it, and object undo can do the same); such a clone still draws, and only a non-finite composed matrix makes an orphan (criterion 35). A command that takes such a clone as an operand applies its own limits. Test: O 1 mm wide at the origin, A = clone of O with scale 1,000, B = clone of A with scale 1,000, all within limits (B is 1,000,000 mm wide); scaling O by 100 is refused because B would pass ±1e7 mm.
18. Given the Select bar with only clones selected, then the two switches "Scale stroke width" and "Scale corner radius" are not shown; with a mix they act on the selected objects that are not clones.
19. Given Duplicate or a Ctrl-copy move (`0010`) of a clone, then the copy is a clone of the same original as its source, with the same matrix (displaced by the move for a Ctrl-copy), above its source: a sibling of the source, not a clone of it (Linked clone, criterion 3, is the command that makes a clone of a clone). It has the same depth as its source. Given Duplicate or a Ctrl-copy move of an original that is a path, then the copy is an independent path that no clone refers to (the existing copy rule, `0010` adrs.md decision 2); the original's clones stay linked to the original. Given the same of an original that is a clone (A in B → A → O), then the copy is a clone of A's own original O with A's matrix, no clone refers to it, and B stays linked to A. When a copy holds an origin together with its clones (a group, a layer, a selection of several objects), criterion 47 applies instead.

### Selecting, the Node tool and the panel

20. Given a click, marquee, lasso or Alt-click cycle (`0014`), then a clone is hit by its resolved outline and its filled interior (holes of a compound origin are not hit) and is one candidate like any object.
21. Given one clone selected, then the Properties panel subject line reads "Clone of Path 3f9a1c" (the direct original's name as the object list shows it: kind and the six-character id, or its name once `0050` exists; for a clone of a clone the direct original is the other clone, so "Clone of Clone of Path 3f9a1c"); given several clones "3 clones"; given a mix of kinds "N objects". The slot is 120 px wide (80 px once `0050` adds its tab), so the text is cut with an ellipsis there; the tooltip and the first line of the Style tab block (criterion 22) give the name whole.
22. Given a selection that holds only clones, then the Style tab shows no style section and no marker block. In their place it shows an inline block, no popup: the text "Linked clone of Path 3f9a1c." (customer change 2026-10-14: the second sentence about the style was removed) and two buttons, **Select original** and **Unlink clone**; for several clones "3 linked clones." with **Select originals** and **Unlink clones**. When at least one selected clone has depth 2 or more, the block also shows a muted line "Chain of 3 clones. The root original is Path 3f9a1c." (for several: "Chains of up to 3 clones.") and a third button **Select root original** (plural **Select root originals**) between Select original and Unlink clone; with only depth-1 clones the line and the button are not in the tree (criterion 56). The block is in the tree only for such a selection (hidden, not disabled).
23. Given a selection that holds an object that clones follow (a path, a compound path or a clone), then the Style tab shows its sections as for any path (for a clone also the block of criterion 22) and, above them, the button **Select clones** (customer change 2026-10-14: the count line above the button was removed; the button is in the tree only while the object has at least one clone that follows it directly; clones further down a chain are counted at the clone they follow). Given a selection of an original and some of its clones, then both lines appear for what applies.
24. Given a style edit on a selection that holds clones and other objects, then the edit is written to the other objects only; the clones follow their origins, and the "Mixed" values of `0017` criteria 9 and 14 are computed from the objects that are not clones. A clone is never given a style. The same holds for the Opacity field of `0050` (its criterion 26).
25. Given **Select original** with clones selected, then the selection becomes their direct originals (each once; one step up a chain, so for B → A → O it selects A). Given **Select root original**, then the selection becomes their root originals (O). Given **Select clones** with originals selected, then the selection becomes the clones that follow them directly (for O it selects A, not B). All three are view state: no commit. The origin that is in another group is selected in that group's context (`0023` criterion 15). An origin or clone that is effectively hidden or locked cannot be selected (`0050` criterion 14): it is left out; when none of the targets can be selected the selection stays as it was and a refusal notice says so ("The original is hidden or locked. Show or unlock it in the Layers tab. Nothing was changed."), when some can the notice reads "Selected 2 of 3 originals. The rest are hidden or locked." (UX notes). While the pointer or the keyboard focus is on Select original or Select root original, the hover box of `0014` is drawn on each target (at most 50) and removed in the frame the pointer or focus leaves (Proposal). This hover box is separate from the marks of criteria 57 to 62, which show whenever a clone is selected.
26. Given the Node tool and a selection of one clone, then the resolved outline is drawn, no node, handle or segment overlay is shown, and the Node bar slot shows a text-only line "Linked clones have no nodes. Edit the original or unlink the clone." (`role="status"`). Given a double-click on a clone with the Select tool, then the tool does not change and a hint chip shows the same sentence for 3 seconds. A clone is no target of Join, Split, segment bending (`0031`) or the Pen's continue and connect (`0034`); those refuse or ignore it and nothing changes.
27. Given "Object to path", then it is not offered for a clone (Unlink clone is its counterpart).

### Unlink, delete and the other commands

28. Given one or more clones selected, when the maker activates **Unlink clone**, then each clone becomes an independent path (a compound path when its root is one): the same id, the same place in the stacking order, still selected; the anchors are the resolved outline's (the composed matrix applied to the root's outline) with new anchor ids that are unique in the document (the caller mints them); the style is a copy of the root's style, and the opacity is the opacity the clone showed before (the root's `opacity` register), so the drawn result does not jump; `rotation` 0. The drawn outline before and after is the same (every point within 1e-9 mm). One commit, `unlink_clone`; no other node is changed, and the clones that follow an unlinked clone keep following it: it is now a path, so for B → A → O unlinking A leaves B a clone of the path A (criterion 55). A one-line notice reads "Unlinked 1 clone." or "Unlinked 3 clones." (status, 3 seconds).
29. Given an unlinked path, then a later edit of the former original changes nothing in it, and the Node tool edits it like any path. Clones that follow the unlinked path now follow the path, and no longer the former original.
30. Given a clone is deleted, then only the clone is removed; clones that follow it are repaired in the same commit by criterion 31. Given Delete on a selection, then the whole selection is removed.
31. Given an object is removed by any command, that is Delete, a Boolean operation, Combine, Break apart, Split, Fracture, Flatten (the commands of `0016`, `0035`, `0036`, `0037`, `0048`) or the last-node delete of the Node tool, then in the same commit every clone that is not itself removed by the same command and whose direct original is removed is repaired. The rule: walk from the clone's direct original down the chain while the object is removed and is a clone. (a) The walk reaches an object that stays: the clone is re-pointed to it, its matrix becomes the clone's own matrix times the matrices of the removed clones that were skipped (for B → A → O with A removed: M_B·M_A), and it stays a clone; its drawn outline, style and opacity do not change. (b) The walk ends at a removed path or compound path: the clone is unlinked (criterion 28 with the outline as it was just before). Nothing disappears: the clones stay where they were, as clones or as paths. The commit is atomic. The only case in which a clone goes away is criterion 35: a clone whose original cannot be found at all, so that there is no outline left to keep. A one-line notice adds the counts: "Deleted 1 object. 3 clones became paths." / "Union: 3 objects became 1 path. 2 clones became paths." / "Deleted 1 object. 2 clones now follow their next original." (status, 3 seconds; both sentences when both happen). Tests: origin P with clones C1, C2; Delete P: C1 and C2 are paths with P's outline under their matrices and P is gone; Delete P and C1 together: only C2 becomes a path. Chain B → A → O: Delete A: B follows O with M_B·M_A and draws exactly as before (criterion 54); Delete O: A becomes a path and B stays a clone of A; Delete A and O together: B becomes a path.
32. Given a command that keeps the original object and its id (Duplicate, which copies; a style edit; a move, resize, rotate or skew; Offset, which keeps the original), then the clones stay linked. Given a command that replaces the original by another object with a new id, then criterion 31 applies.
33. Given a command that reads the geometry of selected paths (Booleans, Combine, Break apart, Split, Fracture, Flatten, Offset, Split compound path), then it reads a clone's resolved outline (through its whole chain) as if it were that path, and a clone among the operands is consumed like any operand. Given a result that takes the base operand's style (`0016` criterion 21) and the base operand is a clone, then the style is the root's. Test: Union of a clone with M = translate (20, 0) and a path that overlaps it gives the same outline as the union of the unlinked clone and the path.
34. Given Group and Ungroup (`0023`), then a clone and its original may be in different groups or layers and the link holds (it is by id); no clone changes how it looks. Given a group transform (`0023` criterion 22) of a group that holds a clone and objects of its chain, criterion 16 applies; of a group that holds only the clone, criterion 15; of a group that holds only an original, the clones that follow it follow (criterion 10).
35. Given a clone that is an orphan after an Open or a merge (see "Words used below"), then this criterion applies and criterion 31 does not: criterion 31 turns clones into paths or re-points them when a command in this editor removes an object it can see, and there the clone keeps its outline. An orphan normally has no outline to keep, because a clone stores none; the one exception is the merge residue of criterion 38. Two cases give an orphan: a merge in which one peer deleted an original while another peer created a clone of it at the same time (the deleting editor could not repair a clone it did not know), and an Open of a file written by another tool or edited by hand. The first cannot occur before sharing exists (ADR 0004; today only the second can). An orphan is not drawn, not hit-tested, not selected and not output, and the editor removes all orphans in one repair commit (`remove_orphan_clones`) right after the Open or the merge: it deletes and never unlinks, except a clone that has no link and a valid stored outline, which becomes that path (criterion 38). A clone whose chain leads to an orphan is an orphan too, so a whole broken chain goes in that one commit. Whether a clone is an orphan depends only on the converged state, not on the order in which clones are visited, so peers that repair the same state delete the same clones. The maker sees a status notice that stays 8 seconds: "Removed 2 clones whose original was not found." (singular: "Removed 1 clone whose original was not found."); the deletions are counted with this sentence and the conversions with criterion 31's "N clones became paths." (both sentences when both happen). No other clone is touched and no command of criterion 31 is involved. The project is marked changed. Given a clone whose original is itself, or clones that refer to each other in a ring of any length, then all of them are orphans and are removed the same way; nothing loops or crashes. Given a chain longer than 8 clones, in a file or made by undo or a merge, then it is not damaged and no clone of it is an orphan: every clone resolves and draws (the limit of 8 is checked only when Linked clone creates a clone, criterion 52; on such a chain Linked clone is refused at its deepest clones, and Unlink clone and every other command work).
36. Given `0020` has merged, then Linked clone, Unlink clone, the orphan repair and every command of criterion 31 are one step each with the operation names "Linked clone", "Unlink clone", "Remove orphan clones" (the guard of `0020` criterion 41 fails the build without these entries). Taking back a Delete or Boolean that unlinked clones restores the original with its id and turns those clones back into clones with their matrices (the kind of the node changes back, field by field, the engine of ADR 0014 §1). Taking back a Delete that re-pointed clones (criterion 31, case a) restores the deleted clone and gives the re-pointed clones their previous original and matrix (the link as a whole). Two cases of undo, redo and object undo are pinned: (a) a clone's link is put back only if its target exists after the restore; when it does not (the deleted clone cannot be revived, for example because a peer's later step removed what it needed), that clone is left out of the restore, the maker is told, and the clone keeps the original it follows now; (b) an undo, redo or object undo that removes a node (for example undo of Linked clone, or undo of the creation of a path that clones now follow) repairs the clones behind it in the same step by criterion 31: they are re-pointed or unlinked, never left as orphans. Undo may leave a chain deeper than 8; it resolves and draws (criterion 35). Redo repeats it.

### Saving, the file and hostile input

37. Given a project with clones is saved and reopened, then every clone has the same original id, the same matrix to the last bit, and the same place in the stacking order; every original and every clone, chains included, draws as before closing. `format_version` goes to the next free number at merge (`specs/README.md`, "`format_version` plan"); a file saved by a newer build, with or without clones, is refused by an earlier build with the "saved by a newer version" message (the format version is checked first; an earlier build would also read a clone node without an outline); a file from an earlier build opens unchanged and is not rewritten on open. A golden file `clone_v<N>.curvyo` pins the format; it holds a chain of three clones.
38. Given a file whose clone has a link with no origin id, an origin id that is not a valid id string, no matrix, a matrix that is not a list of exactly six numbers, or a matrix with an entry that is not finite or lies beyond ±1e7, then the file is refused as damaged and the editor does not crash. A clone whose origin id is valid but names nothing or names a group or a primitive is not damaged: it is an orphan (criterion 35). A clone whose origin id names another clone is a chain and is valid. A clone with no link at all (neither origin nor matrix stored), which a merge can leave behind, is not damaged: it is an orphan (criterion 35), and if its stored outline is a valid path, the repair turns it into that path.
39. Given a file with 100,000 clones of one original, or with clones that refer to each other in a ring of 10,000, or with a chain of 10,000 clones each following the next, then it opens without hang or crash and without recursion that grows with the chain (the ring becomes 10,000 orphans, removed by the repair commit; the chain resolves in full, all 10,000 clones stay and draw, since the depth limit is not a reader rule and the composed matrices are finite).
40. Given the `document.json` view, then a clone is listed with `"shape": "clone"`, its original's id and the matrix, and no outline. It is a non-authoritative view (ADR 0004 §1).

41. Test in the document core: the path read of a clone equals the path read of the same clone after Unlink clone (anchors within 1e-9 mm, style equal). Whether a hidden clone or a hidden original takes part in an output is not decided here or in `0050`: the customer decides it with the manufacturing view (`0050`, "Out of scope"). No output path exists yet (`export_loro_snapshot` and `export_json` store the document and are not outputs in this sense).

### Copying a group or layer, and opacity (added after the first review)

47. Given a copy of a set of nodes that holds an original and at least one of its clones, that is Duplicate or a Ctrl-copy move of a group, of a selection of several objects, and, once they exist, duplicate layer and paste within the same project, then the copy of each such clone follows the copy of the original, not the source original (so a copied chain is a chain of copies, with the same depth), with the same matrix (for a Ctrl-copy move by G, the matrix G·M·G⁻¹ of criterion 16, so the copy of the arrangement looks like the source arrangement moved). The copy of the origin is a path as in criterion 19, and it now has those copied clones. A clone of the same origin that is not in the copied set keeps following the source origin. All copied nodes get new ids; the source nodes are unchanged. One commit. Test: group G holds path P and its clones C1, C2; clone C3 of P lies outside G. Duplicate G gives G' with P', C1', C2'; C1'.origin = P', C2'.origin = P'; C3.origin = P. Dragging a node of P' changes C1' and C2' and neither C1, C2 nor C3; dragging a node of P changes C1, C2, C3 and neither C1' nor C2'.
48. Given a copy of a set of nodes that holds a clone but not its original (a group or layer that holds only the clone, or a selection of the clone alone), then the copy of the clone follows the same original as the source clone, with the same matrix (displaced by the move for a Ctrl-copy, criterion 19), and is a sibling of the source clone, not a clone of it (only Linked clone makes that, criterion 3). Test: group G holds only C1, a clone of P that lies in another group; Duplicate G gives C1' with C1'.origin = P; editing P changes C1 and C1'. Chain test: group G holds A (a clone of O) and B (a clone of A) and O lies outside; Duplicate G gives A' with A'.origin = O and B' with B'.origin = A'; editing O changes A, B, A' and B'; changing A's matrix changes B but not A' or B'. Given the origin is in the copied set but the clone is not, then the clone stays linked to the source origin, and the copy of the origin has no clones.
49. Given a clone, then it has no opacity register of its own: its object opacity (`0050`) is the root original's `opacity`, read live, times the `opacity` of every group and layer above the clone itself; the ancestors of the root and of the clones in between do not count (`0050` criterion 28). The clone's flags `visible` and `locked` and its name are its own (decision 7). Test: root P with opacity 50 % in a layer of opacity 100 %, clone C in a layer of opacity 50 %: C's object opacity is 25 %; set P's opacity to 100 %: C's is 50 % in the next frame. For a clone D of C (in a layer of opacity 100 %) the object opacity is P's, 100 % then, whatever the layer of C. The Opacity field of `0050` never writes to a clone (criterion 24).

### Chains (customer decision of 2026-10-11: a clone of a clone is allowed)

Criteria 3, 8 to 10, 12, 13, 15 to 17, 19, 21 to 23, 25, 28 to 31, 33 to 39 and 47 to 49 above already read for chains; the criteria here pin the cases that only exist with chains.

50. Given a chain B → A → O, then B's drawn, hit-tested and measured outline is M_B applied to A's resolved outline, which equals the composed matrix M_B·M_A applied to O's outline (every point within 1e-9 mm by both computations). Test: O the square of side 10 mm at (0, 0); M_A = translate (30, 0); M_B = scale 2 about (0, 0), (2, 0, 0, 2, 0, 0). A covers x = 30 to 40, y = 0 to 10; B covers x = 60 to 80, y = 0 to 20; M_B·M_A = (2, 0, 0, 2, 60, 0). The style and the opacity of A and B are O's (criteria 8, 49).
51. Given a chain B → A → O, then each change is seen in the next frame by everything behind it and by nothing in front of it. (a) A node of O is dragged: A and B change. (b) A is moved 5 mm right by a gesture (criterion 15): A's matrix changes, O is untouched, and B moves in its own frame (criterion 12): with M_B = (0, 1, -1, 0, 0, 0), B moves 5 mm down. (c) B is moved: A and O are untouched. (d) O's stroke colour is edited: A and B change colour.
52. Given Linked clone on a selection that holds a clone of depth 8 (a chain of 8 clones), then nothing is created and nothing is converted, all or nothing, even when other selected objects could be cloned; each offending clone is outlined in the refusal outline (row "Refusal outline", at most 200); and a refusal notice (`role="alert"`, 8 seconds) reads "Linked clones can follow each other 8 levels deep. Clone the root original instead. Nothing was changed." Duplicate, Ctrl-copy and the copy of a set never exceed the limit, because a copy has the depth of its source. The limit 8 is the product owner's default (Question 9). Test: a chain is built with 8 presses; the ninth press is refused with that text; Select root original followed by Linked clone gives a clone of depth 1.
53. Given any sequence of the commands of this spec and of `0020`, `0023`, `0050`, then no cycle can form, by construction. The original of an existing clone is written in three places only: (i) when the clone is created, to an object that exists; (ii) in a re-point (criterion 31), to an object further down the clone's own chain; (iii) in a copy (criteria 47 and 48), to the copy of an object in the copied set or to the source's own original. No command lets the maker set the original of an existing clone to an object of his choice (Relink is out of scope). So every clone points to an object that existed before the clone was created, a relation without a cycle, and the same holds after merging the versions of two peers, because each peer's writes keep it. The limit of criterion 52 is a rule of Linked clone alone: undo, redo and a merge can make a chain deeper than 8 (for example undo of the Unlink of a middle clone), and such a chain resolves and draws (criterion 35). Only a foreign or hand-edited file can hold a ring, and criterion 35 removes it. Test: a property test of 1,000 random sequences of Linked clone, Duplicate, copy of sets, Unlink, Delete (of paths and of clones), Group, Undo and Redo on 30 objects, with merges between two replicas: after every step each chain ends in a path or compound path, no node occurs twice in a chain, and `remove_orphan_clones` finds nothing to remove; chains that Linked clone makes never exceed 8.
54. Given a chain B → A → O and a command that removes A and keeps O (Delete, a Boolean with A as an operand, Combine, Break apart, Split, Fracture, Flatten, the last-node delete of the Node tool), then in the same commit B's original becomes O and B's matrix becomes M_B·M_A; B stays a clone and keeps its id, its place in the stacking order and in its group, its selection state and its flags; its drawn outline is the same before and after (every point within 1e-9 mm). The notice reads "Deleted 1 object. 1 clone now follows its next original." (plural "2 clones now follow their next original."). Test: O, M_A = translate (30, 0), M_B = scale 2 about (0, 0): B covers x = 60 to 80, y = 0 to 20 before and after Delete A, and afterwards B's original is O and its matrix is (2, 0, 0, 2, 60, 0). Ctrl+Z gives back A, and B follows A again with M_B (criterion 36).
55. Given a chain B → A → O, then (a) Unlink clone on A: A is a path with its resolved outline (M_A applied to O), B stays a clone of the path A with M_B unchanged and draws as before, a later edit of O changes neither A nor B, and an edit of A's nodes changes B. (b) Unlink clone on B only: B is a path with the composed outline (M_B·M_A applied to O); A and O are unchanged, and an edit of O still changes A. (c) Unlink clone with A and B both selected: both are paths, each with its own resolved outline, and independent. (d) O is not a clone: it has no Unlink clone. One commit each, `unlink_clone`.
56. Given a selection of clones of which at least one has depth 2 or more, then the clone block (criterion 22) shows the line "Chain of 2 clones. The root original is Path 3f9a1c." (the depth of the deepest selected clone and the root's name as the object list shows it) and the button **Select root original**, which selects the root originals, each once, under the hidden-or-locked rule of criterion 25. With only depth-1 clones selected neither is in the tree. Test: B → A → O with B selected shows the line with "2 clones" and both buttons; Select original selects A; Select root original selects O; with A selected neither the line nor the button is in the tree.

### Marking a selected clone and its original (customer decision of 2026-10-11)

The customer asked that a selected clone is marked on the canvas and its original is marked at the same time. This replaces my earlier default of no mark. The mark is on selection only: a clone that is not selected looks like the path it follows, because the picture on the canvas is also the production picture. The look follows the design system's rule for a new cue (one new token, shape plus text as well as colour); the `ux-engineer` confirms the numbers before the build.

The customer may veto this half without touching the rest.

## Decided by the product owner

Change any of these if you disagree. The ones that could cost the customer something later are repeated as questions below.

1. **Model.** A clone is its own kind of node: one register `clone_link = {origin, matrix}`, where `origin` is an object id (a path, a compound path or another clone) and `matrix` a list of six numbers; the original and the matrix are one atomic value. It has no outline, anchors, style or rotation of its own. The resolved outline is computed when the document is read, so everything that draws, hits, measures or outputs a path sees a clone as a path. One atomic matrix register, because two peers writing single entries would mix into a matrix neither of them made.
2. **Style and opacity follow the root original; there are no overrides.** Inkscape lets a clone override single properties. Here the only things that differ between a clone and its original are the matrix and, once `0050` exists, the visibility, lock and name of the clone. The object opacity (`0050`) is not one of them: a clone has no opacity register of its own; its object opacity is the root's, read live, and the layer and group opacities of the clone's own ancestors apply on top (criterion 49). The ancestors of the root and of the clones in between do not count. Reason: a maker who needs a differently coloured copy for another machine role wants an independent path, and Unlink clone is one click; overrides need a way to show, edit and reset per property, which is a panel of its own. ADR 0002 §5 says "no inheritance"; a clone's style is a reference to one other node's style, not a cascade, and this is the exception that ADR 0015 records. **The customer accepted it on 2026-10-11.**
3. **Chains are allowed (customer, 2026-10-11).** A clone of a clone follows that clone. The customer saw no reason to forbid it; Inkscape allows it too. To keep it safe: a depth limit of 8 at creation (criterion 52); no cycle can form, by construction (criterion 53); a removed clone in the middle re-points the clones behind it, so nothing moves and nothing is lost (criterion 31); resolution composes matrices once per clone (criterion 63). The earlier rule "a clone of a clone is a clone of the origin" is withdrawn; Duplicate of a clone still makes a sibling (criterion 19).
4. **A clone is placed exactly on its origin**, as Inkscape and Affinity do (Question 4 for an offset).
5. **Output expands.** A clone is a path in every output. SVG `<use>` round trip is not part of this slice (Question 7).
6. **The matrix is applied on top of the origin's stored geometry.** Because every transform in this product is baked into anchors and frames, the origin's stored geometry already holds "all its transformations"; the matrix adds the clone's own. No transform is stored on the origin.
7. **A hidden or locked original does not hide or lock its clones** (`0050`): the clone has its own flags. A hidden original with visible clones is a normal state, and the way to keep a master out of the way. What a hidden object does in a machine output is not decided here (criterion 41).
8. **Which original a repair points to (customer asked for a default, 2026-10-11).** When a clone in the middle of a chain is removed, the clones behind it are re-pointed to the next original that stays, with the matrices composed (criterion 31). Alternatives: unlink them (nothing is lost, but the maker loses the live link he built), or delete them (data loss). Re-pointing keeps the picture and the link, and is the same operation as the composition of criterion 50.
9. **Unlinking a clone in the middle** leaves the clones behind it following it (criterion 55): it is a path now, and they follow the path. Re-pointing them to the root would make the unlink of one clone change the behaviour of others, which Unlink is not meant to do.
10. **Depth limit 8.** Enough for a tab, a copy of the tab and a mirrored copy of that, with room; deeper chains are hard for a maker to follow, and the limit bounds the cost of an edit. It is only checked when a clone is made (criterion 52). A different number needs no other change.
11. **What is marked, and when (customer, 2026-10-11).** The customer asked for a selected clone and its original to be marked at the same time. I chose: marks only on selection (the canvas is also the production picture); the clone dashed and the original solid, each with a text tag, in one new violet token; the direct original in full and the root of a chain thin; a faint view of the clones when an original is selected as a Proposal (criterion 59); a cap of 200 traces and 50 originals (criterion 61). A line between the two was rejected: with thousands of clones it is noise, and an original that is off screen cannot carry one (the edge chip of criterion 58 does that job).

## Out of scope

- **Clones of groups, layers, text, images or primitives as such.** Only paths and compound paths are origins; a primitive is converted first (criterion 2). Clones of groups are a later entry.
- **Style overrides on a clone**, and any per-property link to the origin (decision 2).
- **Editing nodes through a clone** (Question 5), and any command that needs the clone's nodes (Join, Split, segment bending, Pen extension).
- **Tiled or arrayed clones** (Inkscape's Create Tiled Clones, LightBurn's Grid Array): a grid or circle of linked clones from one dialog. A natural follow-up for makers; a Proposal for a later entry, not part of this slice.
- **Relink**: pointing a clone to another original ("Relink to copied" in Inkscape) and turning a path into a clone. Not having it is also what makes cycles impossible (criterion 53). Chains themselves are in scope (criteria 50 to 56).
- **Selecting every clone further down a chain** (all descendants of an object). Select clones takes the direct clones only; the maker repeats it to go further.
- **A line between a clone and its original on the canvas**, and marks on clones that are not selected (decision 11).
- **SVG import and export** of `<use>` (`0024`, Question 7).
- **Copy and paste between projects.** No object clipboard exists. When one does, a clone pasted into a project that lacks its origin must paste as an independent path (Inkscape pastes an orphan). Recorded for that spec.
- **Keyboard shortcuts** for the commands of this spec (Question 6). The customer's overall review of all shortcuts at the end (`README.md`) may add them.
- **What a hidden or locked original or clone does in a machine output** (criterion 41; `0050` "Out of scope").
- **Undo and redo** themselves (`0020`); this spec only fixes the steps (criterion 36).
- **Anything a job does with clones**; a clone is a path to it (criterion 41).

## Open questions

Each has a default; nothing blocks the build. Questions 1 and 3 are closed by the customer's decisions of 2026-10-11.

1. **Document model (criteria 37, 38; decision 1). Closed, 2026-10-11:** accepted, including the exceptions to "no inheritance" (a clone reads style and opacity from its original; visibility, lock and opacity resolve through the ancestors). ADR 0015 records it (the architect updates it for chains, see `adrs.md`).
2. **Style overrides (decision 2).** *A (default, and what the accepted exception means):* none; the clone shows the root's style. *B:* overrides per property (colour, stroke width), with a panel that shows and resets them. Recommendation A: a separate, larger spec if it turns out to be needed.
3. **Clone of a clone (criterion 3). Closed, 2026-10-11:** a real chain (the earlier option B). The depth limit and the repair rules are criteria 52 to 55; the limit is Question 9.
4. **Where the clone appears (criterion 1).** *A (default):* exactly on the origin. *B:* displaced by 10 mm right and down, so the maker sees at once that something happened. With A the notice and the selection box are the cue.
5. **Node tool on a clone (criterion 26).** *A (default):* no nodes; the hint tells the way out. *B:* the Node tool edits the origin's nodes through the clone (the pointer mapped back through M⁻¹), so the maker never has to find the original. B fails for a matrix with determinant 0 and confuses when the origin is elsewhere on the page. Recommendation A.
6. **Shortcuts.** *A (default, kept by the customer on 2026-10-11):* none. *B:* Inkscape's Alt+D (clone), Shift+D (select original), Shift+Alt+D (unlink). Alt+D focuses the address bar in a browser, so B would be wrong for the browser build; recommendation A until a key is found that works everywhere (the key table is `docs/design-system.md`). All shortcuts get one overall review at the end, where this is decided with the rest.
7. **SVG (criterion 42).** *A (default):* a clone is written and read as a plain path. *B:* a clone is written as `<use xlink:href="#id" transform="matrix(...)">` so Inkscape sees a clone, and `<use>` of a path is read as a clone. B is correct only when the matrix has no scale, because SVG scales a clone's stroke and ours does not; so B writes `<use>` only for a rotation and translation and a path otherwise. Decided in `0024`; the default here is A.
8. **Where the buttons live.** Default in the UX notes: Linked clone in the Select bar, last, after "Offset"; Select original, Select root original (chains only), Unlink clone and Select clones in the Style tab block (criteria 22, 23, 56) and, once `0050` exists, as row actions. Not the rail: its two columns are allocated (`docs/design-system.md`, "Tool rail architecture"), and a further family of commands goes to the Select bar or the panel.
9. **Depth limit of a chain (criterion 52).** *A (default):* 8. *B:* another number, or none. Without a limit, a chain has no bound on the cost of an edit and a maker can build one he cannot follow; no limit is a one-line change in the criterion. Recommendation A.
10. **Faint view of the clones when an original is selected (criterion 59, Proposal).** *A (default):* on, capped at 50 clones, no tags. *B:* off; only a selected clone shows marks. A costs a little clutter when an original with many clones is selected. Recommendation A, because it tells the maker what an edit will change.

### The button in the Select bar

- **Linked clone** is a text button in the Select bar, the look of "Offset" (28 px, 1 px `--toolbar-icon` outline at 60 %, `rounded-[5px]`, 14 px label). **Changed: no `Link2` glyph, and it comes last, after Offset.** The bar already holds the Link corners toggle (`Link`, `Unlink`); a second near-identical link glyph with another meaning, in the same bar, is a trap. The bar's rule is that a new control is appended so that no earlier control moves ("Offset" is last for that reason), so Linked clone follows Offset in a group of its own.
- Shown (in the tree, never disabled) when the selection holds at least one object and no group. **Changed:** the draft said "at least one clonable object", which would offer the button for a group together with a path, against criterion 4. A layer is never in the selection (`0050`), so criterion 4 needs no layer case. Tool other than Select: the bar is not there.
- Tooltip, `side="bottom"`, three lines: "Linked clone" / "A second copy that follows the original." / "Edit the original and every clone changes."
- **Criterion 18 is an exception to the bar's rule that the two switches are "always shown".** With only clones selected "Scale stroke width" and "Scale corner radius" leave the tree, because they would do nothing, and an inert switch would lie. The first row then begins with Offset and Linked clone. The switches come back with any other object.
- Not on the rail: column B is full and column A has room for two tools (row "Tool rail architecture"); a new family of commands goes to the Select bar or the panel. This holds together with the rail layout that `0048` fixed (Path card first in column B, Boolean card under it).

Height about 112 px (up to 132 px when row 1 wraps). **Changed: the draft said about 90 px.** It scrolls with the body. **Chains (criterion 56, 2026-10-11):** when a selected clone has depth 2 or more, a row of 12 px `--panel-muted-fg` text "Chain of 3 clones. The root original is Path 3f9a1c." (about 16 px, 32 px when it wraps) follows row 1, and a third button **Select root original** sits between Select original and Unlink clone (+36 px): about 164 px, up to 196 px with wrapping. The extra row and button are in the tree only then.
- **Origin line** (an original selected, a path, compound path or clone, and at least one clone follows it directly): the full-width outline button **Select clones** ("Select clone" for one). Customer change 2026-10-14: the count line above the button, with its `Link2` glyph, was removed; about 28 px. The label is live (a peer's clone, an unlink). With an origin and its clone both selected, both blocks show, clone block first.

The same box on the clones for Select clones is not drawn (there may be thousands). It is separate from the marks of selection (next section): the hover box says "this is what the button would select", the marks say "this is what you have selected and what it follows".

### On the canvas

- **A clone looks like the path it follows**: the root's fill, stroke, dash and markers, the stroke width in document millimetres whatever any matrix scales (criterion 9), holes kept. Nothing marks it when it is not selected: a cue on every clone would put noise on artwork that is also the production picture (twelve hinge tabs must look like twelve hinge tabs). **Changed on 2026-10-11 (customer):** the earlier "no mark at all, a faint mark is open" is withdrawn; a selected clone is marked, and its original with it (criteria 57 to 62, next bullets).
- **Marks of a selected clone and its original** (criteria 57 to 62). Draw order back to front: artwork, link traces, member boxes, group box, handles, tags. **Clone:** its outline traced 2 px dashed (6 on, 3 off, so it differs from the 4 / 3 selection box) in `--clone-link` with a 1 px white casing, and a chip "Clone" with `Link2`. **Original (direct):** its outline traced 2 px solid in `--clone-link` with the casing, and a chip "Original". **Root of a chain** (when it is not the direct original): 1 px solid at 100 % (50 % measured 2.1:1), chip "Root". **One object with several roles:** the strongest trace (Clone, Original, Root) and one chip, "Clone + Original". The hue is a new token, `--clone-link` `#7B3FD6`, a violet used by nothing else: the blue is the selection, green and red are the marquee, red is refusal and the reference box, so a fourth hue keeps the link from being read as a selection state; the design system's "one accent" rule is about selection states, and the customer asked for a cue that is not the selection. Measured: 4.87:1 on `--canvas-bg`, 3.02:1 on `--pasteboard-bg`. Against the selection blue the violet is almost the same hue to a deuteranope or protanope (ΔE 8 and 12), so the meaning is carried by dash, width, outline and text, never by hue. **Chip:** 20 px high, bar surface, 1 px `--clone-link` border, 12 px `--toolbar-icon` text, 10 px outside the object's screen box over the top left corner, then above right, below left, below right, then above left raised and below left lowered to 30 px; it is dropped when every position meets a drawn handle glyph (not a hit area: a chip takes no pointer events), the centre handle, a reference mark of `0047`, a refusal label, a DOM chip, another chip or the viewport edge. **Off-screen original:** a chip at the viewport edge, "Original" and an arrow, at most 8. **Hidden original:** not drawn, the clone's chip reads "Clone (original hidden)". **Hidden while dragging** (any move, resize, rotate, skew, node drag, marquee) and in every frame that draws a `--preview-new` outline (also the Offset preview), shown again in the frame after the release, so it never meets the blue preview. **Many:** 200 traces, 50 originals, chips only when 12 objects or fewer are marked and the object is at least 24 px; objects under 6 px get an 8 px ring. **Proposal:** an original that is selected shows "Original (12 clones)" and a faint dashed trace (65 %) on up to 50 of its clones.
- **Selected clone**: the usual dashed blue box and the handles of `0019` over the resolved outline; no member-box difference. Move, scale, rotate, skew, the typed move (`M`) with its reference points (`0047`), `R`, `S`, `K` work as for a path; `K` never refuses a clone.
- **During a drag that edits an original** each clone behind it, directly or through a chain, is previewed as a selected object is (1.5 px `--preview-new` outline, criterion 11), none above 500 clones.
- **Node tool**: one clone selected: the resolved outline, no node, handle or segment overlay, and the Node bar slot holds a text-only pill (bar surface, 14 px `--toolbar-icon`, `role="status"`) "Linked clones have no nodes. Edit the original or unlink the clone." (as the compound path pill). The pill shows only when every selected object is a clone or compound path; with a path and a clone selected the path's nodes show and the clone draws its outline, as `0016` criterion 38 does for compound paths. The double-click hint chip (3 s) says the same.
- **Orphan, unlink and delete** are never seen as states: an orphan is removed on load or merge (with the notice of criterion 35), a delete of an original turns its clones into paths, or re-points the clones behind a removed clone (criterion 31), in the same frame.

### The Layers list (`0050`)

A clone row has `Link2` as its kind glyph (16 px), the name "Clone of <original name>" (the direct original's own name, or "Path 3f9a1c" when it has none; for a clone of a clone "Clone of Clone of Path 3f9a1c", which the maker can rename), its own eye and lock, the root's opacity as the muted readout (read only; criterion 49), and the row action **Select original** (`Locate`, 24 px) in the row-action slot (one step up the chain; Select root original is in the Style tab only). The default name is 20 characters or more and is cut by the ellipsis at 128 px (100 px with the opacity readout); the glyph says clone, and the tooltip has the whole name with a second muted line "Linked clone, chain of 3. Root: Path 3f9a1c" (the chain part from depth 2). The original's row looks like any path or clone. Accessible name "Clone of Path 3f9a1c, linked clone, hidden, opacity 60 percent". Renaming a clone sets the clone's name; the origin's name is not touched.

### Keyboard, screen reader, contrast, touch, 800 x 600

- The block's buttons and Select clones are ordinary Tab stops in the body after the strip, in the order Select original, Select root original (chains only), Unlink clone; Enter and Space press; names are their texts. Linked clone is a Tab stop in the Select bar after Offset. No key starts any of the three (criterion 6).
- Notices are `role="status"` (refusals `role="alert"`) and never take focus. The block is a `role="group"`; the glyphs are `aria-hidden`; nothing is told by colour alone (a text sentence names the link).
- Contrast: the block uses `--toolbar-icon` (8.3:1) and `--panel-muted-fg` (5.0:1) on the panel; the buttons are the existing outline buttons (border 3.1:1, label 8.3:1).
- Touch: the buttons are 28 px high at full width and need no hover; the hover cue is a pointer extra. 800 x 600: nothing is added to the canvas; the Style tab gains the block (112 px, about 164 px for a chain) or the origin line (52 px) and scrolls as it always does; the Select bar gains one 112 px button that wraps with its group.

### Fit with the neighbours

- **`0043` tabs.** The block is in the Style tab; Layers stays active when a clone is selected there (`0050` criterion 2). Nothing about tabs changes. A maker who works in Layers reaches the link through the row action; the Style tab (Shift+Ctrl+F) has the full block.
- **`0044` Ctrl+A and nudge.** Clones are objects: Ctrl+A selects them, the arrows nudge them (a clone's matrix changes, the origin does not).
- **`0023` groups.** A group in the selection hides the button (criterion 4); a clone in a group is cloned inside that group's context; a clone and its origin in different groups keep the link (criterion 34); Select original in a group enters it (criterion 25).
- **`0047` transform.** No conversion and no notice for a clone's skew or stretch; the silent conversion applies once, when the clone is made from a primitive (criterion 2); the typed move works on the clone's resolved box.
- **`0048` rail.** Nothing is added to the rail. Split, Break apart, Cut and the Boolean card read a clone as its path (criterion 33); their notices are unchanged and add the count of clones that became paths (criterion 31).
