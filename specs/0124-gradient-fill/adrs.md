# ADRs for gradient fill

Status: Proposed (architect, 2026-11-18). Two new ADRs: [ADR 0066](../../docs/adr/0066-gradient-fill-in-the-document-model.md) (stored form and evaluation, `needs-customer`: document model and file format, accepted with the story PR) and [ADR 0067](../../docs/adr/0067-gradient-drawing-and-svg-gradients.md) (drawing and SVG, architect). Decisions marked **(Proposal)** are the architect's and vetoable at the demo. No customer question.

- [ADR 0066](../../docs/adr/0066-gradient-fill-in-the-document-model.md): `fill_paint` value `gradient`; two atomic registers `fill_gradient` (kind and geometry as box fractions, radial `ratio`) and `fill_gradient_stops` (`["#RRGGBBAA", offset]`, at least two, no upper limit), so a drag and a stop edit merge without loss; kept when switched away; one `colour_at` and `over_white_grey` in `curvyo-document-core` for canvas, hit test, SVG and `0123`; exact affine image on transforms, re-fit on node edits, picture kept on operations; format next free at merge; no crate, no dependency.
- [ADR 0067](../../docs/adr/0067-gradient-drawing-and-svg-gradients.md): per-vertex gradient coordinates plus one stop-table texture in the one artwork pipeline (exact per pixel, hard edges hard, no extra draw call, no frame skipping, no new per-frame rebuild); grey stops on laser pages; SVG export and import as criteria 13 and 14 with `svg-core`'s own gradient type; budgets 24 a to e confirmed.
- [ADR 0029](../../docs/adr/0029-live-pattern-fill.md) §1, §2, §4, §11: the `fill_paint` key, the kept-data rule, the leaf frame and the preview-until-release rule are reused; no text changes.
- [ADR 0015](../../docs/adr/0015-node-references-and-ancestor-resolved-state.md), [ADR 0016](../../docs/adr/0016-clone-overrides.md), [ADR 0045](../../docs/adr/0045-clones-of-groups-texts-images-and-movable-placed-pages.md): clones read the root's gradient through the style keys; own style carries its own.
- [ADR 0018](../../docs/adr/0018-svg-import-crate-parser-and-limits.md): `curvyo-svg-core` stays free of Curvyo crates; the mapping is in `ui-core` (import) and the session (export).
- [ADR 0011](../../docs/adr/0011-workspace-and-crate-layout.md): no new crate or edge.

## Feature-local decisions

Reconciled 2026-11-18 (product owner): every "For the PO" below is applied in the specification (criteria 11, 13, 19, 22; criterion 27 is new).

- 2026-11-18: **Damage refuses the file** (ADR 0066 §7), as every style key does today, including `fill_pattern`. Criterion 22 says "the shape is shown with no fill, the file opens, the damage is counted in the existing notice" and calls that `0071`'s rule; `0071`'s rule is a refused file. **For the PO:** align criterion 22; its damaged golden becomes one file per reason (`gradient_fill_damaged_colour`, `_fraction`, `_one_stop`, `_unordered`, `_paint_without_gradient`, each `_v<N>.curvyo`), each refused.
- 2026-11-18: **`fill_opacity` does not apply to a gradient** (Proposal): each stop has its own alpha; SVG import multiplies `fill-opacity` into the stops; export writes none for a gradient. The Fill block hides the opacity field while Gradient is chosen (for the UX engineer).
- 2026-11-18: **"Re-based" in criterion 19 means the picture is kept** (Proposal): the result's gradient has the input's placed geometry, expressed in the result's box, so Break apart and Object to path continue one shade over the pieces. **For the PO:** say so in criterion 19.
- 2026-11-18: **`gradientTransform` only for an elliptical radial** (ADR 0067 §6). The stored geometry is already in the shape's frame, so a rotated shape exports plain `x1 y1 x2 y2` or `cx cy r`. **For the PO:** criterion 13 names rotation and skew; the golden `gradient_ellipse_rotated.svg` stays and is the one that carries a matrix.
- 2026-11-18: **PNG** (criterion 11): the only PNG is the container's page thumbnail, drawn by the same pipeline; there is no PNG export to change. **For the PO:** reword criterion 11 to the thumbnail or drop it.
- 2026-11-18: **Format**: project `format_version` next free at merge (49 if nothing merges first); no migration; `legacy_fill.rs` stays and keeps ignoring `fill_kind` and `fill_stops` (criterion 23).
- 2026-11-18: **Hard edge**: at an offset shared by two stops the later stop's colour applies from that offset on, as SVG.
- 2026-11-18: **Dependency** (implementer, Proposal, architect review N11): `curvyo-editor-wasm` gains the dev-dependency `naga` (MIT OR Apache-2.0, version 30, features `wgsl-in` and `glsl-out`), the same crate and version `wgpu` already compiles in, so `Cargo.lock` adds no package; a host test parses, validates and translates the gradient WGSL to GLSL ES 3.00, so a shader error fails `cargo test` instead of the browser (`gpu_shader.rs`). No runtime dependency is added (criterion 25 holds for the shipped crates).
- 2026-11-18: **Angle** shown in the panel is derived from the stored points with `libm::atan2`; it is display only and never feeds a stored value except through the points a typed Angle writes.
