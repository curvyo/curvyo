# ADR 0059: Fixture sets, job fixtures and pins in the project file: set nodes with an On-this-page register, job fixtures beside them with a lock, the pin kind and pin and screw grids, two fixed jobs per pin or screw, format 47

**Status:** Proposed 2026-11-12, `needs-customer` (document model and file format). Built on the customer's decisions of 2026-11-12: Frage 207 B (a fixture set is a named group of the machine; a laser page switches on any number of them; plus the page's own job fixtures), 208 A (pin: a round fixture with a diameter, single or gridded), 209 A (centre mark: a cross in a circle with a settable size, for pins and screws; plus engravable diameters), 210 (job fixtures are never mirrored; "Apply fixtures from page" copies another page's job fixtures), 211 B (a fixture in a set keeps its own On the bed check), P16 reduced (the screw keeps its Head and Thread presentation). **Amends** [ADR 0049](0049-laser-fixtures-in-the-project-file.md) §1 (a sixth kind), §2 (parent, parameters, a lock), §7 (format) and [ADR 0052](0052-laser-fixture-jobs-in-the-project-file.md) §1 to §3 (a role register, new part keys); notes go on both on acceptance. The profile record is [ADR 0060](0060-fixture-sets-in-the-machine-profile-record.md). Spec: [`0113`](../../specs/0113-fixture-sets-and-pins/specification.md) criteria 1 to 40, 42. Feature notes: [`0113` adrs.md](../../specs/0113-fixture-sets-and-pins/adrs.md).

**Amended 2026-11-15** (lead, Proposal, vetoable; Curvyo is not deployed): no legacy conversion. Option C below replaces A for old files; decision 7 has no migration and decision 9 no migration golden.

**Amended 2026-11-16** (architect review, Proposal, vetoable): decision 3 names where the order lives; decision 8 counts Apply against the job-fixture limit.

**Amended 2026-11-16, second** (architect, after the customer tried the build: "machine sets cannot be locked yet, and they are bound to the page; they should be persistent across all pages and instances"; format 47 is unreleased, PR #365 open, nothing deployed): **the profile record is the only home of a set** (ADR 0060 §5a). The set subtree of a page becomes the page's **mirror** of its profile's sets: aligned from the record, carrying the record's ids, read-only where the record is missing, and holding the page's own choices. Decisions 1, 2, 6, 7, 9 and option "Where a set's contents live" below are amended; decision 10 is new.

## Context

Today a laser page holds one flat list of fixture nodes, each a child of the manufacturing node, copied from the profile. `0113` needs named sets that the page switches on or off, fixtures of this page only that a profile action never touches, a lock for those, a round pin, pins and screws laid out as a grid, and two fixed jobs (Centre mark, Diameters) per pin or screw whose Output is the toggle in the fixture row.

## Options

**How a set is stored**

- **A. A set node, `shape = "fixture_set"`, child of the manufacturing, holding its fixtures as children (chosen).** Order of sets and of their fixtures is the tree's child order; removing a set removes its fixtures, slots and jobs in one tree delete, revived by undo (ADR 0014); no sweep.
- **B. A `fixture_set` register on each fixture naming its set.** A set delete must sweep its fixtures; set order needs a second order. Rejected (ADR 0052 option B for the same reason).
- **C. Sets as an atomic list on the manufacturing.** Two peers editing two sets lose one edit. Rejected.

**Job fixtures**

- **A. Fixture nodes directly under the manufacturing, beside the sets (chosen).** Every direct fixture child is a job fixture, so no marker is needed (and an old flat fixture reads as one, decision 7).
- **B. A job-fixture container node.** One more shape and level for no gain. Rejected.

**Old files (page-level fixtures, no set)**

- **A. Migrate at open into one set "Set 1", one `migrate_format` commit (ADR 0042 §9) (chosen 2026-11-12, replaced by C on 2026-11-15).** Readers and commands know one shape.
- **B. Read them as a virtual "Set 1" and create the set node at its first edit.** Every set command and reader carries a second path forever. Rejected.
- **C. No conversion: the flat fixtures are direct children of the manufacturing, so they read as job fixtures by decision 2 (chosen 2026-11-15, replaces A).** No migration code, no second path; the maker rebuilds sets by hand (nothing is deployed).

**Where a set's contents live (2026-11-16)**

- **A. A copy per page, edited on the page, written to the profile by Update profile (chosen 2026-11-12, replaced by C).** The customer found it bound to the page: an edit on one page reached no other page or project.
- **B. Only in the record; the page holds an opaque snapshot text and choices keyed by record id; the session reads the loaded record live.** Clean file shape, but set fixtures would no longer be nodes: every fixture command (move, resize, slots, jobs, ticks, lock) would need a second implementation on record values, and every session path (draw, hit, drag, handles, chips, jobs) a second fixture identity, for ever. Rejected (the two-path cost decision 1's option B was rejected for).
- **C. Only in the record as the source; the page keeps a mirror subtree of nodes carrying the record's ids, aligned from the record, with the page's choices on the mirror nodes (chosen 2026-11-16).** Every reader and command keeps one node shape; an edit commits on the mirror and writes the record in the same step (ADR 0060 §5a); other pages follow by alignment (decision 10); the mirror is the snapshot a computer without the profile reads.

**Which jobs are Centre mark and Diameters**

- **A. A `job_role` register on the job (chosen).** The toggle finds its job by role; commands refuse to delete or re-tick a role job.
- **B. Derived from the job's ticks.** A merge or a hand-made file could make two jobs match. Rejected.

## Decision

1. **Set node** (`shape = "fixture_set"`, child of the manufacturing, sets first in child order): `name` (existing; 1 to 40 characters, need not be unique) and `set_on_page` (boolean, absent = on). Its children are fixture nodes (ADR 0049 §2). A `fixture_set` elsewhere, or a non-fixture child of a set, is kept and never read (as the slot orphan of ADR 0049).
   **Amended 2026-11-16 (mirror):** a set node is the page's mirror of one set of the page's profile record (ADR 0060 §1). It gains `set_uid` (string, the record set's `id`) and `set_locked` (boolean, absent = off, the record set's `locked`); a fixture node in a set gains `fixture_uid` (the record entry's `id`) and reads `fixture_locked` as the entry's `locked`; a fixture job node under a set fixture gains `job_uid` (the record job's `id`). **Contents** (name, order, `set_locked`, the fixture registers but `active` and `visible`, slots, jobs and ticks but `op_output`) come from the record. **Choices of the page** (never in the record, never touched by alignment): `set_on_page`, the fixture's `active` (On the bed, Frage 211 B) and `visible`, the job's `op_output`. A set node without a readable `set_uid` counts one damaged value and is read; a second set node with the same `set_uid` (two devices aligning at once), a second fixture with the same `fixture_uid` in one set or a second job with the same `job_uid` in one fixture is kept and never read; the next alignment deletes it. The mirror holds every set of the profile, on and off, so a computer without the profile can still switch them.
2. **Job fixture** = a fixture node that is a direct child of the manufacturing. It carries `fixture_locked` (boolean, absent = off; a separate key, not the drawing `locked` of ADR 0015, because a locked fixture stays selectable). ~~`fixture_locked` on a set fixture is kept and ignored.~~ **Amended 2026-11-16:** a set fixture is locked when its own `fixture_locked` or its set's `set_locked` is on (both mirrored from the profile, ADR 0060 §1); the lock behaves as a job fixture's (`0113` criterion 32). `is_locked(fixture_locked, set_locked)` in `fixture_sets.rs`. Job fixtures have no uid and never reach a record.
3. **On the bed** (Frage 211 B): a set fixture lies on the bed when its set's `set_on_page` and its own `active` are on; a job fixture when its `active` is on. Only a fixture on the bed is drawn as bed, hit, a snap or fit target and runs jobs (`0103` criteria 13 to 15 gain the set condition). Order everywhere (Layers, jobs, summary): sets in child order with their fixtures in child order, then job fixtures in child order. Pure rules in `curvyo-laser-core/src/fixture_sets.rs` ("which fixtures of a page lie on the bed and which are locked": `on_bed`, `is_locked`); the order is the snapshot's listing order of `curvyo-document-core/src/manufacturing_fixture_sets.rs`, the one place every reader takes it from (amended 2026-11-16).
4. **Pin and grids** (amends ADR 0049 §1, §2). New kind `curvyo.laser/pin`, `fixture_params`: `diameter_mm` (0.5 to 1,000, default 6). Pin and screw both gain `columns`, `rows` (integers 1 to 50, product at most 400), `column_spacing_mm`, `row_spacing_mm` (1 to 1,000, centre to centre, default 20) and `mark_mm` (the Centre mark size, 0.5 to 50, default 4); absent keys read as their defaults, so an old screw is a 1 x 1 grid. The origin is the centre of the first pin or screw; columns run in +x, rows in +y of the page (down on the screen). Their `fixture_matrix` is a translation: a rotation or anything else reads as its translation part and counts one damaged value (they never turn, `0113` criterion 21). Damage per field as ADR 0049 §6; a product above 400 reads both counts as 1 and counts one damaged value. Centres: `curvyo-laser-core/src/fixture_grid.rs` ("the centres of a pin or screw grid and its limits").
5. **Fixed jobs** (amends ADR 0052 §1 to §3). A pin and a screw are created with two `fixture_job` children, kind `score`, `op_output` = `false`, and `job_role` = `centre_mark` (tick `target.<id>.marks`) or `diameters` (pin: `.circle`; screw: `.head` and `.thread`). New part suffixes: `.circle` (pin) and `.marks` (pin, screw); one key covers every centre of the grid. Commands refuse to delete a role job, to change its ticks, and to add a job to a pin or a screw; the role jobs are deleted with their fixture. Reads: a `job_role` that is not one of the two, on a kind other than pin or screw, or the second job of the same role on one fixture, counts one damaged value and the job reads as an ordinary job. Jobs a screw got under `0103` stay and run as before. Geometry of the two parts: `curvyo-laser-core/src/fixture_marks.rs` ("the lines of centre marks and diameters"): a circle of `mark_mm` and two cross lines spanning it at every centre; the pin's circle, the screw's head and thread circles at every centre.
6. **Commands** (`curvyo-document-core`, one commit each, labels in the feature notes): add, rename, remove, move a set; set on page on and off; add a fixture into a set or as a job fixture (the add labels gain `add_pin`); lock and unlock; **Apply fixtures from page**: deep copies of every job fixture of the source manufacturing (fixture, slots, jobs, registers) that **replace** this page's job fixtures (the existing ones are deleted and the copies inserted in one step; amended 2026-11-16, customer; decision 8) with fresh node ids, the same `fixture_matrix` (work-area position), name, `fixture_locked`, `visible` and `active`, every job's `op_output` = `false`, and every `target.` key remapped to the copy's own node ids; never mirrored (Frage 210). **Pick profile** and **Reset from profile** (ADR 0050 §4, ADR 0060) replace the set nodes only; job fixtures stay. Commands check the shape and the parent: a set id passed to a fixture command is refused. **Amended 2026-11-16 (architect review):** `fill_fixture_set_uids(manufacturing, next, label)` gives every set, set fixture and set fixture job that has no profile id (`set_uid`, `fixture_uid`, `job_uid`) one from the caller's `next` (`new_record_id`, ADR 0060 §1), inside the step it is called in; it covers a format-47 file written before the uids and the nodes a command just made (a new set, fixture or job). It runs on two paths, both kept: in the step of every set edit before the record is built (ADR 0060 §5a), and in Save as profile before the mirror is written into the new record (ADR 0060 §6). Slots carry no uid; they follow by place (decision 10).
   **Amended 2026-11-16:** the set and set-fixture commands stay document-core commands on the mirror; the add commands take the new uid from the caller (the session makes it with `new_record_id`), and lock and unlock gain a set form (`lock_fixture_set` / `unlock_fixture_set`) and accept set fixtures. Document-core does not know the library: the session commits a content command only while the page's profile record is loaded and readable, and writes the record in the same step (ADR 0060 §5a). **Pick profile** replaces the mirror by a fresh mirror of the picked record (fresh node ids, the record's uids, every set On this page, every fixture On the bed, every job Output off; one undo step). **Reset from profile** no longer touches sets. Picking **Generic laser** deletes the mirror (the sets stay in their profile; no notice).
7. **`format_version` 47.** A build of 46 refuses a manufacturing child of shape `fixture_set` as damage (the manufacturing validator, ADR 0046 §6 and the format-39 note of `CURRENT_FORMAT_VERSION`); the bump makes it a version refusal, as ADR 0033 §7 requires. A `pin` kind or `fixture_locked` alone would not need it. **No migration from 46 and below** (amended 2026-11-15): such a file opens as it is and nothing is written; its direct fixture children are job fixtures (decision 2, `fixture_locked` absent = off); a screw without role jobs keeps its `0103` jobs and has no Centre mark or Diameters job (the session hides both toggles). The validator accepts a set node and its children.
   **Amended 2026-11-16:** 47 also carries `set_uid`, `set_locked`, `fixture_uid`, `job_uid` and, on the manufacturing, `mfg_fixture_sets_modified` (`I64` Unix ms, the record `modified` the mirror was last aligned to or written with; absent = 0). No further bump: 47 is unreleased.
8. **Limits** (UI add refusals; the reader reads everything): 16 sets per page, 64 job fixtures per page, and the slot limit of ADR 0049 §3 per holder (`0113` criterion 17, confirmed). Apply fixtures from page is an add: `apply_page_fixtures` refuses with `TooManyJobFixtures`, copying nothing, when this page's job fixtures plus the source's would pass 64, and the Apply list does not offer such a page (amended 2026-11-16, Proposal).
   **Amended 2026-11-16, customer:** Apply replaces this page's job fixtures (decision 6: deletes them and inserts the copies in one step), so only the source's count is limited: `TooManyJobFixtures` when the source holds more than 64, and the Apply list offers every page with 1 to 64.
9. **Goldens** in `curvyo-document-core/tests/fixtures/`: `fixture_sets_v47.curvyo` (`0113` criterion 38: two sets, one off; a grid, a holder with two slots, a 4 x 1 screw grid with Centre mark on and `mark_mm` 3, a fixture with `active` off; a locked 2 x 2 pin grid with Diameters on, a single pin; a hand-set tick on a holder job); `fixture_sets_damaged_v47.curvyo` (criterion 40: text in `diameter_mm`, a NaN spacing, a missing set name, a pin with no diameter, a count of 0, a product of 401, a third role job, a rotated pin matrix); `fixtures_pre_sets_v46.curvyo` (criterion 39: flat fixtures with jobs and a screw, opens unchanged with them as job fixtures, no set, no role jobs, nothing written). The existing fixture goldens (`fixtures_*_v40`, `fixture_jobs_*_v41`, `fixtures_grid_v39`) open unchanged and keep their "nothing written on open" assertions.
   **Amended 2026-11-16:** `fixture_sets_v47.curvyo` is regenerated with uids on every mirror node, one set locked, one set fixture locked and `mfg_fixture_sets_modified`; `fixture_sets_damaged_v47.curvyo` gains a set node without `set_uid` and two set nodes with one `set_uid`. New `fixture_sets_align_v47.curvyo` with `curvyo-laser-core/tests/fixtures/machine_profiles/format5_align_newer.json` (same profile id, a newer `modified`; one set renamed, one fixture moved, one fixture and one set added, one removed): loading aligns in one commit with the reserved label and no step; `set_on_page` off, `active` off and `op_output` on of the kept nodes survive; the new set reads off (Frage 218 default) and its fixture On the bed; node ids of kept nodes are unchanged. The same golden with the record's `modified` lowered to the page's writes nothing.
10. **Alignment** (new 2026-11-16, Proposal). `align_fixture_sets(manufacturing, sets: &[FixtureSetRecord], modified)` in new `curvyo-document-core/src/manufacturing_fixture_align.rs` ("aligns a page's set mirror with its profile's sets"): sets matched by `set_uid`, fixtures by `fixture_uid` within the set, jobs by `job_uid` within the fixture; a kept node keeps its node id and its choices, its content registers are rewritten where they differ; a missing one is created (a set **off** on this page, Frage 218 default A; a fixture On the bed; a job Output off), a node whose uid the record lacks is deleted with its subtree, and the child order follows the record; slots follow by place; ticks are rewritten from the record's tokens (ADR 0052 §7). It also writes `mfg_fixture_sets_modified`. The session runs it (a) when the record's `modified` is above the page's `mfg_fixture_sets_modified` **and** the contents differ (`sets_differ`, choices ignored), at project open, at a library reload and at page activation, as one commit with the reserved label `align_fixture_sets`: no step on the stacks, no history row (as `migrate_format`, ADR 0042 §9, and `refresh_material_numbers`, ADR 0054 §3); the `modified` guard is monotonic, so two computers cannot rewrite each other back; and (b) unguarded in the step of a set edit made in this project, for every other manufacturing of the project on the same profile. A record whose `modified` is not above the page's never overwrites the mirror (the mirror then is the newer state and the next edit writes it to the record).

## Consequences

- Every walk of a manufacturing's children now meets sets: the skip predicate of ADR 0032 already covers the whole subtree, so drawing walks stay safe; the two raw walks (`read_fixture`, `validate`) and the fixture-job reads must follow the set level. A fixture is at depth 2 and a job at depth 3 under the manufacturing.
- A set that is off hides its fixtures from every reader but the Fixtures tab; `0029` must use the decision 3 rule, never the raw list.
- Apply copies are independent nodes; nothing links them to their source.
- (2026-11-16) Opening a project whose profile changed since its last save aligns it and leaves the project modified; this is the one write a library load causes, guarded by `modified`. The goldens open without a matching record and write nothing. Two devices aligning one synced project at once may create twin mirror nodes; the reader ignores the second and the next alignment deletes it.
- (2026-11-16) Published keys add `set_uid`, `set_locked`, `fixture_uid`, `job_uid`, `mfg_fixture_sets_modified` and the reserved label `align_fixture_sets`. Rejected: an opaque snapshot with a live record read (option B of "Where a set's contents live", every fixture command twice).
- Published keys: `fixture_set`, `set_on_page`, `fixture_locked`, the kind `pin`, the parameters of decision 4, `job_role` and its two values, the part suffixes `.circle` and `.marks`. Renaming one is a format change.
- (2026-11-16, customer) The root register `snapping_centres` (boolean, absent = on; the Centres snap target of `0113` criterion 30, a sibling of `snapping_fixtures`) is published in format 47; a non-boolean value is refused on open like every snapping register.
- Rejected and why: a set register on fixtures (B, sweep and second order), an atomic set list (C, lost edits), a container for job fixtures (B), a virtual legacy set (B, two paths), a migration into "Set 1" (A, not needed while nothing is deployed), roles derived from ticks (B, ambiguous).
