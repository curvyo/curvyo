# ADR 0061: Image trace mask in the project file: parts, regions and part settings as keyed registers on the image node, in the image's unit square, format 45

**Status:** Proposed (architect, 2026-11-12). `needs-customer` by rule (document model, file format, sync merge, removal of accepted behaviour, `CLAUDE.md` §3); the behaviour is the customer's decision of 2026-11-12 (quoted below) and the spec defaults CLONE-MASK A, MASK-SETTINGS A, SYNC-MASK A, ELLIPSE-REGION later, ASSET-SWAP drop. Nothing here leaves that behaviour, so no question is open. Extends [ADR 0017](0017-image-nodes-and-embedded-assets.md) §1 (image registers), [ADR 0009](0009-concurrent-editing-semantics.md) §3 (merge per register), [ADR 0014](0014-history-undo-and-branches.md) (one commit per gesture), [ADR 0045](0045-clones-of-groups-texts-images-and-movable-placed-pages.md) §1 to §5 (picture-root clones). Replaces the tool-state model of [`0094` adrs.md](../../specs/0094-masked-composite-trace/adrs.md) (mask paths as selected objects, parts dropped on leaving the tool); keeps its clip, stack, join and worker hand-off. Spec: [`0114`](../../specs/0114-image-trace-mask/specification.md). Feature notes: [`0114` adrs.md](../../specs/0114-image-trace-mask/adrs.md).

## Context

The customer (2026-11-12, verbatim): "ich möchte zusätzlich zum rectangle einen lasso haben, dass man mit mehreren mausclicks eine form mit geraden stücken bauen kann. wenn man sie nicht zu macht wird sie automatisch geschlossen. ich möchte, dass du das mask genau so auch in curvyo einbaust, also das select object kommt weg. ist vom workflow eher hakelig. die mask hängt an dem bild, wenn man das nochmal mit trace anclickt, ist die maske wieder da. wenn man das bild löscht wird auch die mask mit gelöscht".

So the mask stops being a set of selected document paths and becomes data of the image: rectangles and lasso polygons, added or subtracted, grouped into up to 8 parts with Inside/Outside and their own trace settings (spec Behaviour 8, MASK-SETTINGS A). It must survive save, reopen and sync, follow the image's transform, merge without losing a peer's region (SYNC-MASK A), and go with the image on delete and undo. Facts that shape the decision:

- An image node is a leaf whose meta map holds `image_asset` (written once) and `image_placement`, the affine from the **unit square** (0,0)-(1,1) to document mm (ADR 0017 §1). The unit square was chosen so that a working copy at another resolution never moves the frame.
- Ctrl+C copies the **working image** (possibly downscaled), and Ctrl+V imports it as a new asset (`0087`). Picture pixels of a copy are not the original's pixels.
- `copy_subtree` (Duplicate, Ctrl drag copy, the clone repair as a copy of ADR 0045 §5) copies every meta key as it is.
- Registers are plain Loro values in the node's meta map; a map value is written whole (last writer wins per key). Keyed families of registers already exist: `member.<key>` on operations (ADR 0046 §2), `target.<id>` on fixture jobs (ADR 0052).
- The kernel (`curvyo-geometry-core::boolean`) unites per operand with the nonzero rule on a 0.001 mm grid; `curvyo-ui-core::trace_region`, `trace_parts` and the worker clip are reused unchanged from `0094`.

## Options

**Where the mask lives**

| Option | Verdict |
|---|---|
| **A. Keyed registers on the image node: one per part, one per part's settings, one per region (chosen)** | Two peers' new regions are two keys, so both survive a merge; one region is one atomic value, so a concurrent edit of the same region never mixes two shapes; delete, undo, Duplicate and the clone repair carry the mask with no new code, because they already treat the meta map whole. |
| B. Child nodes of the image (one node per part, one per region) | Per-node merge, but an image stops being a leaf: selection, the Layers panel, bounds, hit test, export and the roughly 120 matches on leaves would each need a "not a drawing child" rule (the skip rule of manufacturing subtrees again, ADR 0033 Consequences). Rejected. |
| C. One atomic register `trace_mask` holding everything | Simplest codec, but two peers drawing on the same image offline lose one side's regions (SYNC-MASK B, which the customer did not choose). Rejected. |
| D. A nested Loro container (map of maps, point lists as `LoroList`) | Per-field merge: one peer moving a lasso and another moving a corner of it interleave into a shape nobody drew; nested containers also need their own copy, revival and `document.json` paths. Rejected. |

**Coordinate space of a region**

| Option | Verdict |
|---|---|
| **A. The image's unit square, `f64` (chosen)** | Moves, scales, rotates and skews with `image_placement` by construction; independent of the working copy's resolution, so a downscaled Ctrl+C copy, a re-decode or a later decoder limit never shifts a region; document-core and ui-core map it to mm with the placement alone, without decoding the asset. Corners still land on whole picture pixels: the editor snaps to the working image's pixel grid before writing (spec Behaviour 2). |
| B. Integer picture pixels (Tracyo's `PxRect`) | Exact pixel corners, but the pixel grid is the working copy's, which depends on decode limits and on the copy path (Ctrl+C), and every reader needs the pixel size to map to mm. Rejected for the file; the editor uses pixels while drawing. |
| C. Document mm | Breaks on every transform of the image (the reason `0094` had to select paths). Rejected. |

**Part settings in the file (MASK-SETTINGS A)**: stored as one atomic map per part, interpreted by a typed module in `curvyo-ui-core` (decision 5). The alternative of the spec (regions and modes only) is not needed: about 25 plain values per part are small next to one lasso.

## Decision

1. **Registers on the image node** (amends ADR 0017 §1; image meta, `curvyo-document-core/src/trace_mask_codec.rs`, "the stored shape of an image's trace mask"):
   ```text
   trace_part.<part>           = { order: i64, outside: bool }
   trace_settings.<part>       = { <setting key>: <plain value>, ... }       // decision 5
   trace_region.<part>.<reg>   = { order: i64, kind: "rect" | "lasso", subtract: bool,
                                   points: [u0, v0, u1, v1, ...] }           // unit square
   ```
   - `rect` holds exactly two points, opposite corners (any order; read as min/max). `lasso` holds at least three points, closed implicitly from the last to the first. Coordinates are finite and within ±1000 (a thousand picture widths; damage beyond, decision 7). No count limit on regions or lasso points; the format needs none.
   - **Ids.** `<part>` is `0` for the part the first gesture on an untouched image creates (decision 3), else a new id; `<reg>` is always new. A new id is the text `<counter>@<peer>` of the creating commit's first operation, so it is unique across peers and never reused; ids contain no `.`. Ids are local to their image: a copy of the image keeps them (decision 8).
   - **Order.** Parts are ordered by (`order`, id); a new part takes the highest `order` + 1, so Add part appends and two concurrent Add parts give two parts in the same order on every peer. Regions are ordered the same way (`order` = highest + 1 within the image); the order decides only which region a click selects (topmost = last), never the mask.
   - **Stored only after a gesture.** An untouched image has no `trace_*` key. Opening the tool, analysis, retracing, Create paths and undo/redo previews never write (spec criterion 19).
2. **The mask of a part** (pure, `curvyo-ui-core/src/trace_mask.rs`, "a stored trace mask as kernel regions in document mm"): every region's points are mapped by the image's placement (for a clone, its composed matrix, decision 8) to document mm; a `rect` becomes its four mapped corners (a parallelogram under skew). Then `boolean(Union, one operand per added region)` and, if any subtracted region exists, `boolean(Difference, [that union, one operand per subtracted region])`, tolerance `TRACE_REGION_TOLERANCE` (0.005 mm), operands in region order. One operand per region keeps the per-operand nonzero rule: a self-crossing lasso paints by non-zero winding (criterion 23), two regions of opposite winding never cancel. An operand without area (collinear lasso, zero-width rectangle) is dropped and the call retried, as `TraceRegion::of_operands` does; nothing left means an empty mask. The result is `TraceRegion::from_polygons(..., outside)`, and from there the `0094` pipeline is unchanged: `trace_part_clips`, the worker's clip, `join_trace_parts`, the wash and the M ∩ Q notice. Regions have no curves, so no flattening adds error (budget: 0.0007 mm grid, 0.003 mm traced-curve flattening, against criterion 10's 0.005 mm).
3. **Parts.** The parts are the image's stored parts in order, or, with none stored, one implicit part 1 that reads the remembered settings (`0089`). The first mask gesture on an untouched image (draw a region, Add part) writes `trace_part.0` and `trace_settings.0` with part 1's current mode and settings in the same commit; Inside/Outside and setting changes before that are tool state, as today. Two peers drawing on the same untouched image both write part `0`, so their regions land in one part (the same key, last writer wins on its identical-in-intent value) instead of two. Remove part (two or more parts) deletes the part's three key families in one commit; Clear mask deletes the active part's regions and keeps the part and its settings (criterion 20). A part's stored registers are never removed otherwise. The UI offers Add part up to 8 parts; a merge can exceed 8, and the reader shows and traces every part (Add part stays dimmed); no region is hidden. The active part is session state, not stored.
4. **Sync and merge** (ADR 0009 §3, per key):
   - Concurrent new regions or parts: different keys, all kept (criterion 18, target met).
   - Concurrent edits of the same region (move, resize, corner): the region is one value; the later write by Loro's order wins on every peer; the shape is always one peer's whole shape. Delete against edit of the same region: same rule (it is gone or it is the edited one).
   - Concurrent edits of the same part's settings: one map, the later wins (ADR 0054's atomic-settings precedent: settings are coupled, e.g. Method with its tolerances and palette). Mode and settings are separate keys, so Outside on one peer and a slider on the other both survive.
   - A region or settings key whose part key is absent (one peer removed the part while the other drew in it): ignored on read, kept, never repaired on read (ADR 0033 §4); the next Remove part, Clear mask or region delete on that image removes such dangling keys in its commit. Removing a part wins, as deleting an object does.
   - Delete of the image against a mask edit: the node is gone; writes on a deleted node are lost with it (tree semantics, as for every register).
   - Byte-identical convergence (criterion 18) holds because every read sorts by (`order`, id) and never by map iteration order.
5. **Part settings** (`curvyo-ui-core/src/trace_part_settings.rs`, "the stored trace settings of one part with their ranges and defaults"). Keys, snake case, every key optional: `threshold` (number, absent or null = Auto), `smooth`, `tolerance`, `specks`, `corners`, `upscale`, `denoise`, `invert`, `ignore_background`, `recognise_text`, `recognise_shapes`, `method` (`"brightness" | "remove_background" | "pick_colours"`), `background_tolerance`, `pick_tolerance`, `background_auto`, `background` (`"#rrggbb"`, `""` transparent, null unread), `swatches`, `output` (`"single" | "multi"`), `colours` (2 to 16, null Auto), `fixed`, `excluded`, `kept_palette` (list or null), `preset` (key) and `preset_edited`. Ranges are the bar's (the implementer moves them from `traceText.ts` into this module; the frontend reads them from Rust). This is everything the result depends on, so criterion 12 (same preview and Create paths after reopen) holds; automatic values (auto Threshold, Auto background) are re-derived from the picture, deterministically.
   - Read: a key with a wrong type or out of range reads as its default; unknown keys are ignored. Write: the gesture writes the typed values over the stored map and keeps unknown keys, so a newer build's key survives an older build's edit.
   - document-core stores the map as an opaque plain value (ADR 0033 §3); it interprets nothing.
6. **History** (ADR 0014; labels in `trace_mask_commands.rs`, `curvyo-ui-core/src/history_names.rs` and `step_scope.rs`). One commit, one step, per finished gesture: `draw_trace_rectangle` "Draw rectangle", `draw_trace_lasso` "Draw lasso", `move_trace_region` "Move region", `resize_trace_region` "Resize region", `move_trace_lasso_corner` "Move lasso corner", `delete_trace_region` "Delete region", `clear_trace_mask` "Clear mask", `trace_mask_inside` "Mask: Inside", `trace_mask_outside` "Mask: Outside", `add_trace_part` "Add part", `remove_trace_part` "Remove part", `edit_trace_settings` "Change trace settings". A drag writes once, at release; an arrow key is one step per press, as the object nudge. A lasso being drawn is session state until it is finished or auto-closed (spec Behaviour 3). Deleting the image removes its keys with the node; one undo restores both, since the keys are part of the node's meta (criterion 16). The oplog keeps deleted values until a document wipe, as for every deleted object (ADR 0014 §9, ADR 0017 §2); "no mask data remains" in criterion 16 is read on the current state and `document.json`.
7. **Damage and validation** (on read, never repaired on read). A region that is not a map, has an unknown `kind`, a wrong point count for its kind, a non-finite or out-of-range coordinate, or a non-integer `order` is ignored (the part reads without it) and saved back unchanged; a part key that is not `{ order: integer, outside: bool }` makes its part read as Inside with `order` 0. Unknown `trace_*` keys are kept. Nothing of it makes the image unreadable.
8. **Copies, clones and other commands.**
   - **Duplicate, Ctrl drag copy, Group, Ungroup, move into a group, layer moves:** the meta map goes along (`copy_subtree` copies every key), so the copy has the same parts and regions; ids stay, being local to the image. Editing the copy's mask writes the copy's node only (criterion 14).
   - **Ctrl+C / Ctrl+V** (Proposal): the system clipboard carries only the picture (`0087`). The session's copy returns, besides the pixels, a fingerprint (FNV-1a 64 over width, height and RGBA of the working image) and the mask's registers; the page keeps both in memory at module scope (so it works across documents of one app instance). A paste whose decoded working image has the same fingerprint gets the mask written in the import's commit; otherwise the paste is the picture alone. A clipboard from another app, another app instance, or a browser that changes partially transparent pixels on the way gives the picture without the mask, never a wrong mask. Unit-square coordinates make the mask fit although the pasted asset is the downscaled working copy.
   - **Linked clone (CLONE-MASK A):** a clone whose root (ADR 0045 §1) is an image is traceable; it shows and edits the **root image's** registers, mapped by the clone's composed matrix, and Create paths places the result over the clone. A clone of a group is not traceable, as today. Unlink and the removal repair copy the root (ADR 0045 §5 via `copy_subtree`), so the unlinked image keeps a copy of the mask; a codec test pins it. Deleting a clone touches no mask. A locked root or a locked clone makes the region tools and mask commands unavailable on it (Proposal; reading and tracing stay).
   - **Tiling instances** (ADR 0030) are written from the source snapshot and get no mask; a mask drawn on an instance stays on that node.
   - **Object to path** does not apply to images (ADR 0017 §1); the image and its mask are unchanged.
   - **Asset swap (ASSET-SWAP).** No command changes `image_asset` of an existing node today except the tiling instance update (`tiling_write::update_image_copy`). Rule in `image_codec::write_image`: writing an asset different from the stored one removes every `trace_*` key of that node in the same commit, so a mask never moves silently onto other pixels. The step is the command's own visible step (the tiling regenerate today; a later crop or replace command names it in its own ADR). No migration of the mask to new pixels.
9. **Session contract** (`curvyo-editor-wasm`; the state lives in one feature-owned struct, architecture review 2026-11-06 finding 1). The document is the only source of the mask; the session keeps only the active part, the pressed region tool, Subtract, the selected region id, a drag or lasso in progress, and caches keyed by the document version.
   - Commands (each one commit, decision 6): `set_trace_region_tool(none | rect | lasso)`, `set_trace_subtract(bool)`; pointer and key input of the Trace tool (press, move, release, double click, Enter, Esc, Backspace, Delete, arrows) drive drawing and editing in Rust, in picture pixels of the working image, converted to unit coordinates on write; `set_trace_mask_outside`, `clear_trace_mask`, `add_trace_part`, `remove_trace_part`, `set_trace_active_part` keep their names and now write the document; new `set_trace_part_settings(index, json) -> bool` (one step, at the end of a field edit or slider drag).
   - Reads: `trace_parts()` (chips as today, regions instead of mask paths), `trace_part_settings(index) -> json`, `trace_mask_view() -> json` (tools, selected region, notices), `trace_part_clip_list` and `trace_part_mask_json` (clips from stored regions); the region outlines, handles, rubber band and wash are session overlay objects as the wash is today. The frontend re-reads settings when the document version changes, so undo and redo while the tool is open reshow them.
   - Trace input: `trace_images` takes the images and image-root clones of the selection and ignores every other object; `TraceSelection::Mixed` and `TRACE_MIXED` go.
   - **Removed:** `trace_mask_pick.rs` and its tests, `set_trace_mask_pick`, the Shift+click route, `is_mask_path` as a trace input, the mask-path half of `RegionCache` (`mask_operand` stays for Boolean users if any, else goes), the parts' `mask: Vec<NodeId>`, the frontend's `traceMaskPick`, `pick-mask` cursor, Pick mask paths button and the 0094 pick tests (spec Consequences). Removing accepted behaviour is the customer's request quoted above.
10. **Determinism and tolerance.** Stored `f64` are read as written; the unit-to-mm map is the placement's multiply-add (no fused operations), the kernel is integer, and operands are in stored order, so two runs, a reopen and another device give byte-identical results (criterion 11). Checking tolerance in tests 0.01 mm (0016), kernel tolerance 0.005 mm (above).
11. **`format_version` 45** (next free at merge; ADR 0057 and 0059 hold 45 and 46 provisionally and move up if this merges first). A build of 44 would open the file, show no mask and trace the whole picture on a device where the customer expects the stored mask ("ist die maske wieder da"), and its tiling update would not drop a mask on an asset change: the ADR 0033 §7 case for a refusal. **Migration: none**; masks were never stored, and mask paths drawn under `0094` stay ordinary paths. A format-44 file opens unchanged and is not rewritten. `document.json` lists each image's parts and regions as stored. SVG export is unchanged (the mask is not artwork).
12. **Goldens** (`curvyo-document-core/tests/fixtures/`): `trace_mask_v45.curvyo` (M1 with part `0` holding R1, L1 and a subtracted rectangle, part 2 Outside with a lasso and other settings, a second image untouched, a rotated and skewed placement); `trace_mask_damaged_v45.curvyo` (a lasso of two points, a NaN, a coordinate of 1001, an unknown kind, a non-list `points`, a part key that is not a map, a dangling region, settings with an out-of-range and an unknown key: opens, each case reads as decision 7, saves back with equal content); `trace_mask_clone_v45.curvyo` (a linked clone of a masked image and an unlinked copy). Every older golden still opens with no mask.

## Consequences

- Published keys: `trace_part.*`, `trace_settings.*`, `trace_region.*.*`, their fields and the setting keys of decision 5. Renaming one, or adding a setting that changes the trace result, is a format change.
- Each move of a lasso rewrites its whole point list into the oplog (a 200-point lasso moved 100 times adds about 160 KB). Accepted; a delta encoding is not worth a format now.
- Concurrent edits of one region, or of one part's settings, keep one side; stated here and in the spec's criterion 18 target (both regions survive, which holds). Not a debt.
- A cross-app or cross-instance paste brings the picture without its mask (decision 8, Proposal).
- Clones of images become traceable (new, CLONE-MASK A); clones of groups stay untraceable.
- Rejected and why: child nodes (B, leaves stop being leaves), one atomic mask (C, loses a peer's regions), nested containers (D, mixed shapes), pixel or mm coordinates (resolution and transform dependence), settings left out (criterion 12 would fail).
