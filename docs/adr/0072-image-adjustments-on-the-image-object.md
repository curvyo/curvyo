# ADR 0072: Image adjustments on the image object: three registers, own adjustments on a clone, the crop as the visible part, one format number per slice

**Status:** Proposed (architect, 2026-11-19), `needs-customer` (document model and file format, `CLAUDE.md` §3). The placement of the adjustments was decided by the customer (Frage 272 A, 2026-11-19); the register shape, the clone rule, the crop rule and the format numbers below are the architect's and are accepted with the slice 1 PR. Decisions marked **(Proposal)** are vetoable at the demo. Spec: [`0135`](../../specs/0135-image-optimisation/specification.md) criteria 4, 8 to 10, 24, 46, 51, 59, 61 and "File format notes". Extends [ADR 0017](0017-image-nodes-and-embedded-assets.md) §1 (image registers), [ADR 0016](0016-clone-overrides.md) §1 to §5 (a third override), [ADR 0045](0045-clones-of-groups-texts-images-and-movable-placed-pages.md) §1 (image roots), [ADR 0057](0057-test-grid-object-with-derived-operations.md) §1 and [ADR 0069](0069-raster-rows-output-and-settings.md) §7, §8 (recipe and `op_options`). The pipeline that reads the registers is [ADR 0073](0073-image-adjustment-pipeline-and-presets.md); stored AI results are [ADR 0077](0077-derived-image-assets-in-the-project-file.md).

**In plain words (for the customer).** Each picture remembers its preset, its Strength and its list of steps, as a few small values next to the picture. The pixels are never written again. A linked clone shows the original's improvements until you change one on the clone; from then on it has its own full set. Crop only hides part of the picture, so Restore original brings everything back.

## Context

Frage 272 A puts the stack, the Preset and the Strength on the image object; a linked clone may own a complete set of its own (all or nothing, like own style), and Restore original must always return to the imported picture. Clones of images exist since ADR 0045 (the spec's "amends `0049`" is already done there). The stored shape is what is hard to change: it must merge safely between peers (ADR 0009 §3), survive damage, and keep the original bytes untouched.

## Options

| Question | Chosen | Rejected and why |
|---|---|---|
| Shape of the stack | **A. One atomic register `image_adjustments`: an ordered list of steps** | B. One keyed register per step (`image_step.<id>`, as the trace regions of ADR 0061): merges two peers' edits of different steps, but Make editable, Paste adjustments, Restore original, a preset pick and the clone copy all rewrite the whole list, the pipeline order rule couples the steps, and a merge of two half-edited stacks is a stack nobody wrote. Concurrent editing of one picture's steps is rare; whole-list last-writer-wins is the ADR 0054 precedent. |
| Preset and Strength | **Two separate registers** | Inside the list value: a Strength drag would contend with a step edit of another peer for no reason. Every combination of the three registers is a valid state (spec criterion 30), so separate registers cannot merge into nonsense. |
| Own adjustments on a clone | **A. A marker `own_adjustments` plus the same three registers on the clone node (ADR 0016 option A)** | B. One nested value `own_adjustments = {preset, strength, adjustments}` (the spec's file note): a second shape for the same data, a second codec, and a Strength drag on the clone would rewrite the stack. With A the reader and writer of the original's registers are reused and "complete by construction" holds because absent registers read as their defaults. |
| Crop | **The crop is a step; `image_placement` keeps its ADR 0017 meaning (the whole picture's frame); the visible frame is the placement restricted to the crop rectangle** | Crop rewrites `image_placement` to the cropped part: the trace mask's unit square (ADR 0061 §1) would shift its meaning, a clone with its own crop would need its matrix rewritten, and Restore original would have to recompute the frame. |

## Decision

1. **Registers on an image node** (meta map; codec `curvyo-document-core/src/image_adjust_codec.rs`, "the stored shape of an image's adjustments"):
   - `image_preset`: text, absent = `expert`. Known values `photo`, `graphics`, `black_white`, `line_art`, `dot_raster`, `newspaper`, `expert`.
   - `image_strength`: integer 0 to 100, absent = 50.
   - `image_adjustments`: one plain list value, absent or empty = no stack. Each entry is `{ kind: text, enabled: bool, fields: { <key>: integer, ... }, result?: { ... } }`. **Every field is an integer in its field's step unit**, and the unit is in the key (precedent `threshold_pct`): `_pct` whole percent, `_centi` hundredths (Gamma), `_um` micrometres of the page (radii, widths, ADR 0064 §2 units), `_px` pixels (Resize). So a stored stack never holds a float, and two devices read the same numbers. The key list per kind is in ADR 0073 §2. `result` is written only by an AI step (ADR 0077 §2).
   - The steps are kept in list order; the zone order of the pipeline (ADR 0073 §3) is enforced by the writer, and a list out of zone order (a merge, a later build) is run in zone order, stable within a zone, and never rewritten on read.
2. **Linked clones** (extends ADR 0016 §1 to §5 and ADR 0045 §1).
   - `own_adjustments`: bool on a clone node, absent = false. It is offered only on a clone whose root (ADR 0045 §1) is an image; a clone of a group shows its members' own registers and has no override (as the trace mask, ADR 0061 §8).
   - **Adjustment source** A(c): the nearest node on the clone's chain, c itself first, whose `own_adjustments` is true, else the root. A clone reads Preset, Strength and stack from A(c). Memoised in the one read pass of ADR 0015 §6 beside the style source S(c); the same chain rule as ADR 0016 §3 (CHAIN-STYLE A).
   - The first adjustment edit on a clone without the marker writes, in that edit's commit, the marker and a copy of A(c)'s three registers, then the edit. **Follow original** removes the marker and the clone's three registers in one commit. **Restore original** on a clone writes the marker with `expert` and an empty list (spec criterion 59).
   - Repair and Unlink follow ADR 0016 §4: a re-pointed clone that loses its source gets a copy of what it showed; Unlink writes the effective registers onto the new image node and removes the marker. Duplicate copies the meta map (`copy_subtree`), so a duplicate has its own copy (spec criterion 9).
3. **Crop and the visible frame.** The crop step's four fields (`left_pct`, `top_pct`, `width_pct`, `height_pct`) are the one part of the stack that document-core interprets, because the frame is geometry: `ImageSnapshot` gains `visible: UnitRect` from the effective adjustments (whole square when there is no enabled crop), and ADR 0017 §1's `frame_outline()` becomes the placement applied to `visible`. Bounding box, hit test, transform handles, the raster grid's rings (ADR 0068 §2), Cut and Cut-out of the frame (ADR 0069 §13) all already go through `frame_outline()`. The trace mask stays in the whole picture's unit square. Restore original therefore writes no placement.
4. **Merge** (ADR 0009 §3, last writer wins per register, as ADR 0016 §5).
   - Two peers editing different steps: one stack wins whole; every stack a peer wrote is complete.
   - A preset pick against a step edit: both survive (separate registers); with a preset the manual tone steps show as "Preset in use" (spec criterion 30), a valid state.
   - Own adjustments switched on against an edit of the original: the clone keeps the copy taken at the switch. Follow original against an own edit: the marker is gone, the stray registers are ignored (residue).
   - Crop against a transform: independent registers, both kept.
   - An AI result written against a stack edit: one list wins; a result no list refers to is dropped at save (ADR 0077 §4).
5. **Damage** (on read, never repaired on read, saved back unchanged; the rule of ADR 0056 §6 and ADR 0061 §7). An `image_preset` that is not text or is unknown reads as Expert and counts as one step that could not run; an `image_strength` that is not an integer in 0 to 100 reads as 50; an `image_adjustments` that is not a list reads as no stack. An entry with an unknown kind, a missing or non-integer field, a field out of its range (ADR 0073 §2) or a malformed `result` is kept and not run. Each of these counts in the check line "<n> steps in the Adjustments of <image name> could not run." (spec criterion 23). A flag that is not a bool on a clone is damage of that flag only (reads false). Nothing here makes the image unreadable or the file refuse to open.
6. **Image operation and test grid** (amends ADR 0069 §7 and §8).
   - `op_options.dither` gains `halftone` and `line_screen`; two optional keys `screen_size_mm` (0.20 to 5.00, absent = 0.80) and `screen_angle_deg` (0 to 89, absent = 45) are valid on `image` only and shared by both screen modes (Cell size and Line pitch are the same length; switching mode keeps it). ADR 0074 is their arithmetic. The `dither: "halftone"` damage case of the 0123 golden moves to `"halftone_x"`.
   - The test-grid recipe (one type for the grid and the material test record, ADR 0069 §8) gains `picture: "ramp" | "selected"` (absent = ramp) and, with `selected`, an axis `strength` beside power, speed, passes and interval. In the project, each cell of a picture grid is a generated image node (ADR 0057 §1, regenerated in place) with the picture's asset, a copy of its effective adjustments and the cell's `image_strength`; the grid keeps the asset referenced. The material test record keeps the recipe only, never the picture or a stack (spec criterion 52): **material record format 4** (Proposal). Place on page of a picture test from Materials uses the selected image, else it places the Ramp without the Strength axis and says so (Proposal).
7. **History.** All registers are ordinary fields (ADR 0014 §1); undo, object undo and Restore bring them back field by field. Step names: "Edit adjustments", "Restore original", "Follow original", "Run <step name>" (`history_names.rs`). A drag of the Strength slider writes once at release.
8. **Format numbers, one per slice** (the spec proposed one bump; slices are separate PRs, `CLAUDE.md` §4). Each takes the next free `format_version` at merge, because a build of the previous number would burn other dots (the ADR 0033 §7 refusal case); none migrates (Curvyo is not deployed):
   - **Slice 1** (next free after 50, so 51 if nothing else merges first): the three registers with kinds `levels`, `local_contrast`, `contours`, `sharpen`, `denoise`; `own_adjustments`; the two dither values and screen keys; the recipe keys; material record format 4. Goldens `image_adjust_v<N>.curvyo` (a preset picture, a manual stack, a clone with own adjustments, a clone chain, a two-operation picture), `image_adjust_damaged_v<N>.curvyo` (each case of decision 5).
   - **Slice 2**: kinds `crop`, `resize`, `channel_mix`, `curves` (an older build would engrave the uncropped picture). Golden `image_adjust_crop_v<N>.curvyo`.
   - **Slice 3**: kinds `remove_background`, `upscale`, `ai_denoise` with `result`, and `assets/derived/` (ADR 0077). Golden `image_adjust_ai_v<N>.curvyo` with one stored result per kind.
   A slice merged without a bump of its own (for example slice 2 folded into slice 1's PR) shares the number.

## Consequences

- The original asset is never rewritten: a crop, a preset and Restore original only write registers (test: the asset's SHA-256 is unchanged after every edit).
- Two peers editing two steps of one picture lose one edit; the trigger to move to per-step keys is a reported loss in a shared workspace.
- `frame_outline()` gains the crop; every frame consumer follows without its own change, and ADR 0017 §1's "the unit square is the picture" is amended by a note on acceptance (the stored placement still is; the drawn frame is its visible part).
- Up to three format numbers for one story; each slice PR states its number in the README table (the lead's edit).
- Amends by notes on acceptance: ADR 0016 (a third override), ADR 0017 §1 (visible frame), ADR 0045 §1, ADR 0057 §1, ADR 0058 §2 (record format 4), ADR 0069 §7, §8.
