# ADR 0095: Pencil stroke pipeline: per-frame pen sample batches into the session, a Pencil tool of its own, one kurbo-based fitter shared with centre lines, pressure to a width profile in `curvyo-ui-core`, a hollow outline preview while drawing

**Status:** Accepted 2026-11-27 (merged with PR #525, spec 0158 slice 1; proposed by the architect the same day). Not `needs-customer`: the Pencil's output (centre line plus width profile) is the customer's Frage 410 C, the input route is ADR 0094 (Frage 408 A), the separate tool beside an untouched Freehand mode is Frage 414 A, and nothing here changes the document model, the file format or sync. No new crate, no new dependency, no `unsafe`, no `format_version` change. Spec: [`0158`](../../specs/0158-pen-display/specification.md) slice 1 (Ready 2026-11-27, criteria 1 to 17). Builds on [ADR 0053](0053-editable-curves-and-width-profiles.md) (centre line, width profile on normalised arc length, multiplier of the stroke width), [ADR 0094](0094-native-pen-input-on-linux-through-gdk-events-of-the-webview.md) (`PenSample`, per-frame batches, Pointer Events route the gesture) and [ADR 0063](0063-centre-lines.md) (the centre-line fit). Choices marked **(Proposal)** are the architect's and vetoable at the demo.

**In plain words (for the customer).** The Pencil is its own tool. While you draw, Curvyo collects every pen sample of a frame at once and shows the outline of the line with its width straight away. When you lift the pen, the samples become a smooth curve with few nodes and a width profile, exactly the kind of path the width diamonds already edit. Saving needs nothing new. The Pen's Freehand mode stays exactly as it is.

## Context

Verified on `story/pen-pencil` (2026-11-27):
- `curvyo-editor-wasm::wasm_api` has `pointer_down/hover/up(x, y, modifiers)` in canvas-relative CSS px, converted by `Session::screen_to_document`; no pressure, no time. `session::Tool` has no Pencil and no Eraser. The Pen's Freehand mode (`PenTool::freehand_move`, Douglas-Peucker in `ui-core/src/pen_tool/freehand.rs`, `freehand_smoothing` default 0.4 mm) stays untouched (criterion 16).
- `curvyo-ui-core::pen_sample` (slice 0) holds `PenSample`, `Pressure` (0 to 1), `Tilt`, `PenEnd`, `PenPhase`, `PenBatch`. ADR 0094 decision 5 names `frontend/src/platform/penSamples.ts` as the one adapter; it does not exist yet.
- `curvyo-geometry-core::centre_line::fit` (719 lines) turns samples with a width (`medial_axis::AxisSample { point, radius }`) into cubic anchors plus a `WidthProfile`: corner cuts relative to the local width, per piece `cleaned` → `bridged` → Catmull-Rom `smooth` → `safe_fit::simplify` (kurbo 0.13.1 `fit_to_bezpath` behind a guard against its unbounded candidates) → `strays` split. The profile pass (`centre_line/profile.rs`: greedy smoothstep points, `refine`, `merge_points`, a no-op at merge distance 0) checks each sample against `T(w) × share`, `T(w) = max(0.05 mm, 3 % of w)`.
- The unmerged `origin/story/pen-tablet-input` has a third fitter (Schneider, `geometry-core/src/freehand_fit.rs`) and `ui-core/src/pencil_pressure.rs`, `pencil_tool.rs` (Soft `p^0.5`, Linear `p`, Firm `p²`, Min/Max mapping, the 3-sample pressure mean of `0032` criterion 9).
- `variable_stroke_outline` unites offset samples on the 0.001 mm grid; the canvas reaches it through the artwork memo. `curvyo-render-core::stroke` tessellates screen-space lines with `lyon` 1.0.22.
- `Document::batch(label, ..)` with `create_path` plus `set_width_profiles` writes a path and its profile in one commit and one history step (`session/centre_lines.rs`).

## Options

**Entry point for samples**

| Option | Why it won or lost |
|---|---|
| **A. `WasmSession::pen_samples(flat: &[f64])`, one call per frame, beside `pointer_*` (chosen)** | One boundary crossing per frame; a `Float64Array` copies straight into linear memory; the record layout is one constant shared with TypeScript through a getter. |
| B. `pen_samples_json(&str)` with the serde `PenBatch` | Stringify in JS and parse in wasm every frame, allocations per sample; no gain over A. |
| C. Pressure and time added to `pointer_hover` | One call per coalesced event and a signature change for every tool; still no samples between DOM events on WebKitGTK. |

**Samples to curve**

| Option | Why it won or lost |
|---|---|
| **A. Extract the piece fit of `centre_line::fit` into a shared module; a small stroke front end with its own corner rule, an explicit accuracy and an explicit width tolerance (chosen)** | One fitter for traced and drawn centre lines; the kurbo guard and its tests are kept; the profile pass is reused with the tolerance passed in. |
| B. Merge the Schneider fitter of the old branch | A third fitter beside kurbo and Douglas-Peucker with no second user; its advantage (tremor below the accuracy adds no nodes) also holds for A, because the simplifier approximates the smoothed chain within the accuracy. |
| C. Douglas-Peucker as the Freehand mode does | Keeps per-sample corner nodes on curves; fails criterion 2. |
| D. Call `centre_line::fit` unchanged | Curve tolerance `T(w)` of the width (0.05 mm for a thin line) and corners as "a turn within one local width": tremor would become nodes and corners; its width tolerance is not criterion 5's. |

**Preview while drawing**

| Option | Why it won or lost |
|---|---|
| **A. The hollow outline of the raw samples (both sides offset by half the width, round ends) as one 1.5 px screen line, rebuilt each frame (chosen)** | The design-system row "Live preview outline"; linear in the sample count, no boolean union. |
| B. `variable_stroke_outline` of the samples every frame | A union of the whole growing stroke on the 0.001 mm grid each frame; cost grows with the stroke. |
| C. Fit live every frame | Slice 3; refits the whole stroke each frame. |

## Decision

1. **Entry point.** `WasmSession::pen_samples(flat: &[f64])` in `wasm_api.rs` beside `pointer_down/hover/up`, which stay as they are for every other tool, for routing and for the cursor. `flat` is a run of records of `PEN_SAMPLE_STRIDE` (9) values in `PenSample` field order: `x`, `y` (canvas-relative CSS px, as `pointer_*`), `pressure` (NaN = none), `tilt_x`, `tilt_y` (NaN = none), `end` (0 tip, 1 eraser), `phase` (0 hover, 1 contact, 2 out), `barrel` bits, `time_ms`. `curvyo-ui-core::pen_sample` gains `PEN_SAMPLE_STRIDE` and `PenSample::decode_flat(&[f64]) -> Vec<PenSample>` (a short or non-finite record is skipped); the wasm getter `pen_sample_stride()` lets TypeScript assert the same number. Tilt and barrel are carried and change nothing (criterion 11).
2. **Frontend feed (ADR 0094 decision 5).** While the Pencil is the active tool, `frontend/src/platform/penSamples.ts` turns either source into flat batches: on Linux with `pen_watch` true, the native channel's `PenBatch`es with `clientX/Y` minus the canvas rect; elsewhere, and on Linux before the first native sample of a stroke, each Pointer Event of type `pen` or `mouse` (never `touch`, criterion 11) with its `getCoalescedEvents()`, `pressure`, `tiltX/Y / 90`, `timeStamp`. One `pen_samples` call per animation frame, before the frame is drawn. With the Pencil active the canvas sends no `pointer_down/hover/up` for it: the samples carry the whole gesture (start on the first contact sample, end after the last), and hover samples move the pointer as `pointer_hover` does. The adapter flushes on `pointerup`, waiting at most one frame for the last native batch. Other tools are fed as today.
3. **Pencil tool.** New `session::Tool::Pencil` (rail, key `P`). Its state machine is new `curvyo-ui-core/src/pencil_tool.rs` (one responsibility: the Pencil's gesture from samples to a finished stroke or an erase), with no reference to `PenTool`. It reads the samples in order: a contact sample with `end = Tip` starts or continues a stroke; the first non-contact sample after it ends the stroke; samples split over batches give the same stroke as one batch; Escape drops the stroke (criterion 15). A contact sample with `end = Eraser` starts an erase gesture whose path is the eraser's samples; on lift every visible, unlocked object whose line comes within the 8 px hit rule of `0014` is deleted in one `Document::batch` named "Erase", nothing hit means no commit; while the eraser hovers, the session's existing hover box marks what it would delete (criterion 12). The session glue is new `curvyo-editor-wasm/src/session/pencil.rs` (routing samples to the tool and writing its results); `session/pen.rs` and `pen_tool.rs` are not changed.
4. **The stroke in progress.** `curvyo-ui-core/src/pencil_tool/stroke.rs` (one responsibility: the samples of one stroke and their widths). Per sample it keeps the document point, the time and the width, computed on arrival (decision 6), so each frame only appends. On release, fewer than 2 samples or a length below 0.1 mm creates nothing (criterion 15); otherwise the session writes one `Document::batch` "Pencil stroke": `create_path` with the current stroke style and the current layer's or page's operation as a new Pen path takes it, fill None (criterion 13), then `set_width_profiles`; the new path is selected and the tool stays the Pencil (criterion 1).
5. **Fitter.** The piece fit of `centre_line/fit.rs` (`fit_piece`, `cleaned`, `bridged`, `fit_kept`, `smooth`, `anchors_of`) and `centre_line/safe_fit.rs` move unchanged into `curvyo-geometry-core/src/cubic_fit.rs` and `cubic_fit/safe_fit.rs` (`pub(crate)`; one responsibility: cubic Béziers through one corner-free run of points within an accuracy). `centre_line::fit` calls them; its tests and goldens pass unchanged (a pure move, which brings `fit.rs` under 500 lines). The profile pass takes the tolerance of each sample from its caller instead of computing `T(w) × share` inside (centre lines pass exactly that, so they stay unchanged). New public `curvyo-geometry-core::stroke_fit` (one responsibility: fitting a drawn stroke's samples): `StrokeSample { point: Point, width: Length }`, `fit_stroke(&[StrokeSample], accuracy: Length, width_tolerance: Option<Length>) -> Option<FittedStroke { anchors, width, profile }>`, `None` tolerance meaning no profile. Corner rule: a corner where the chords to the samples `reach` before and after turn by more than 60°, `reach = max(4 × accuracy, 1 mm)` **(Proposal)**. The accuracy is the Pencil's Smoothing value with the Freehand slider's scale and default (criterion 9), floored at 0.05 mm so that 0 stays within 0.1 mm. The width tolerance is 5 % of `Max − Min` (criterion 5), on the smoothed sample widths, merge off. A stroke without pressure and without simulation gets no profile and the current stroke width (criterion 7).
6. **Pressure to width.** New `curvyo-ui-core/src/pencil_pressure.rs` (one responsibility: mapping pressure to a stroke width), started from the old branch: the has-pressure rule (some sample not 0 and not 0.5, `0032` criterion 3), the trailing mean of the sample and the two before it, `PressureCurve::{Soft, Linear, Firm}::apply`, `PencilWidths { min, max }` (`Length`, defaults 0.2 and 2 mm, ranges 0.05 to 20 and 0.1 to 50, Max never below Min) with `width_for(p) = min + (max − min) × curve(p)` (criteria 3, 4). The path's stroke width is `max` and each width point's multiplier is `width / max`, so the profile widths come from Min and Max, not from the style (criterion 13). New `curvyo-ui-core/src/speed_pressure.rs` (one responsibility: pressure simulated from drawing speed): per sample `v` from the document distance and `time_ms` to its neighbours, `p = clamp(1 − v / 300 mm/s, 0, 1)`, then the same smoothing, curve and Min/Max (criterion 8). "Simulate pressure", Smoothing, Curve, Min and Max are Pencil settings for the session, never in the document (criteria 9, 17).
7. **Live preview.** New `curvyo-render-core/src/pencil_preview.rs` (one responsibility: the draw list of a Pencil stroke in progress): the hollow outline of the raw samples, each side offset by half the sample's width along the local normal and joined by round ends, drawn as the 1.5 px `--preview-new` line of the row "Live preview outline"; a stroke without pressure and without simulation shows its centre line at 1.5 px (criterion 10). It is rebuilt each frame from the appended samples; nothing else is recomputed per frame. `variable_stroke_outline` is not called while drawing; after release the committed path reaches it once through the artwork memo, as every profiled path does.
8. **Cost, measured.** `curvyo-editor-wasm/tests/pencil_cpu_time.rs` on the `cpu_time` helper (thread CPU time, `CLAUDE.md` §5), release build, with criterion 2's stroke (2000 samples on a 150 mm S-curve): one preview frame at 2000 samples under 8 ms **(Proposal)**, and the release (smoothing, fit, profile, commit) under criterion 2's 200 ms. If the frame fails: build finished chunks of 64 samples once and only the tail per frame (named fallback, not built).
9. **Document and format.** A Pencil stroke is an ordinary path with ordinary anchors, a stroke style and width points, what the width diamonds and profile buttons of `0110` already edit (criterion 6). No new field, no `format_version` change, no golden-file change; save and reopen give the same path and profile (criterion 5). Nothing about the device or the raw samples is stored (criterion 17).
10. **Layout and size.** No new crate, no new dependency (`kurbo` is already in `geometry-core`, `lyon` in `render-core`). New modules, each under 300 lines: `geometry-core::{cubic_fit, stroke_fit}`, `ui-core::{pencil_tool, pencil_tool::stroke, pencil_pressure, speed_pressure}`, `render-core::pencil_preview`, `editor-wasm::session::pencil`. The Pencil bar follows the UX notes.

## Consequences

- Traced centre lines and Pencil strokes share one fitter; a fix to the kurbo guard serves both. The Schneider fitter of the old branch is not merged. The Pen's Freehand mode keeps Douglas-Peucker (criterion 16).
- Accuracy bounds: the fit keeps every sample within the Smoothing value (floor 0.05 mm) and the profile within 5 % of `Max − Min`. Criteria 2 (0.1 mm) and 10 (0.15 mm) therefore hold only at a Smoothing of at most 0.1 mm; at the default 0.4 mm the centre line may lie up to 0.4 mm from the samples and the preview, which shows the raw samples, up to about 0.5 mm from the result (note in `specs/0158-pen-display/adrs.md`).
- Tests first in core: `decode_flat`, the has-pressure rule, smoothing, curves and widths (criterion 3's numbers), speed pressure, `fit_stroke` (accuracy at every sample, node count on criterion 2's S-curve, a drawn L keeps one corner, profile within 5 % of `Max − Min`), the tool's sample routing over batch boundaries, hover, eraser and Escape, and the moved `centre_line` tests unchanged.
- Slice 2's pen window calls the same `pen_samples` in its own session (ADR 0096).
- Slice 3 (live fit, stabiliser) reuses `fit_stroke` on the prefix; slice 4's calligraphy reads `Tilt` and direction from the same samples.
